# 系统架构

一个仓库、一个 Python 包，交付 Data Hub、Research、Live 三个应用。
最终目标是受控实盘；第一轮目标为完整跨日回测与 Live Sim（柜台仿真资金）。
当前提供数据、研究、文件回放 Paper 和 Live 只读/影子能力，第一轮完整回测与报撤单闭环仍待交付。
启动和环境配置见 [README](../README.md)，后续工作见 [ROADMAP](ROADMAP.md)。

## 1. 工程与运行结构

| 目录 | 职责 |
|---|---|
| `frontend/` | 三个 Next.js 应用、共享呈现与独立 `tests/` |
| `backend/` | Python 源码、测试、依赖、构建与 Dockerfile |
| `proto/` | 前后端共同消费的协议源码 |
| `scripts/` | 协议生成、安装及跨进程验收 |
| `deploy/` | 独立部署配置 |

```text
浏览器 → 所属 Next.js 前端 → 所属 Python API → 业务模块
                                     │
                                     └─ Live API → 独立 Live 内核 → 柜台适配子进程
```

三个前端与 API 分别启动和监管。Live API 不打开业务数据库，不直接调用柜台 SDK。
前端只提供交互和同源转发，不持有数据库或柜台凭据。前端、API 与内核故障分别处理，
页面关闭或管理端重启不拥有交易内核的停止权。

三个应用各有 `deploy/<应用>/compose.yaml`，独立构建、启停和查看状态。
Data Hub 在 `core.local`，Research 在 `research.local`；两者通过网络访问 `nas.local` 上的 PostgreSQL，
NAS 的一个 PostgreSQL 服务提供三个逻辑库及独立非超级用户，应用账号不持有跨库或 DDL 权限。
Data Hub 独占来源/加工库，Research 独占研究库；NAS Live 库只接收不可变归档，内核不连接它。
`deploy/database/` 在 NAS 本地目录初始化数据库与共享身份；应用停止不停止 NAS。
QNAP 导出路径须现场确认，默认优先 NFSv4。来源、市场发布、研究产物和备份分开挂载；
Research 不挂载来源，市场只读、自己的产物可写；备份仅挂载到维护容器。挂载或身份不符时拒绝启动。
PostgreSQL 运行目录在 NAS 本地卷，Research 临时目录和应用日志在各自本机。
[Live 独立部署](../deploy/live/README.md) 只运行 Live 所需服务，使用自己的持久卷。
目标部署位置为 Data Hub 在 core、Research 在工作站、Live 在独立运行域；生产云部署后置。
第一轮 Live Sim 可在符合 SDK 要求的本机或独立主机运行，沿用同一部署结构；本机验收不代表云端已交付。
Python 依赖由 `backend/uv.lock` 固定，前端依赖由 `frontend/package-lock.json` 固定。

## 2. 当前能力与限制

| 应用 | 当前代码提供 | 尚未完成 |
|---|---|---|
| Data Hub | 来源留存、独立持久加工、失败证据、质量检查、不可变快照、查询导出和联合备份 | Tushare 定时增量/分片补数、15 分钟到日线完整研究输入 |
| Research | 因子与策略目录、固定配置、因子计算、回测比较、Paper 检查点、策略版本与候选发布 | Web 重启后继续运行的持久 worker、完整样本外评价与因子挖掘 |
| Live | 独立内核、诊断、SimNow 有界只读查询与接收、影子目标、保存回报处理、核对、预算、归档和候选接收 | 生产报撤单、完整资金/结算账本、预占与唯一发送者、执行授权及交易恢复 |

Research 当前保存执行尝试后同步执行；中断记录不伪装成成功，也不自动重跑。
文件 Paper 可以从已提交检查点继续，但不等于持久研究调度器。
进程隔离不代表整机故障隔离，也不代表所有后台任务已经独立运行。

### 第一轮交付边界

Data Hub 以文件导入和 Tushare 历史同步为两条入口，补齐来源隔离、版本化清洗、质量诊断、行情/覆盖可视化、固定快照发布和范围读取。
Research 在单策略、单真实合约的明确范围内完成夜盘/日盘、跨日账户、结算与成本、受约束模拟成交、
持久任务、可复核报告与固定评价。多合约组合、连续合约换月与高级挖掘后置，不以样例单日回测代替完整链路。

Live Sim 使用获准柜台仿真账户和资金，复用正式 Live 的运行内核、策略、风控、订单状态机、账本、控制和恢复。
环境、凭据、账户、条款和运行授权明确绑定且隔离，不建立简化的第二套 Sim 业务内核；第一轮拒绝生产环境。
仿真成交必须来自柜台确认，不能用 Paper 撮合替代。软件业务规则相同不代表仿真柜台的流动性、成交或结算细节与生产一致，
实际差异与能力限制须在运行和验收中记录。仿真验收不授予生产执行权。

## 3. 模块与状态所有权

以下目录均相对于 `backend/src/northstar_quant/`。

| 模块 | 唯一负责的行为或状态 |
|---|---|
| `apps/` | 应用装配、启动、API 注册和进程生命周期接入 |
| `data_management/` | 来源、加工尝试、质量、数据目录、快照、发布及保留 |
| `research/` | 研究尝试、因子运行、固定配置、回测、Paper、策略版本与候选 |
| `live/` | 运行实例、接收与控制、恢复协调及材料接收 |
| `factors/` | 因子输入、预热、计算与可得性语义 |
| `strategies/` | 账户无关目标、决策原因和策略内部状态 |
| `risk/` | 手数、限制与风险预算计算 |
| `execution/` | 当前的委托观察与核对；后续订单身份、状态机和预占也归此模块 |
| `broker/` | 具体 SDK 接入、查询、原始回报及接收证据 |
| `accounting/` | 确认事实入账、持仓投影、资金观察及核对差异 |
| `simulation/` | 固定假设下的模拟成交与成本 |
| `web/` | Python 共享接入、会话保护及 Protobuf 传输 |
| `cli/` | 参数转换、调用、输出及退出码 |

界面和 CLI 调用所属业务接口；核心计算不导入应用入口、页面或 CLI。
模块可以共用事务与数据库，但不能各维护一份任意修改的账户真相。
跨进程访问使用所有者的客户端或固定产物，不通过共享 ORM 绕过业务入口。

目标职责是：Live 管会话，Execution 管订单，Broker 管具体柜台；
Risk 计算许可与预算，Execution 管理未决预占，Accounting 管理已发生事实。
拆包不能拆断成交去重、入账和相关状态更新的一致性。

## 4. 数据与时间

### 历史研究数据入口

Data Hub 只负责文件导入与 Tushare 历史/盘后同步，不支持实时订阅、Tick 录制或 CTP Recorder。
业务由 `data_management/` 拥有，`apps/data_hub/` 装配 API 与独立 worker；仍是一份本地托管研究数据，
保留原始响应、来源与修订，发布后由 Research 读取固定快照，不在回测时请求供应商。

| 入口 | 职责 |
|---|---|
| 文件导入 | 外部文件原文、来源声明、固定映射、校验、覆盖与异常报告 |
| Tushare 同步 | 首次历史下载、盘后增量、按缺失区间补数；来源始终标记为 Tushare，token 只在服务端 |

盘后同步与 Live 盘中行情分开：Live 自己取得行情和柜台回报，不依赖 core、NAS、Research 或 Tushare 历史接口。
Live 保存的执行/接收证据和可选固定段归档仍属于 Live；Data 可处理获准文件副本，这不构成实时录制能力。

新同步/修订不按最后写入覆盖旧研究输入。同合约同时间存在差异时保留原文并检查口径，
缺口不会自动填价格；补数产生明确来源和新版本。研究引用的快照与配置保持固定。
来源对象按内容哈希落盘，私有原文与只读市场发布仍分开挂载；Research 不获得原文写权限。

### 当前实现

Web `/sync` 和 CLI `data sync-tushare` 使用同一持久同步任务。独立 `data-worker` 下载后
保存 Tushare 原始 JSON、无凭据请求参数与实现身份，关联原文加工任务；RECEIVED 不等于已发布。
PENDING 跨进程保留；下载中断不盲目重试。原文已提交而任务状态未确认时恢复其引用，不重新下载。
失败要显式新建请求；重复 UUID 返回原记录，参数或代码改变时拒绝复用该身份。

当前接通 `ft_mins` 的 SHFE 真实合约一分钟数据，限定已过去日期、最长两小时连续日盘范围，
响应最多 5 MiB。通过 HTTPS 固定地址请求，无重定向；token 只由 worker 读取，不进入任务、浏览器协议或错误原文。
`trade_time` 按分钟结束解释，来源时间为北京时间，FINAL_REVISED 的可得时间是研究假设；
须用有权限的真实样本核对标签、覆盖和夜盘口径，不能根据下载时间宣称历史首次可得。
当前量价使用 Decimal，成交额/持仓量暂只保留在原文，不宣称完整结算输入。

定时增量、历史分片、自动有限重试、水位、15 分钟/日线与跨夜盘/跨休市加工尚未实现。
文件导入当前支持固定 CSV；Parquet 和通用字段映射仍待实际需求。已有 EDB 下载实现已替换为 Tushare，
不保留并行下载入口或 Recorder 建设计划。使用见 [CLI](CLI.md)，接口依据见 [SOURCES](SOURCES.md)。

Data API 接收原文和固定参数后持久排队，独立 `data-worker` 负责加工与发布。
Data 首页按全部尝试统计排队、运行中、失败和已发布数量，显示最早排队任务及等待时间；
统计只读，不根据轮询恢复或重试任务，运行中记录不等于执行进程健康。
当前沿用单项有界加工锁（每文件最多 5 MiB），新来源接收不等待已有加工；并行加工与采集优先调度尚未实现。
排队任务跨重启保留；失去执行进程的 RUNNING 尝试在下一次认领或维护核查时标为失败，须明确新建重试，
不能因超时自动重放。执行器拒绝不同实现版本的排队任务。CLI 一次性导入复用同一队列、认领和发布操作，等待结果退出。

来源内容与加工尝试分开保存；失败必须可解释，计算完成不自动等于可发布。
发布快照不可变，保留来源、参数、质量、时间口径和内容身份；被引用证据不得作为临时文件删除。
Data Hub 将已校验快照发布为原子、带校验值的固定文件，Research 通过数据所有者的读取接口消费，不访问 Data Hub 表。
已提交发布的文件导出中断由 Data worker 重试导出，不重新加工、不覆盖旧快照。研究引用通过研究所有者的产物记录交付，Data 不再查询研究表。
来源文件与引用它们的数据库记录一起备份；研究备份包含自己的库、固定市场输入和研究产物。来源存储 UUID 绑定显式 NAS 挂载，缺失不自动创建本地替代目录；
恢复到全新目录时可明确初始化目标存储身份，不能自动接管没有身份标记的旧数据。查询研究数据通过数据业务接口返回固定值。

分别保存事件开始、完成、可得时间和交易日，不能用本地接收时间代替历史首次可得时间。
缺少历史发布或修订证据时，只能在明确的信息时钟假设下研究事后取得的数据。
研究标签不能进入决策输入，拟合参数必须在训练范围之外固定。来源边界见 [SOURCES](SOURCES.md)。

统一使用真实期货合约 UUID，明确 tick、乘数、币种和时段；资金与价格使用 Decimal。
缺失、预热与无新目标分别表达，不将缺失值填零。

## 5. 账户与执行顺序

当前模拟范围是单合约、显式日内时段、分钟输入及固定成本假设，未完整模拟部分成交、市场冲击或交易所结算。
Simulation 在后续可执行市场事件上尝试成交，先应用已可得账户事实与有效条款，再处理之前的授权，
随后计算策略目标与风险许可。数据结束不自动生成平仓成交。

Broker 会话只应用确认的外部事实，不从分钟线编造成交；生产资金不能来自研究初始现金。
保存成交按固定身份去重，冲突保留并解释；入账后用独立证据核对，不能用核对输入偷偷修补其依据。
累计资金/费用观察不能作为每次新增金额重复入账，逐笔费用未知时不能填零。
当前数量匹配、资金观察或预算通过，都不构成完整账户核对和发送权限。

## 6. 研究与结果身份

策略、因子、Risk 和模拟参数保存为不可变配置，运行绑定确切修订与输入。
修改模板不改变活动会话，也不授予执行权限。因子计算与策略状态分开；
运行会话保存绑定状态，账户投影仍从已确认账本重建。

代码身份使用完整 Git commit，构建时写入制品；正式构建要求工作区干净。
`-dirty` 仅是开发标记，不能仅凭该提交号复原未提交源码。
结果保存快照、配置、实现身份及评价证据；固定研究结果不证明盈利能力。

候选发布、Live 材料接收和真实执行授权是不同事实。
当前 Live 只接收与本机干净代码版本匹配的固定候选，状态为 `RECEIVED`，不自动创建生产实例。
新增算法、登记和验证见 [因子与策略开发](FACTOR_STRATEGY_DEVELOPMENT.md)。

## 7. Live 控制与恢复边界

Live 的硬约束：NAS、core、research 停机或断网，不得成为正在运行的 Live 的交易、风控、账户记账或本地恢复依赖。
运行所需的固定产物、配置、有效条款和恢复依据必须已在 Live 本地可靠保存；行情和柜台回报由 Live 自己接入。
不得在发送前等待 NAS 提交，也不得通过远端租约、认证或监控把家庭主机重新放入交易关键路径。

下一项计划将长期归档 PostgreSQL 集中到 NAS，Live 保留最小本地恢复日志并由独立上传器异步归档。
NAS 不可用只积压归档；上传器失败、重试和资源占用不能阻塞内核。以实测记录速率、容量和余量确定可保证的离线时长。
达到本地安全容量边界或本地持久化故障时停止新增风险，不丢弃关键记录；这是本地安全边界，不是远端失联即停交易。
验收须覆盖三个远端分别/同时不可用、延迟或丢包，继续处理交易事实及本地重启核对，并验证补传去重与延迟预算。
这项改造尚未实现：当前 Live 仍使用本地 PostgreSQL，不能先删数据库容器；普通可丢弃运行日志不能充当交易恢复日志。

当前启动、重启和恢复不自动连接柜台或恢复接收。显式查询和有时限接收由 Live 拥有，
SDK 工作放在有界子进程中；CLI 退出、前端或管理 API 重启不回收内核接收任务。
暂停影子计算、请求停止与确认完成分别表达。

以下为发送能力必须满足的约束，尚不能当作已交付功能：

- 默认无发送权限；授权绑定环境、账户、合约、策略配置、时间窗口与风险限额。
- 发送前持久化订单身份和预占；未知结果保留预占并查询，不盲目重发。
- 成交、部分成交、撤单请求和撤销终态分别处理；关闭连接不代表订单结束。
- 启动、重连和恢复须完成核对再启用；一个账户只有一个确认的发送者，租约过期不自动允许接管。
- 未解决事实阻止新增风险；用户本人在验证后的软件中启用真实投资执行。

## 8. 入口、维护与验收

`logging_/` 提供按应用/进程隔离的有界异步运行日志，`apps/logging.py` 接入生命周期和安全的 HTTP 摘要。
Live 调用线程不做消息格式化、磁盘写入或轮转，后台按小批量处理；队列满或磁盘故障只影响运行日志，丢弃与故障可诊断。
日志文件不是成交、订单、授权或恢复事实的存储，不得把“日志写入成功”用作业务提交条件。
同一日志路径独占写入；API 和内核分别轮转，日志线程退出排空有时限。具体文件与参数见 README。

各应用页面归 `frontend/apps/`，共用控件归 `frontend/shared/`，测试归 `frontend/tests/`。
协议只维护 `proto/` 中的一份定义，生成 Python 和 TypeScript 实现，具体见 [API](API.md)。
CLI 按用户操作分组，高级证据处理不堆到顶层，具体见 [CLI](CLI.md)。

恢复只接受空数据库和新的来源目录，并核验引用和内容身份，不覆盖当前业务数据库。
本机维护权限不等于交易授权，跨域归档副本不成为账户事实的新写入者。

使用现有验收入口，不用文档或目录测试证明业务完成：

| 验收 | 入口 |
|---|---|
| 协议、类型、构建与行为 | 根目录 `make verify`，使用专用 PostgreSQL 测试库 |
| 安装后数据、研究、Paper 与恢复 | `scripts/check_install.py` |
| 三个应用的真实浏览器交互 | `scripts/check_browser.py` |
| Live 独立部署与故障行为 | `scripts/check_live_deployment.py` |

具体环境与调用见根目录 README 和 CI。合成输入、历史研究、柜台模拟与真实账户证据分别记录。
Research 持久 worker 应按实测资源调度并保护取消与主机响应；生产 Live 配额按实际需求测量，
不把本地验收的固定资源上限当作生产容量结论。
