# 国内期货个人量化系统架构

最终目标：国内期货实盘。一个维护者、一个项目、一个工作台，优先纵向打通受限真实交易。
历史研究、内部 Paper 与柜台仿真是验证手段，不是必须先建设完毕的独立平台。
本设计区分当前能力和目标能力；模块划分约束职责，不要求现在创建全部文件或抽象。
开发任务和实时状态以 [GitHub Project 1](https://github.com/users/isqiwen/projects/1) 为准。

## 1. 设计判断与交付边界

采用模块化单体：一个 Python 包、一个应用部署、一个 PostgreSQL；
来源归档和大体积产物使用应用管理的持久文件目录，暂不增加独立存储服务。
策略、风控、账户计算和执行管理在进程内协作；具体 Adapter 只放在实际行情和柜台接入处。
采用“小 Interface 隐藏完整行为”的原则，让变化集中在拥有该行为的 Module 内。

比较过三种方向：继续加厚单日脚本最省初始改动，却容易把跨日账户逻辑散落到调用方；
通用事件平台和插件系统适配面很大，却没有当前需求支撑其维护成本；
共用决策与事实账本能够服务研究、Paper 和实盘，故选后者，但不共用模拟成交假设。
统一工作台按数据、因子、策略、风控、研究、运行与账户组织，各入口调用拥有行为的 Module。

“科学”落实为可得时间正确、账户守恒、真实成本与交易约束、预先确定评价方案和可复核结果；
“简洁”落实为单一职责所有者、少量入口、已有行为复用和一项纵向结果一次交付。
这些可检查条件优先于仓库数量、文件数量或测试数量。拓扑仍可随实际需求改变。

第一个实盘完成条件：一个明确柜台和账户、一个真实合约、一个固定策略配置，
在操作者明确授权的时间与风险范围内完成真实委托、成交、平仓和资金持仓对账；
在此之前通过外部柜台仿真及断线、未知订单、重启和备份恢复验证。
首版以有人监督的限定日盘窗口为目标；最小一手若超出批准限额则不交易。
日内目标不保证平仓成功，残余仓位与未决委托必须可见并有人工处置路径。
高级研究、完整历史跨日模拟、无人值守隔夜、多合约和策略组合不阻塞首个受限技术闭环。
期权、高频、多币种和交割不在首版；技术闭环不等于盈利验证或扩大资金的许可。

## 2. 当前实现与能力缺口

| 能力 | 当前事实 | 目标 |
|---|---|---|
| 数据 | 单合约、单自然日连续 DAY 时段的分钟 CSV；托管实际原文字节，记录失败/重试、质量、发布与研究/Paper引用；PostgreSQL 保存规范化事实 | 真实持续来源、交易日多时段、按可得时间读取修订与较大数据产物 |
| 因子与配置 | 一个动量计算；网页可保存和选择固定策略/Risk/模拟成本组合配置，修订与实际 Paper 绑定不可变 | 按实际研究需要计算、复用和评价因子；受控实盘生效管理 |
| 研究 | 单日完整序列、动量目标、风控、费用与滑点、FIFO 账户 | 连续跨日账户、保守成交、共同评价窗口、事前实验计划与样本外比较 |
| 结果 | PostgreSQL 完整结果、内容校验、精确重放、网页 | 试验组织、运行进度、成本和每日损益解释 |
| Paper | 已接受文件按固定序列单步推进；每步持久事实、命令去重、账本核对与有界 checkpoint，默认暂停、重启不自动推进；网页和 CLI | 真实持续来源、外部柜台会话与完整安全控制 |
| 柜台与实盘 | 已实现具体 CTP/SimNow 有限只读查询、持久证据与网页；原生 SDK 离线验证通过，实际登录待私密配置验收；无柜台账本、报撤单或实盘权限 | 真实只读验收 → 柜台仿真订单闭环 → 恢复与执行控制 → 明确授权的受限实盘 |
| 交付 | 单仓库源码、Docker、安装包及安装态 CI 验收入口 | 每次交付从远端干净检出验证，保持部署可复现 |

底层已有夜盘日历与不可变修订能力，但公开研究入口尚未接通；不能把底层类型存在算作交付。
SHFE 日频获取代码也不等于已具备持续分钟行情源。
首份真实分钟文件采用 [EDB 历史行情](data-source.md)，仅用于一个完整日盘子时段的
事后探索；没有取得逐条历史首次可得或修订证据，不将其计为严格时点回测或持续行情接入。
基线交付的提交、CI 与干净检出证据统一记录在 [#16](https://github.com/isqiwen/northstar-quant/issues/16)。
当前 `simulate_fill` 只生成模拟成交，`Account.apply` 按逐笔成交身份做 FIFO 入账，
`TradingSession` 支持有界状态与独立账本核对恢复。持久会话仍是明确的文件 Paper，
按固定初始模拟资金独立建账；尚无柜台初始事实、外部订单管理或实盘执行权限。
当前接收许可和限额先于归档，获准来源及加工尝试先于参数/格式检查；失败与已完成阶段可查询。
导入、质量评估与 Snapshot 发布分阶段持久化；只有加工确认发布且归档核验通过才可新研究，
不能将已有导入或中间 Snapshot 当成完成。原文与终态处理记录不可覆盖；审计识别中断和未引用文件。
既有 EDB 手工资料包仍是历史工程证据，当前导入另外建立明确的托管来源及实际转换关系。
Compose 有数据库、来源和备份持久卷；已交付该切片的一致数据库/文件备份与独立空环境恢复。

## 3. Module 与职责所有权

下表中的后续文件名是定位建议，只有相应行为进入开发时才调整代码。

| Module | 使用者可依赖的 Interface | 内部 Implementation 与数据所有权 | 当前定位 |
|---|---|---|---|
| Data | 接收来源、查询/重试加工、发布和读取数据、解释引用 | 来源归档、处理尝试、文件位置与保留、合约条款、日历、质量、修订及 Snapshot | `data/library.py` 为公开入口；`data/research.py` 保留研究值及私有加工实现，`files.py` 管字节，`maintenance.py` 管联合备份恢复 |
| Strategy | 固定配置、当时可见信息与策略状态 → Target exposure | 实际因子计算、预热、参数含义和策略内部状态；不持有账户或下单权限 | `strategy.py` |
| Risk | 固定配置、目标、账户事实、待单预占及条款 → 有界授权或拒绝 | 定手数、账户与合约限额、保证金、成本、数据新鲜度和减仓规则 | `risk.py` |
| Accounting | 已识别的成交、结算和资金事实 → 可重建账户与核对差异 | 现金、方向与今昨仓、结算基准、费用及柜台核对；来源不同但不重复记账 | `accounting.py` 已有逐笔成交与 FIFO；结算/柜台基准待实现 |
| Simulation | 既有授权与后续可用市场事件 → 模拟成交或未成交 | 滑点、费用适用、价格和量限制、部分成交、委托有效期 | `execution.py` |
| Trading | 可见信息、账户与未决委托 → 决策及有界授权 | 因果顺序、Strategy/Risk 调用和策略状态；各模式共用，不自行假设柜台成交 | `research.py:TradingSession` 当前是有界研究/Paper 模拟循环；柜台事实驱动待接入 |
| Research | 在固定数据和评价计划上运行、比较结果 | 评价窗口、候选方案、预热、基准、试验记录和长任务 | `research.py`、`runs.py` |
| Session | 从固定配置创建会话、推进事实、查询和控制 | 运行绑定、PostgreSQL 事务、游标、重建、新鲜度与生命周期；Paper 与柜台会话分别记录资金事实 | `sessions.py` 当前交付暂停单步文件 Paper，不提前创建柜台空实现 |
| Broker execution | 只读核对；执行已授权委托；接收回报；恢复未决状态 | 具体柜台 Adapter、订单状态、预占、发送尝试、节流、独占外发与 UNKNOWN 对账 | `broker/workspace.py` 统一显式查询；`ctp.py` 管原生采集，`records.py` 管固定证据与完整性；执行与柜台账本待实现 |
| Workspace | 数据/因子查询、配置选择、研究、账户核对与会话控制 | 用户会话、命令授权与去重、状态呈现；不直接操作文件/ORM 或调用柜台 | `web.py`、`static/`、`cli.py` |

请求和结果类型与拥有行为的 Module 共处；不建立共享 contracts、schemas、
validators、fixtures 或换名后的同类层。因子是 Strategy 使用的计算，不成立独立平台；
Data 管理需要持久复用的因子产物，Research 管理其评价，网页统一展示计算含义和使用关系。
Strategy/Risk 各自解释并检查参数，配置修订就近保存；Research/Session 保存实际运行绑定，
不为统一管理界面另建配置服务、通用规则引擎或重复的业务实现。
PostgreSQL 是当前确定依赖，不设计任意数据库替换接口；首个柜台接入时实现具体 Adapter，
共享合约事实留在 Data，订单和账本含义留在拥有行为的 Module，不建立共享协议仓库。
当前选定 `ctpwrapper==6.7.13`，整个应用部署于 Linux amd64；macOS/arm64 原生只运行非柜台功能。
已在无网络容器核实 SDK 创建/释放与实际版本，认证和查询仍须真实验收；
[SDK 依据](broker-source.md)明确已验证事实与未知。原生释放持有 GIL、回调也需 GIL，
因此一次有限查询使用同包短命子进程与有界 Pipe，隔离崩溃/卡住；不是独立网关部署或泛化任务平台。

## 4. 数据、时间与因果顺序

市场事实分别记录事件起始、完成、来源发布时间或可得时间、本地接收时间、交易日和稳定来源身份。
历史 Availability time 必须有来源依据；本次导入时间不能冒充历史发布时间，
最终修订文件也不能冒充当时已知数据。不能确认的条件进入研究限制或阻止相应模式运行。

当前 CSV 导入明确区分三种依据：`SOURCE_DECLARED` 记录导入者提供的来源时刻，
但不宣称系统已独立验证；`FINAL_REVISED` 仅允许以每根分钟线结束作为模拟可见时刻，
标记为事后探索而非历史可得性证据；`SYNTHETIC` 只用于工程演示。
来源引用、依据说明和时间口径随原始导入证据固定，并进入完整研究结果。
后续重复上传不能替换已接受观察的原始来源；列表只提供选择，详情与研究读取重新核验固定证据。
当前 Data 托管获准留存的实际文件，规范化入账事务同时在固定 mapping 中保存归档身份及证据摘要。
明确区分收到的 CSV 与外部转换文件；可关联实际保留的上游原文，但不伪造已执行转换或历史血缘。
Broker 单独保存有限查询期间实际复制的白名单回调与接收时刻；尚无持续行情来源归档。
柜台查询记录不是 Data 已发布行情产品；详细生命周期见第 8 节。

交易日包含显式的夜盘、日盘和休市间隔；自然日不能替代交易日。
预期覆盖来自交易日历与所选交易范围，不能由文件实际包含的行反向定义。
合约 tick、乘数、最后交易日、涨跌停、手续费和保证金条款都带适用范围；
研究冻结其证据，不能用今天的参数无声覆盖历史参数。
具体交易时段以[交易所公布的时间](https://www.shfe.cn/services/calenderandholidays/tradinghours/)为依据。

历史输入按可得时间、来源顺序和稳定身份确定排序。同一市场事实的后续修订只在公布后可见。
无法合理合并的迟到或乱序数据隔离并说明原因；禁止回写既有决策或补造过去成交。

模拟交易每一步的固定顺序为：

1. 接受当前输入，确定此刻已经可得且生效的合约条款和交易时段。
2. 结算与资金事件按其实际到达顺序入账；条款更新不追溯修改以前的决策和成交。
3. 只有可执行市场事件才尝试撮合之前授权的待单；以当前适用条款重检约束，
   已失效的价格、成本或资金授权不能继续成交。
4. 成交与费用入账，更新持仓估值；形成此刻可见的信息集，推进特征和策略状态。
5. Strategy 给出目标；Risk 基于当前账户及全部未决授权计算可接受动作，
   保存下一事件才可能执行的授权，以及本步解释信息。

普通 bar 仍遵循旧单成交→账户更新→新决策的顺序；单独结算或条款事件不提供成交价格。
尚未取得必需结算事实时暂停需要该事实的推进，不能提前借用未来才公布的价格。

实盘先应用已经接收的柜台成交/账户事实，再以可见行情决策；不运行上述模拟撮合步骤。
柜台回报与行情分别保留来源身份和本地接收顺序；晚到回报按实际事实入账并核对，
即使成交超出了先前预期也不能因 Risk 拒绝而丢弃它，应停止新增风险并暴露差异。
实时分钟线明确完成条件和缺口；重连补数据只修复观察与预热，不补做过去委托。

bar 完成前不能使用其 close；模拟不能把根据本 bar 做出的决定倒填为在本 bar 上成交。
实盘成交以实际回报为准，成交价恰与某根 bar 的 close 相同不是拒绝入账的理由。
已有订单也不能用在其提交之前已完成、仅晚到的 bar 倒填成交。
处理多合约同一时点时先形成明确的市场批次再共同决策；等时事件的排序和资金分配规则必须确定。

## 5. 账户、结算与模拟成交

共同要求为 CNY、单账户、单合约、单策略；下述历史结算与撮合完善按研究增强顺序交付，
并不是首个实盘的全部前置。实盘不能后移的是柜台真实交易日、今昨仓、开平、费用与保证金
适用信息、资金可用性、未决委托预占和跨日事实核对；不支持的运行范围明确拒绝启用。
初始资金仅在账户建立时产生。多个独立日内实验可以分别评价，但不能直接拼接为连续权益。

研究/Paper 可以声明初始模拟资金，实盘只能从柜台已核对的资金持仓基准开始；
已有持仓不能伪造成新成交或被重置为零。按柜台保证唯一的成交复合身份逐笔入账，
允许一单多笔部分成交；费用未确认时标记待核对，不用研究固定费率冒充实际费用。
柜台汇总与本地投影分别作为核对证据，不维护两份可任意修改的账户真相，也不以静默覆盖消除差异。

每笔持仓保留真实合约、方向、数量、开仓交易日、原始价格和当前结算基准。
成交记录开平性质及实际费用，平今/平昨根据交易日判定。
结算按独立的、有来源的结算事实入账并更新基准，重复结算不重复计入。
不能用收盘价静默替代结算价，也不能把结算盈亏和累计逐笔盈亏重复相加。
国内期货需要日结，是由[上期所结算规则](https://www.shfe.cn/regulation/exchangerules/rules/202606/t20260603_831935.html)
中的保证金与当日无负债结算制度决定的；账户模拟的具体算法仍由所选合约和数据条款验证。

持续保持：

`权益 = 初始资金 + 净资金流 + 已入账盈亏 - 已收费用 + 当前未结算浮动盈亏`

仓位等于已入账成交净额；可用资金同时扣除持仓保证金和未决授权预占。
保证金占用与手续费支出分别记账。研究报告区分交易损益、结算入账和估值，三者可勾稽。

Risk 处理持仓及待单的共同约束，增加风险与减少风险分别判断。
行情或条款缺失、未恢复账户和数据过期阻止新增风险；
不能因此把请求平仓显示成已经平仓。非正权益、跳空和保证金不足要产生明确结果。

当前后续 close 加不利 tick 滑点、全量成交是显式模型假设。
扩展后至少覆盖交易时段、涨跌停、零成交量、成交量参与上限、整手数量、
部分成交、有效期和跨时段待单处理；不足以推断的排队优先级采用声明的保守规则。
不会从 OHLC 推断同根 bar 内精确先后。观察不足时保留未成交和残余仓位。
若配置日终空仓，必须在事前安排可执行的平仓；缺少后续价格时标记未完成。

## 6. 研究方法与结果身份

完整样本外比较、历史修订重放和长任务属于后续增强，不阻塞受限实盘的技术联调。
首个联调仍冻结策略、数据依据、成本与风险配置并记录限制；没有完整评价证据时，不因此
批准无人值守、扩大资金或宣称策略适合实盘获利。

Research plan 在运行前固定：数据身份与期间、策略及候选参数、
训练/验证/最终评价窗口、预热范围、账户起点、成本、Risk、基准和选择规则。
评价按时间划分；候选方案使用共同评分窗口，lookback 变化不能偷偷改变统计期间。
训练或选参不得读取最终评价段；早期数据可用于声明的预热，但不混入该段收益。

初版先使用现金基准，再添加通过同一执行成本与风险约束的简单交易基准。
保存成功、失败和不交易结果，以及尝试过的参数；反复观察最终评价段后继续选参，
该段不再具有未使用样本的含义。样本外切分也不是盈利保证。
这是对[回测过拟合研究](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)
所揭示的多次试验选择偏差的最低限度工程回应，初期不建设复杂统计平台。

报告提供净权益、每日损益、回撤、费用、暴露、成交和未成交原因、评价样本量，
以及预先固定方案与实现身份。评价过短或假设不成立时不输出失真的年化指标。
独立初始化的样本外折只汇总实验统计；要画连续净值就必须真实延续账户和资金。

已有 run_id 绑定数据、参数、结果与源码/依赖/运行环境，CLI 精确重放已有差异检测。
后续增加运行前计划身份和试验关系，使同一计划结果漂移成为显式失败。
完整输出摘要用于检测内容变更；冻结事实不意味着维护旧代码或旧协议兼容。

运行较长时采用持久研究任务、明确的尝试记录和有界并发；关闭网页不会丢失进度。
任务失败或取消不发布完成结果。先在同一部署中实现必要的后台执行；
只有测量证明 CPU 计算影响行情接收时才增加研究 worker 进程；
具体 CTP 原生调用的故障隔离子进程遵循第 3 节的已证实边界，不扩展为研究任务框架。

## 7. 持久会话与故障语义

当前切片将一个已接受 Snapshot 的输入顺序一次固定为 `FILE_REPLAY`，最多 1440 根分钟线。
会话拥有独立模拟账户，每次明确命令在账户锁内核对账本并处理下一条；同一命令重试返回
已提交结果，不受后续来源暂时不可读影响。每步提交后暂停，重启不自动运行；
`COMPLETED` 只表示输入耗尽，仍显示残余仓位和待成交授权。不会后台补做过去订单。
每步重建有限范围内的已入账成交投影并核对 checkpoint；checkpoint 只保存待单、有限预热和
账户投影/指标，不复制整段曲线或重跑全部市场历史。未来持续来源需要再验证长会话负载，
当前上限不能被当作无限期运行承诺。下面的连续接收与完整控制语义由后续接入交付。

由固定配置或研究记录启动 Paper，复用策略、条款要求、成本和风控配置，
Paper 创建自己的模拟账户，不复制研究期末余额。
首个持久会话可以限定当前已支持的日盘时段；不依赖完整研究计划管理或多日历史模拟。
初始状态不足时先预热，不能以“应用在线”代替“会话已具备决策条件”。

内部 Paper 与历史研究共用模拟推进，区别在输入取得方式、时钟和提交频率：
Research 在固定 Snapshot 上计算后保存结果；
Paper 先持久接受输入并确定会话输入序列；市场、结算、条款和操作者命令的相对顺序均可追溯。
后台推进者只处理该序列中的下一项，不能按抢到锁的先后排列事实。对每一步做短事务：

1. 锁定会话所属账户行，读取已提交游标、账本、策略状态和待单。
2. 在锁内选择序列中下一待处理输入；外部指定的后序输入不能越过前序输入。
   检查身份及内容；已处理输入返回原处理结果。
3. 从已提交状态计算完整下一步，不先修改跨事务共享的内存真相。
4. 同事务保存输入处理记录、成交、账本、授权、策略状态、游标和 checkpoint。
5. 提交后再确认输入或发布网页通知。

唯一键、事务和账户级串行处理共同防重复效果；
checkpoint 是可重建加速材料，账本与已接受事实才是依据。
这使用 PostgreSQL 的[行锁和事务语义](https://www.postgresql.org/docs/17/explicit-locking.html)，
不声称外部网络全局 exactly-once。
柜台模式复用持久决策、事实与游标的提交，但网络发送和外部成交不属于同一事务；
其额外语义见第 9 节，不能由内部 Paper 的事务测试代替外部验收。

| 故障 | 必须得到的结果 |
|---|---|
| 提交前退出 | 没有半步入账；重投从已提交状态计算 |
| 提交后确认前退出 | 重投返回原结果，不再成交或扣费 |
| 两个推进者竞争 | 锁内选择确定序列的下一项；相邻输入不能倒序，也不能重复消耗资金 |
| 行情断线或缺口 | 区分休市与故障；暂停新增风险并暴露实际最后接收时间 |
| 重连补历史 | 可修复数据与预热，不能给旧待单制造事后成交 |
| 数据修订 | 保留原决策，按新事实的可得顺序影响以后步骤 |
| 应用重启 | 从已提交记录恢复并核对，再恢复连续推进 |
| 备份恢复 | 默认恢复为待核查的暂停状态，防止原实例与恢复实例同时推进 |

持续行情 Adapter 必须指向实际选定的来源，并记录接收、去重和缺口处理能力。
基于文件的增量验收有价值，但页面须标记输入类型；
来源尚未选定时，持续外部行情接入 Issue 保持待输入，其他开发可以推进。

会话状态至少表达预热、运行、暂停、降级、停止和失败。
暂停停止新增风险授权，但继续记录行情与核对账户；待单如何处理必须明确。
内部 Paper 的平仓请求经过 Risk、模拟执行与账本路径，有可执行价格才可能完成；
柜台会话须经过授权委托、柜台确认成交和事实入账，不能用内部模拟标记平仓成功。
停止会话仍保留可见的残余仓位。控制命令持久化并去重。

## 8. 持久化、界面与运行维护

### 数据生命周期与存储

当前公开切片为每份最多 5 MiB 的来源文件、串行有界加工和显式重处理；
归档默认总量 10 GiB、至少保留 256 MiB 空闲，可由运行配置调整这两个容量限制。
`DataLibrary` 接受真实 bytes，拥有来源权限与输入身份、失败记录和发布门槛；
不要求网页理解目录、ORM 或加工阶段的事务顺序。短命令仍同步执行，不提前引入工作流系统。

| 类别 | 保存内容 | 生命周期 |
|---|---|---|
| Source artifact | 实际接收内容、摘要、来源、接收时间、留存和使用依据 | 获准内容不可覆盖；未取得上游原文不得宣称保留了它 |
| Processing attempt | 输入身份、处理实现及参数、状态、输出、质量和错误 | 每次尝试可追踪；临时缓存默认可重算，仅保留有复用价值的检查点 |
| 已发布数据 | 标准行情、Snapshot、需要复用的因子结果及其计算含义 | 质量与发布成功后可选用；新加工不覆盖已被引用的内容 |
| 运行与账户事实 | 固定输入/配置/实现、结果、决策、命令、订单、成交与账本 | 可核对的持久事实，不能作为中间缓存清理 |

PostgreSQL 保存目录、来源与加工关系、质量、配置、运行状态和交易事实；
来源字节与大体积产物放在应用管理的持久文件目录，不依赖 Git 或容器可写临时层。
当前标准分钟行情仍以 PostgreSQL 为权威存储；大规模历史数据和因子矩阵确有需要时采用
[Parquet 列式文件](https://parquet.apache.org/)，按实际读取范围分区并控制小文件数量。
每类产物只有一处权威内容，其他副本必须明确为可重建派生材料；不同时维护可修改的两份真相。
对象存储和额外部署只在容量、共享或运维需求得到验证时引入，不提前建立替换框架。

先检查权限、大小和资源限额，再安全接收原文并记录处理尝试，随后解析、规范化、质量检查和发布。
接收前拒绝只记录有界原因；获准接收后，即使格式错误、质量失败或发布失败也可查询原因及已完成阶段。
文件完整写入临时位置、校验并持久落位后，才提交数据库可用记录；研究/会话只消费已接受且
满足质量门槛的产物。完整原文即使加工失败，仍可按权限查看或重试；未发布产物不能冒充可研究数据。
两种存储不构成一个原子事务：退出可能留下未引用文件，恢复须识别，不能暴露半文件或半发布结果。
相同输入、处理实现和参数可复用已确认产物；重试保留尝试记录，参数/实现变化建立新身份，
冲突观察隔离处理，不无声改写 canonical 事实、历史决策或原始来源。

查询可沿“来源 → 加工 → 发布数据 → 因子/研究/会话”双向追溯；缺失原文必须显示缺失，
摘要存在不代表能够下载或重新加工。保留期与下载权限服从来源许可；无法满足所需留存条件时，
明确限制相应用途，不能承诺完整复现。大体积计算有界执行，不能挤占交易接收和控制入口。
首版只管理引用和保留状态，不提供破坏性清理。后续清理先预览影响、检查权限和保留期，
复核 Snapshot、运行、审计及有效备份引用，并避开活动写入和宽限期；共享文件不能随一个任务删除。

### 配置身份与受控生效

代码由 Git 管理，实现身份同时固定实际源码、依赖及运行环境；数据库保存不可变的策略与 Risk
配置修订。研究固定 Snapshot 和配置，会话固定输入来源/序列依据、实现、配置及账户/环境，
实时输入逐条留证，不能把持续流误称为一个不断修改的 Snapshot。
编辑配置产生新修订，默认名称仅帮助选择；启动时解析并固定内容，不能绑定可变的“最新版”。
页面分别展示拟选择与实际生效的配置及差异。首版不热换活动会话配置；需先暂停、处理待单和
核对账户，再按新绑定建立运行并明确启用；资金、持仓、累计损益、当日损失与报撤计数等
账户风险状态连续保留，新策略按新配置重新预热，不能借重建运行清零限额或继承旧执行授权。
暂停新增风险等安全命令继续可用；保存风控配置不是执行命令，Risk 配置也不等于实盘授权。
历史配置与内容身份用于解释事实，不保留旧代码执行分支，也不承诺当前实现可精确重放任意旧结果。

### 一个工作台，按实际行为逐步交付

| 入口 | 用户可见行为 |
|---|---|
| 数据 | 来源与文件、处理进度/失败、质量、已发布数据、占用与保留情况，以及被哪些运行使用 |
| 因子 | 当前实际计算的含义、参数、预热、输入、可得性、已计算结果与使用者；按研究需要增加评价 |
| 策略 | 当前实现、所用因子、固定配置、研究/模拟结果与会话绑定 |
| 风控 | 限额修订、适用范围、实际生效值、待单预占、拒绝原因与告警 |
| 研究、运行与账户 | 结果比较、会话状态、资金持仓、委托成交、对账与受保护的操作 |

网页只调用拥有行为的 Interface，不暴露数据库表、任意文件路径或上传执行 Python 的能力。
原文下载也检查使用权限。默认显示名称、合约、日期、状态和原因，UUID 与摘要进入详情；
始终醒目标记研究、内部 Paper、柜台仿真与实盘。状态页区分数据库、文件可用性、连接、
行情新鲜度、账户核对、未决委托与执行权；当前 `/health/ready` 只代表数据库可用，
来源详情及 `audit-data` 单独解释文件状态、容量、未引用/未完成文件。

当前工作台限本机单用户，所有变更使用同一本机地址/同源限制、短期浏览器会话和 CSRF；
来源接收/重处理、文件 Paper 及 SimNow 查询命令持久去重，原文下载还检查当前会话及固定下载许可。
重启后需重新打开页面。它不是外部账户认证或实盘执行授权；
引入柜台交易控制仍须实现第 9 节门禁，单凭 loopback、CORS 或同源检查不能允许报撤单。
远程使用再增加部署认证。
SimNow 凭据只从显式、owner-only 的本机文件读取，Compose 只读挂载；
文件按字面值解析，不执行 shell、不插值，网页不接受凭据或任意前置地址。
来源文件、个人账户资料和秘密不进入公共仓库、Issues 或日志。

### 联合备份与恢复

当前 `backup` 以 PostgreSQL 共享/独占维护锁隔离来源加工，使用
[导出快照](https://www.postgresql.org/docs/17/app-pgdump.html)同时固定数据库导出与来源清单，
逐文件复制并核验；记录备份引用且不提供清理。`restore` 仅接受新目录和空库，先校验全清单，
恢复后核验全部发布引用并标记未完成加工；失败留下禁止正常启动的标记。
当前无自动外部发送，文件 Paper 默认暂停；不宣称这已完成 #27 的柜台对账和安全恢复。

备份由同一数据库快照及其引用的文件清单组成，逐文件校验摘要，备份期间保护这些引用不被清理。
首版采用维护窗口暂停加工/发布，先暂停新增风险并处理未决委托或明确人工接管；
仅关闭发送不证明柜台已无活动风险。维护期间保留必要柜台回报和应急处置，不能为备份丢弃成交。
在一致数据库快照上固定引用清单，文件保持不可变且受保护，避免先建复杂在线协调系统。
在指定空库和独立文件目录恢复，核验来源、加工关系、Snapshot、配置/运行绑定、账本、游标与待单；
缺文件或摘要冲突必须失败。未完成任务转为待核查，不能自动重复外部动作或重绑最新配置。
恢复实例默认暂停，仍须按第 9 节核对柜台事实和旧发送者失权；备份成功不能替代恢复演练。
兼容策略仍是单一当前实现：变更前保存必要事实，重建受影响的开发存储；
实际长期账户事实不能因代码升级无声丢弃或覆盖。

## 9. 首个受限实盘闭环

用户尚未开生产账户，已提供 SimNow 仿真账户及两套环境，并同意按只读验收再受限仿真执行推进。
[CTP / SimNow](https://www.simnow.com.cn/product.action) 是第一条具体路径；
它是外部柜台仿真而非内部 Paper，也不是生产权限。具体生产期货公司、SDK 实际登录能力和
生产准入分别在 Issue 跟踪，尚缺的密码与认证配置只能由用户填写到本机私密文件。
选择版本以官方当前支持、目标柜台和部署实际验证为准，只维护这一套实现，不引入旧版兼容路径。

最短交付顺序为：只读账户与行情 → 固定配置的影子决策 → 外部柜台仿真报撤单与成交 →
故障恢复/安全控制/备份恢复 → 生产只读核对与明确授权的受限开平仓。
开户准入与技术研发并行；尚未开户不阻塞内部持久会话和仿真 Adapter 的实现。

当前只读阶段不是永久禁止仿真报撤单。`BrokerWorkspace.query` 绑定批准环境、账户、指定合约、
命令和实现身份，串行采集资金、全账户持仓/委托/成交、指定合约/费率以及有限行情观察。
固定回包根据实际请求返回码、请求编号、终结标志、身份和错误计算完整性；未响应不当作空仓。
同一环境/账户只运行一批，重试已保存命令不再次连接；不会由 GET、启动、恢复或原生重连自动登录。
查询结束原子保存终态与证据，父进程中断则保留 `PENDING`，不宣称持续逐回调持久化。
即使全部回包收齐也保持 `UNRECONCILED`：多次查询非原子截面，本地柜台账本尚未建立，差异未知。
异步回报单独保留，不从行情造成交、不覆盖 Paper；交易时段、未获返回的条款和行情仍标未知。

### 真实订单和账户事实

1. 只读连接取得交易日、合约条款、资金、双向今昨仓、活动委托及成交；识别原有或人工交易，
   未识别仓位/委托和账本差异均阻止新增风险。完整查询与实时回报要有可核对的汇合批次，
   查询期间的成交不得丢失或重复；柜台不能提供一致截面时保持未核清状态。
2. 事务中固定决策、执行授权、客户端订单身份、风险预占与待发送委托；发送前重检权限、
   行情新鲜度、时段、价格、今昨仓开平及资金限制，持久标记发送尝试，再在事务外调用柜台。
3. 发送超时或进程退出留下 UNKNOWN，保留预占并查询；一次查询未找到不等于从未报入，
   不更换身份盲重发。只有具体柜台证据或有记录的人工核对可以解除不确定性。
4. 逐笔成交按柜台实际唯一的复合身份去重，同一订单允许部分成交；身份相同而内容冲突报警。
   撤单请求不是终态。累计成交与已入账事实未核清前，终态回报也不能提前释放全部预占。

### 默认关闭的执行权限

启动、重连或恢复后禁止自动发送，完成核对并重新获得操作者授权才能启用。
授权固定环境、账户、合约白名单、策略/配置身份、时间窗口、单笔与总持仓、名义金额、
保证金占用、可接受损失、价格偏离和报撤单限额；限额缺失、过期或最小一手超限都拒绝。
首版最多保留一个未决委托，不能因新 bar 到达静默替换。查询、报单与撤单各自有界限频，
按具体柜台核实参数，采用有限退避而非重试风暴。

暂停新增风险、撤单、请求平仓与停止分别记录；损失门槛触发不保证可平仓，
断线、涨跌停或流动性不足时保留真实风险状态、告警和人工柜台应急通道。
行情过期、数据库不可用、回报积压、条款过期、账户差异或执行权不确定均停止新增风险。
已确认成交仍须入账；撤单/降低风险也需满足明确授权及可核实的执行条件。

每个账户只有一个确认有效的发送者。首版不做自动故障切换；锁或租约过期不证明旧进程停止，
旧发送者未确认失效就不得启动替代者。恢复备份默认暂停，先核对恢复点之后的柜台事实再启用。

### 准入和真实验收

实盘前单独确认期货公司、开户、程序化交易协议/报告确认、API/终端认证、适用测试和
行情权限；依据现行规则向期货公司核实，不能以仿真认证码或普通交易账号替代。
[证监会《期货市场程序化交易管理规定（试行）》](https://www.csrc.gov.cn/csrc/c101954/c7564346/content.shtml)
将事前报告确认和系统接入纳入要求；此处作为工程准入检查，不代替期货公司的实际审核。
开发授权、把实盘列入目标、只读登录和仿真成功均不授权代理下真实订单。
开户与协议签署由用户办理，首次真实委托由用户在已验证软件中亲自启用执行；
开发代理交付代码、验证和说明，不代替用户发送真实投资交易指令。

真实开平仓只能在操作者另行确认账户、策略和风险范围后执行，保留委托、回报、实际费用、
资金持仓及异常处置证据。仿真成交不能替代真实验收；失败、拒单和不能平仓须如实记录，
不能为了勾选完成而增加风险或补造交易。扩大资金、隔夜和无人值守运行需要后续验证与授权。

## 10. 完成核心闭环后的扩展

多合约使用一个账户、共同估值时点和组合级限额，待单跨合约共同预占资金；
先采用透明加总保证金，不假设跨品种抵扣。
换月交易真实近远月合约，分别记录费用、价差和未成交；
连续价格只用于声明的特征处理，主力选择仅使用当时可得信息，明确最后交易日前约束。

多策略先定义固定预算、目标净额和解释规则，再增加第二个实际策略。
策略目标贡献不等于独立真实成交；策略相反目标抵消时不虚构两笔账户成交。

## 11. 开发与验收方式

按 [ROADMAP.md](ROADMAP.md) 的阶段和 Project 的原生依赖推进。
每个 Issue 交付从输入到持久结果和用户可见解释的完整行为，
包含范围、依赖、验收与未知条件。先细化当前一至两个任务的实现，再滚动调整后续设计。
以通向首个受限实盘的可运行行为排序；完整历史研究、Paper 产品和组合平台不作为人为前置。
安全控制、恢复对账与外部准入是真正的实盘依赖，不能为缩短进度删去。

验证只保护昂贵失败：时间因果、账户守恒、订单/成交去重、数据身份、
事务恢复和关键真实集成。纯计算尽量直接运行，数据库行为用真实 PostgreSQL，
外部故障用明确的输入或模拟响应；外部接入完成仍须实际来源证据。
不测试文档、目录或重复声明，也不以独立的协议、测试包或脚手架作为开发目标。
