# 系统架构

一个仓库、一个 Python 包，交付 Data Hub、Research、Live 三个应用。
最终目标是受控实盘；第一轮目标为完整跨日回测与 Live Sim（柜台仿真资金）。
当前提供数据、研究、文件回放 Paper 和 Live 只读/影子能力，第一轮完整回测与报撤单闭环仍待交付。
启动和环境配置见 [README](../README.md)，后续工作见 [ROADMAP](ROADMAP.md)。

## 1. 工程与运行结构

| 目录 | 职责 |
|---|---|
| `frontend/` | 三个 Next.js 应用、共享呈现与独立 `tests/` |
| `backend/` | Python 源码、测试、依赖、构建与 Dockerfile |
| `proto/` | 前后端共同消费的协议源码 |
| `scripts/` | Python 运维工具、协议生成及跨应用验收；Makefile 与远程管理共用 Compose 执行规则 |
| `deploy/` | 独立部署配置 |

```text
浏览器 → 所属 Next.js 前端 → 所属 Python API → 业务模块
                                     │
                                     └─ Live API → 独立 Live 内核 → 柜台适配子进程
```

三个前端与 API 分别启动和监管。Live API 不打开业务数据库，不直接调用柜台 SDK。
前端只提供交互和同源转发，不持有数据库或柜台凭据。前端、API 与内核故障分别处理，
页面关闭或管理端重启不拥有交易内核的停止权。

三个应用各有 `deploy/<应用>/compose.yaml`，独立构建、启停和查看状态。
Data Hub 与独立 PostgreSQL 部署在 `core.local`；数据库活跃数据放 core 本机 SSD，
只通过内部 Docker 网络提供给 Data Hub，不发布数据库端口。
Research 在 `research.local`，本机 SQLite 保存任务/结果元数据，不连接 core 数据库。
发布清单 GET 接口固定开放于 `0.0.0.0:19090`，无需 token；Python 管理 API 保持本机绑定。
三个前端通过 `core.local:18082`、`research.local:18084`、`Live 主机 IP:18080` 提供访问；
部署开放前端端口的主机入口与 Docker 转发入口，不限制来源 IP；允许合法 IP 和默认主机名访问，
浏览器仍校验 Host 格式、同源请求和 CSRF 会话。公网域名分别为 `datahub.wangqiwen.me`、`research.wangqiwen.me`、`live.wangqiwen.me`。
HTTPS 反向代理保留公共 Host/Origin；Next.js 校验后按实际 API 连接协议转发 Origin，代理头不参与后端授权。
三个前端绑定 `0.0.0.0`；Python API 仍仅向本机发布，Live 内核不发布主机端口。
Research 通过 Data Hub Protobuf API 取得固定清单，按存储 UUID 与相对路径读取市场目录中的 Parquet，
由本机 DuckDB 计算。发布内容不可原地覆盖，不共享可写 DuckDB 文件。
应用只依赖固定目录、存储 UUID 和读写权限，不感知存储设备、网络协议或主机挂载方式。
来源、市场发布、研究产物和备份使用独立目录；Research 不访问来源，市场只读，备份仅供维护容器。
底层持久存储、挂载、开机就绪顺序和文件系统能力由主机管理员保证。
`init-host` 使用主机配置中的 user 登录，普通用户通过 sudo 提权，以 root 权限初始化 northstar 账号、公钥与免密码 sudo；user 不参与后续应用运行。
远程部署固定以 northstar 登录，通过 sudo 准备本机运行目录，归 northstar 用户及其主组；文件目录缺失时自动创建，无挂载时使用本地磁盘，不递归改权限，已有 PostgreSQL 数据目录保持其所有者。
应用部署记录已准备的持久目录，丢失时要求恢复；前端不挂载这些业务目录。
存储 UUID 不属于用户配置：部署自动生成或从共享目录读取，绑定保存到各应用 `state/.../bindings/storage.json`，并随对应备份保留。
首次空库空目录初始化身份；已有绑定对应的空目录可以在本地磁盘复用逻辑身份，已有内容仍校验标记与文件哈希。
跨主机消费者须看到同一存储 UUID 和固定文件；更换设备时保留内容与身份，不改变应用的数据模型。
Research 临时目录、数据库和应用日志在本机；持久 SSD 行情缓存尚未实现。
[Live 独立部署](../deploy/live/README.md) 只运行 Live 所需服务，使用自己的本机持久目录。
目标部署位置为 Data Hub 在 core、Research 在工作站、Live 在独立运行域；生产云部署后置。
第一轮 Live Sim 可在符合 SDK 要求的本机或独立主机运行，沿用同一部署结构；本机验收不代表云端已交付。
仿真与未来实盘统一使用 Live Compose，由 `NORTHSTAR_LIVE_ENVIRONMENT` 指定环境；当前接受 `simnow_trading`（第一套）或 `simnow_dev`（开发环境），`production` 明确拒绝内核启动。
柜台凭据统一配置在 `deploy/live/.env` 的四个 `NORTHSTAR_SIMNOW_*` 项中，仅注入内核；不使用独立凭据文件或 SimNow Compose。
真实资金支持须完成环境/账户与账本、订单、恢复状态隔离及核对授权，配置切换本身不授予发送权。
主机路径统一固定在 `/opt/northstar/`：`apps/` 保存程序版本，`config/` 保存私有配置，
`files/` 保存数据与产物，`state/`、`credentials/`、`logs/`、`work/` 按应用隔离。
部署不提供目录覆盖参数；Docker 使用显式主机目录映射。容器内部路径为装配细节。
Live 数据库与持久材料在 `state/live/`，不共享 Data Hub 或 Research 的运行状态。
验收只在私有临时目录中重映射 Compose，不能把测试路径作为生产配置能力。
Python 依赖由 `backend/uv.lock` 固定，前端依赖由 `frontend/package-lock.json` 固定。

## 2. 当前能力与限制

| 应用 | 当前代码提供 | 尚未完成 |
|---|---|---|
| Data Hub | 来源留存、独立持久加工、失败证据、质量检查、不可变快照、查询导出和联合备份 | 供应商真实样本验收、跨日/多周期完整研究输入 |
| Research | 因子与策略目录、固定配置、因子计算、回测比较、Paper 检查点、策略版本与候选发布 | 跨日完整回测、完整样本外评价与因子挖掘 |
| Live | 独立内核、诊断、SimNow 有界只读查询与接收、影子目标、保存回报处理、核对、预算、归档和候选接收 | 生产报撤单、完整资金/结算账本、预占与唯一发送者、执行授权及交易恢复 |

Research Web 通过 `/api/tasks` 提交固定输入，SQLite 保存任务、每次尝试、进度、取消请求与结果身份。
独立 `research-worker` 监管计算子进程，前端/API 不启动或拥有它。提交时核验快照内容与来源证据，执行时重新核验本地不可变发布文件。
队列与尝试记录保留；中断后显式重试，从固定输入重新计算，不冒充断点续算。旧尝试身份不能更新新尝试。
执行器持有本机文件锁，计算子进程继承锁描述符；旧进程未退出时新监督者不能接管，无超时租约抢占。
并发根据可用 CPU、内存、磁盘和已完成任务峰值 RSS 估算准入；初始预算保守，预算不足保留排队原因。
当前算法使用 CPU；GPU 算法、持续压力测量与更精细资源终止仍待验证。计算有 100000 条输入边界。
取消在计算检查点确认，保存结果阶段不接受取消。结果完整保存后才标完成；保存中断后重试复用内容身份。
CLI 前台有界研究仍使用同一计算；因子计算尚未迁入此队列。
文件 Paper 可以从已提交检查点继续，但不等于持久研究调度器。
进程隔离不代表整机故障隔离，也不代表所有后台任务已经独立运行。

### 第一轮交付边界

Data Hub 只以 Tushare 自动历史同步为入口，补齐来源隔离、版本化清洗、质量诊断、行情/覆盖可视化、固定快照发布和范围读取。
Research 在单策略、单真实合约的明确范围内完成夜盘/日盘、跨日账户、结算与成本、受约束模拟成交、
持久任务、可复核报告与固定评价。多合约组合、连续合约换月与高级挖掘后置，不以样例单日回测代替完整链路。

Live Sim 使用获准柜台仿真账户和资金，复用正式 Live 的运行内核、策略、风控、订单状态机、账本、控制和恢复。
环境、凭据、账户、条款和运行授权明确绑定且隔离，不建立简化的第二套 Sim 业务内核；第一轮拒绝生产环境。
仿真成交必须来自柜台确认，不能用 Paper 撮合替代。软件业务规则相同不代表仿真柜台的流动性、成交或结算细节与生产一致，
实际差异与能力限制须在运行和验收中记录。仿真验收不授予生产执行权。

## 3. 模块与状态所有权

以下目录均相对于 `backend/src/northstar_quant/`。

| 模块 | 唯一负责的行为或状态 |
|---|---|
| `apps/` | 应用装配、启动、API 注册和进程生命周期接入 |
| `data_management/` | 来源、加工尝试、质量、数据目录、快照、发布及保留 |
| `research/` | 研究尝试、因子运行、固定配置、回测、Paper、策略版本与候选 |
| `live/` | 运行实例、接收与控制、恢复协调及材料接收 |
| `factors/` | 因子输入、预热、计算与可得性语义 |
| `strategies/` | 账户无关目标、决策原因和策略内部状态 |
| `risk/` | 手数、限制与风险预算计算 |
| `execution/` | 当前的委托观察与核对；后续订单身份、状态机和预占也归此模块 |
| `broker/` | 具体 SDK 接入、查询、原始回报及接收证据 |
| `accounting/` | 确认事实入账、持仓投影、资金观察及核对差异 |
| `simulation/` | 固定假设下的模拟成交与成本 |
| `web/` | Python 共享接入、会话保护及 Protobuf 传输 |
| `cli/` | 参数转换、调用、输出及退出码 |

界面和 CLI 调用所属业务接口；核心计算不导入应用入口、页面或 CLI。
模块可以共用事务与数据库，但不能各维护一份任意修改的账户真相。
跨进程访问使用所有者的客户端或固定产物，不通过共享 ORM 绕过业务入口。

目标职责是：Live 管会话，Execution 管订单，Broker 管具体柜台；
Risk 计算许可与预算，Execution 管理未决预占，Accounting 管理已发生事实。
拆包不能拆断成交去重、入账和相关状态更新的一致性。

## 4. 数据与时间

### Tushare 自动同步

Data Hub 只下载 Tushare 全部期货历史数据，没有文件上传、手工导入、下载品种/周期选择或 Tick 入口。
合约与交易日历、1/5/15/30/60 分钟、日/周/月线、结算参数、涨跌停、仓单、持仓排名、
主力映射、复权日线、南华指数和品种周报由明确的接口适配负责。权限不足单独显示，不冒充全市场下载完成。
Live 的盘中行情与接收证据仍由 Live 自己拥有，不依赖此同步服务。

`data_management/tushare/` 拥有设置、目录、分片、覆盖、下载尝试和固定响应版本；
`apps/data_hub/` 只装配 Protobuf API 和独立 `data-worker`。网页 `/sync` 保存 token、启停及查看进度；
不把历史下载放进 HTTP 请求生命周期。token 只写入 core 的私有 `NORTHSTAR_DATA_SECRET_DIR`，
API 不回显、不入任务或日志，Next.js 不挂载凭据目录。更换 token 后可点击重试异常任务。

首次下载与增量使用同一队列。合约目录包括到期合约，按上市/到期范围生成固定历史窗口；
当前月按日安排，每轮固定截止日期。每六小时检查新增范围、最近回看区间及覆盖表缺口，
90 天复核旧区间；默认近期回看约五个交易日的自然日窗口，真实交易日以已取得日历为准。
请求限速时间、重试次数和下一次执行时间落库；近期优先，每五次请求给早期历史一次机会。

同一输入窗口只有一个任务身份；全局数据库锁保证单下载所有者，每次认领另有 generation 防止失效进程覆盖新结果。
中断后未提交任务重新排队，已提交区间跳过；HTTP 可重复，记录与版本不重复。
达到接口行数上限会继续拆分；最小区间仍达到上限时阻塞并报告，不把截断结果视为完整。
空结果不推进覆盖，等待发布或核查；暂时网络/限频退避重试，持续失败保留异常。
存储或凭据不可用暂停同步，不更改已发布版本。

原始 JSON 先持久写入来源对象库并登记来源；检查字段、范围、重复和量价，金额按接口单位转换为精确 CNY 文本。
日线类数据根据合约范围与交易日历检查缺日；分钟目前保存供应商时间标签，不能仅凭返回行数证明每个应有分钟完整。
校验通过后写入不可变 Parquet 与校验清单，再用同一数据库事务登记响应版本、覆盖与完成状态。
相同内容复用原版本，有修订则保留新旧两份；读者按固定清单读取，不扫描目录拼接临时文件。
来源目录同时保留发布恢复对象，现有联合备份包含任务、原文和发布引用；恢复可以重建市场发布副本。
core 的 token 不包含在 文件备份中，重建 core 后在界面重新设置。

### 数据浏览与覆盖

`data_management/exploration/` 拥有按合约、周期、自然日期的固定版本范围读取、字段统计及覆盖证据。
`apps/data_hub/exploration_api.py` 装配只读 Protobuf 查询；Next.js `/browse`、`/quality`、`/versions`
只负责选择与呈现。POST 用于传递有界过滤条件，不创建交易命令或另一套下载任务。

一次查询最多 366 个自然日、32 个已有发布分片、32 MiB Parquet 与 20000 条匹配记录；超过时要求缩小范围。
已选文件先校验摘要，再按 256 行批次读取，单页最多 1000 行，网页默认 200 行；每个 API 进程最多同时两个范围读取。
图表与明细使用相同页原始记录，缩放只改变呈现，不生成聚合成交或修改数值；字段统计针对固定范围。
第一页返回固定 receipt 列表与查询摘要，后续分页必须复用；重复记录只在全部字段相同时合并，冲突拒绝。
导出需要固定版本并检查来源 allow_download；无授权不通过派生页面绕过原文权限。

覆盖页显示当前任务与校验依据，不将窗口覆盖等同于每分钟完整；自然日、交易日与夜盘映射仍须分别解释。
原始异常目前追溯到下载尝试、来源与规则，逐行清洗预览和修订差异仍属于后续治理交付。

### 发布边界

下载响应版本与可直接运行的 `ResearchDataset` 有不同验收条件。同步页面可查看固定响应与质量证据，
但全市场分钟/日线自动下载**不等于**已完成夜盘归属、历史有效条款、标准合约 UUID 绑定及完整跨日回测输入。
现有 Research/Paper 仍使用严格固定的单时段研究快照；多周期/跨日的研究装配继续由对应任务交付，
不会把供应商的主连/复权价格当真实可成交合约。历史响应是 FINAL_REVISED 数据，不以下载时间冒充首次可得时间。
实际账号权限、供应商可覆盖起点、时间标签、无成交分钟规则和盘后就绪时间须由真实样本确认。

来源与只读市场发布分开挂载；Research 不访问 Data 表或写原文。未挂载时允许在同一路径使用本地存储，已有非空目录身份不符或不可访问时拒绝启动。
本地空目录不代表原有发布文件可用，读取仍逐项核验引用文件。没有对个人数据库自动迁移、删除或改写；旧单次下载结构必须先保全证据并准备当前结构的新库。

分别保存事件开始、完成、可得时间和交易日，不能用本地接收时间代替历史首次可得时间。
缺少历史发布或修订证据时，只能在明确的信息时钟假设下研究事后取得的数据。
研究标签不能进入决策输入，拟合参数必须在训练范围之外固定。来源边界见 [SOURCES](SOURCES.md)。

统一使用真实期货合约 UUID，明确 tick、乘数、币种和时段；资金与价格使用 Decimal。
缺失、预热与无新目标分别表达，不将缺失值填零。

## 5. 账户与执行顺序

当前模拟范围是单合约、显式日内时段、分钟输入及固定成本假设，未完整模拟部分成交、市场冲击或交易所结算。
Simulation 在后续可执行市场事件上尝试成交，先应用已可得账户事实与有效条款，再处理之前的授权，
随后计算策略目标与风险许可。数据结束不自动生成平仓成交。

Broker 会话只应用确认的外部事实，不从分钟线编造成交；生产资金不能来自研究初始现金。
保存成交按固定身份去重，冲突保留并解释；入账后用独立证据核对，不能用核对输入偷偷修补其依据。
累计资金/费用观察不能作为每次新增金额重复入账，逐笔费用未知时不能填零。
当前数量匹配、资金观察或预算通过，都不构成完整账户核对和发送权限。

## 6. 研究与结果身份

策略、因子、Risk 和模拟参数保存为不可变配置，运行绑定确切修订与输入。
修改模板不改变活动会话，也不授予执行权限。因子计算与策略状态分开；
运行会话保存绑定状态，账户投影仍从已确认账本重建。

代码身份使用完整 Git commit，构建时写入制品；正式构建要求工作区干净。
`-dirty` 仅是开发标记，不能仅凭该提交号复原未提交源码。
结果保存快照、配置、实现身份及评价证据；固定研究结果不证明盈利能力。

候选发布、Live 材料接收和真实执行授权是不同事实。
当前 Live 只接收与本机干净代码版本匹配的固定候选，状态为 `RECEIVED`，不自动创建生产实例。
新增算法、登记和验证见 [因子与策略开发](FACTOR_STRATEGY_DEVELOPMENT.md)。

## 7. Live 控制与恢复边界

Live 的硬约束：外部存储、core、research 停机或断网，不得成为正在运行的 Live 的交易、风控、账户记账或本地恢复依赖。
运行所需的固定产物、配置、有效条款和恢复依据必须已在 Live 本地可靠保存；行情和柜台回报由 Live 自己接入。
不得在发送前等待 远端存储提交，也不得通过远端租约、认证或监控把家庭主机重新放入交易关键路径。

下一项计划由 Live 保留最小本地恢复日志并通过独立上传器异步归档固定文件到远端；外部存储不运行交易数据库。
归档目标不可用只积压归档；上传器失败、重试和资源占用不能阻塞内核。以实测记录速率、容量和余量确定可保证的离线时长。
达到本地安全容量边界或本地持久化故障时停止新增风险，不丢弃关键记录；这是本地安全边界，不是远端失联即停交易。
验收须覆盖三个远端分别/同时不可用、延迟或丢包，继续处理交易事实及本地重启核对，并验证补传去重与延迟预算。
这项改造尚未实现：当前 Live 仍使用本地 PostgreSQL，不能先删数据库容器；普通可丢弃运行日志不能充当交易恢复日志。

当前启动、重启和恢复不自动连接柜台或恢复接收。显式查询和有时限接收由 Live 拥有，
SDK 工作放在有界子进程中；CLI 退出、前端或管理 API 重启不回收内核接收任务。
暂停影子计算、请求停止与确认完成分别表达。

以下为发送能力必须满足的约束，尚不能当作已交付功能：

- 默认无发送权限；授权绑定环境、账户、合约、策略配置、时间窗口与风险限额。
- 发送前持久化订单身份和预占；未知结果保留预占并查询，不盲目重发。
- 成交、部分成交、撤单请求和撤销终态分别处理；关闭连接不代表订单结束。
- 启动、重连和恢复须完成核对再启用；一个账户只有一个确认的发送者，租约过期不自动允许接管。
- 未解决事实阻止新增风险；用户本人在验证后的软件中启用真实投资执行。

## 8. 入口、维护与验收

`logging_/` 提供按应用/进程隔离的有界异步运行日志，`apps/logging.py` 接入生命周期和安全的 HTTP 摘要。
Live 调用线程不做消息格式化、磁盘写入或轮转，后台按小批量处理；队列满或磁盘故障只影响运行日志，丢弃与故障可诊断。
日志文件不是成交、订单、授权或恢复事实的存储，不得把“日志写入成功”用作业务提交条件。
同一日志路径独占写入；API 和内核分别轮转，日志线程退出排空有时限。具体文件与参数见 README。

各应用页面归 `frontend/apps/`，共用控件归 `frontend/shared/`，测试归 `frontend/tests/`。
协议只维护 `proto/` 中的一份定义，生成 Python 和 TypeScript 实现，具体见 [API](API.md)。
CLI 按用户操作分组，高级证据处理不堆到顶层，具体见 [CLI](CLI.md)。

恢复只接受空数据库和新的来源目录，并核验引用和内容身份，不覆盖当前业务数据库。
本机维护权限不等于交易授权，跨域归档副本不成为账户事实的新写入者。

使用现有验收入口，不用文档或目录测试证明业务完成：

| 验收 | 入口 |
|---|---|
| 协议、类型、构建与行为 | 根目录 `make verify`，使用专用 PostgreSQL 测试库 |
| 安装后数据、研究、Paper 与恢复 | `scripts/acceptance/check_install.py` |
| 三个应用的真实浏览器交互 | `scripts/acceptance/check_browser.py` |
| Live 独立部署与故障行为 | `scripts/acceptance/check_live_deployment.py` |

具体环境与调用见根目录 README 和 CI。合成输入、历史研究、柜台模拟与真实账户证据分别记录。
Research 持久 worker 应按实测资源调度并保护取消与主机响应；生产 Live 配额按实际需求测量，
不把本地验收的固定资源上限当作生产容量结论。
