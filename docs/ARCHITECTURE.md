# 系统架构

一个仓库、一个 Python 包，交付 Data Hub、Research、Live 三个应用。
目标是受控实盘；当前提供数据、研究、文件回放 Paper 和 Live 只读/影子能力，尚未实现完整报撤单与实盘闭环。
启动和环境配置见 [README](../README.md)，后续工作见 [ROADMAP](ROADMAP.md)。

## 1. 工程与运行结构

| 目录 | 职责 |
|---|---|
| `frontend/` | 三个 Next.js 应用、共享呈现与独立 `tests/` |
| `backend/` | Python 源码、测试、依赖、构建与 Dockerfile |
| `proto/` | 前后端共同消费的协议源码 |
| `scripts/` | 协议生成、安装及跨进程验收 |
| `deploy/` | 独立部署配置 |

```text
浏览器 → 所属 Next.js 前端 → 所属 Python API → 业务模块
                                     │
                                     └─ Live API → 独立 Live 内核 → 柜台适配子进程
```

三个前端与 API 分别启动和监管。Live API 不打开业务数据库，不直接调用柜台 SDK。
前端只提供交互和同源转发，不持有数据库或柜台凭据。前端、API 与内核故障分别处理，
页面关闭或管理端重启不拥有交易内核的停止权。

根目录 Compose 提供本机完整环境，共用 PostgreSQL 和来源存储；
[Live 独立部署](../deploy/live/README.md) 只运行 Live 所需服务，使用自己的持久卷。
目标部署位置为 Data Hub 在 core、Research 在工作站、Live 在云端；本机验收不代表云端已交付。
Python 依赖由 `backend/uv.lock` 固定，前端依赖由 `frontend/package-lock.json` 固定。

## 2. 当前能力与限制

| 应用 | 当前代码提供 | 尚未完成 |
|---|---|---|
| Data Hub | 来源留存、导入加工、失败证据、质量检查、不可变快照、查询导出和联合备份 | 独立持久采集执行器、持续调度及跨主机交付 |
| Research | 因子与策略目录、固定配置、因子计算、回测比较、Paper 检查点、策略版本与候选发布 | Web 重启后继续运行的持久 worker、完整样本外评价与因子挖掘 |
| Live | 独立内核、诊断、SimNow 有界只读查询与接收、影子目标、保存回报处理、核对、预算、归档和候选接收 | 生产报撤单、完整资金/结算账本、预占与唯一发送者、执行授权及交易恢复 |

Research 当前保存执行尝试后同步执行；中断记录不伪装成成功，也不自动重跑。
文件 Paper 可以从已提交检查点继续，但不等于持久研究调度器。
进程隔离不代表整机故障隔离，也不代表所有后台任务已经独立运行。

## 3. 模块与状态所有权

以下目录均相对于 `backend/src/northstar_quant/`。

| 模块 | 唯一负责的行为或状态 |
|---|---|
| `apps/` | 应用装配、启动、API 注册和进程生命周期接入 |
| `data_management/` | 来源、加工尝试、质量、数据目录、快照、发布及保留 |
| `research/` | 研究尝试、因子运行、固定配置、回测、Paper、策略版本与候选 |
| `live/` | 运行实例、接收与控制、恢复协调及材料接收 |
| `factors/` | 因子输入、预热、计算与可得性语义 |
| `strategies/` | 账户无关目标、决策原因和策略内部状态 |
| `risk/` | 手数、限制与风险预算计算 |
| `execution/` | 当前的委托观察与核对；后续订单身份、状态机和预占也归此模块 |
| `broker/` | 具体 SDK 接入、查询、原始回报及接收证据 |
| `accounting/` | 确认事实入账、持仓投影、资金观察及核对差异 |
| `simulation/` | 固定假设下的模拟成交与成本 |
| `web/` | Python 共享接入、会话保护及 Protobuf 传输 |
| `cli/` | 参数转换、调用、输出及退出码 |

界面和 CLI 调用所属业务接口；核心计算不导入应用入口、页面或 CLI。
模块可以共用事务与数据库，但不能各维护一份任意修改的账户真相。
跨进程访问使用所有者的客户端或固定产物，不通过共享 ORM 绕过业务入口。

目标职责是：Live 管会话，Execution 管订单，Broker 管具体柜台；
Risk 计算许可与预算，Execution 管理未决预占，Accounting 管理已发生事实。
拆包不能拆断成交去重、入账和相关状态更新的一致性。

## 4. 数据与时间

来源内容与加工尝试分开保存；失败必须可解释，计算完成不自动等于可发布。
发布快照不可变，保留来源、参数、质量、时间口径和内容身份；被引用证据不得作为临时文件删除。
来源文件与引用它们的数据库记录一起备份。查询研究数据通过数据业务接口返回固定值。

分别保存事件开始、完成、可得时间和交易日，不能用本地接收时间代替历史首次可得时间。
缺少历史发布或修订证据时，只能在明确的信息时钟假设下研究事后取得的数据。
研究标签不能进入决策输入，拟合参数必须在训练范围之外固定。来源边界见 [SOURCES](SOURCES.md)。

统一使用真实期货合约 UUID，明确 tick、乘数、币种和时段；资金与价格使用 Decimal。
缺失、预热与无新目标分别表达，不将缺失值填零。

## 5. 账户与执行顺序

当前模拟范围是单合约、显式日内时段、分钟输入及固定成本假设，未完整模拟部分成交、市场冲击或交易所结算。
Simulation 在后续可执行市场事件上尝试成交，先应用已可得账户事实与有效条款，再处理之前的授权，
随后计算策略目标与风险许可。数据结束不自动生成平仓成交。

Broker 会话只应用确认的外部事实，不从分钟线编造成交；生产资金不能来自研究初始现金。
保存成交按固定身份去重，冲突保留并解释；入账后用独立证据核对，不能用核对输入偷偷修补其依据。
累计资金/费用观察不能作为每次新增金额重复入账，逐笔费用未知时不能填零。
当前数量匹配、资金观察或预算通过，都不构成完整账户核对和发送权限。

## 6. 研究与结果身份

策略、因子、Risk 和模拟参数保存为不可变配置，运行绑定确切修订与输入。
修改模板不改变活动会话，也不授予执行权限。因子计算与策略状态分开；
运行会话保存绑定状态，账户投影仍从已确认账本重建。

代码身份使用完整 Git commit，构建时写入制品；正式构建要求工作区干净。
`-dirty` 仅是开发标记，不能仅凭该提交号复原未提交源码。
结果保存快照、配置、实现身份及评价证据；固定研究结果不证明盈利能力。

候选发布、Live 材料接收和真实执行授权是不同事实。
当前 Live 只接收与本机干净代码版本匹配的固定候选，状态为 `RECEIVED`，不自动创建生产实例。
新增算法、登记和验证见 [因子与策略开发](FACTOR_STRATEGY_DEVELOPMENT.md)。

## 7. Live 控制与恢复边界

当前启动、重启和恢复不自动连接柜台或恢复接收。显式查询和有时限接收由 Live 拥有，
SDK 工作放在有界子进程中；CLI 退出、前端或管理 API 重启不回收内核接收任务。
暂停影子计算、请求停止与确认完成分别表达。

以下为发送能力必须满足的约束，尚不能当作已交付功能：

- 默认无发送权限；授权绑定环境、账户、合约、策略配置、时间窗口与风险限额。
- 发送前持久化订单身份和预占；未知结果保留预占并查询，不盲目重发。
- 成交、部分成交、撤单请求和撤销终态分别处理；关闭连接不代表订单结束。
- 启动、重连和恢复须完成核对再启用；一个账户只有一个确认的发送者，租约过期不自动允许接管。
- 未解决事实阻止新增风险；用户本人在验证后的软件中启用真实投资执行。

## 8. 入口、维护与验收

各应用页面归 `frontend/apps/`，共用控件归 `frontend/shared/`，测试归 `frontend/tests/`。
协议只维护 `proto/` 中的一份定义，生成 Python 和 TypeScript 实现，具体见 [API](API.md)。
CLI 按用户操作分组，高级证据处理不堆到顶层，具体见 [CLI](CLI.md)。

恢复只接受空数据库和新的来源目录，并核验引用和内容身份，不覆盖当前业务数据库。
本机维护权限不等于交易授权，跨域归档副本不成为账户事实的新写入者。

使用现有验收入口，不用文档或目录测试证明业务完成：

| 验收 | 入口 |
|---|---|
| 协议、类型、构建与行为 | 根目录 `make verify`，使用专用 PostgreSQL 测试库 |
| 安装后数据、研究、Paper 与恢复 | `scripts/check_install.py` |
| 三个应用的真实浏览器交互 | `scripts/check_browser.py` |
| Live 独立部署与故障行为 | `scripts/check_live_deployment.py` |

具体环境与调用见根目录 README 和 CI。合成输入、历史研究、柜台模拟与真实账户证据分别记录。
Research 持久 worker 应按实测资源调度并保护取消与主机响应；生产 Live 配额按实际需求测量，
不把本地验收的固定资源上限当作生产容量结论。
