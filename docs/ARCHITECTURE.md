# 系统架构

Northstar 是面向中国期货的个人量化框架：**三个独立应用，共享业务规则，一个账户一个事实所有者。**
首轮交付一个真实合约、一个策略的跨日回测，以及同一业务规则下的 SimNow 开平仓与恢复。
多品种、换月、多策略、机器学习和真实资金分阶段加入。运行方法见 [README](../README.md)，任务见 [ROADMAP](ROADMAP.md)。

## 0. 设计取舍

参考项目及官方资料见 [REFERENCES](REFERENCES.md)。本次核对日期：2026-09-10。
采用 NautilusTrader 的组件边界、VeighNa 的 CTP/开平转换思路、RQAlpha/LEAN 的账户与模拟模型分工；
参考 Qlib/MLflow 组织研究，ArcticDB 组织固定版本。具体取舍是 Northstar 的设计，不代表这些项目共同规定的标准。

- 保留 Python、Next.js、Protobuf、PostgreSQL、SQLite、Parquet/Arrow 与 DuckDB；本轮不引入另一套交易框架、任务平台或存储引擎。
- Research/Live 通过进程内 `messaging` 总线路由明确类型的命令与事件，计算仍使用直接调用；跨进程只经过所属 API、客户端或固定产物。
- 类型及不变量放在业务所有者旁，不增加 `core/`、`contracts/`、`schemas/` 等统一外层；接口有真实调用者后才抽象。
- 成交、资金与数据可复核优先；关键持久化的成本需要测量，不能靠取消可靠落盘来获得“低延迟”。
- 每次替换同时修改调用、协议、测试与文档，删除旧实现。历史证据可以保留，旧架构不继续运行。

## 1. 三个应用与存储

| 应用 | 长期运行进程 | 权威状态 | 文件与外部接口 |
|---|---|---|---|
| Data Hub（core） | Next.js、Python API、独立数据 worker | core 本地 PostgreSQL：目录、任务、质量、发布、引用 | Tushare；原文与固定 Parquet；发布清单 API |
| Research（research） | Next.js、Python API、独立研究 worker/计算子进程 | 本机 SQLite：计划、任务、尝试、结果、候选 | API 取清单、只读市场文件；DuckDB 查询；本机产物/临时目录 |
| Live（独立主机） | Next.js、管理 API、每账户实例独立内核及 CTP 子进程 | 每实例本机 SQLite：绑定、回报、账本、订单、授权、恢复 | 独立行情/柜台；本地固定材料；后续独立异步归档 |

前端、API、worker/内核分别监管；浏览器或管理 API 退出不停止持久任务与交易内核。
Data Hub 与 Research 通过固定清单和只读文件协作，不共享可写业务表。DuckDB 是查询器，不是另一份任务库。
Live 运行与本地恢复不等待 core、research、NAS 或 WAN 数据库；远端断线只影响可选的材料传输或归档。

目录固定在 `/opt/northstar/`：`apps`、`config`、`files/{source,market,research,backup}`、`state`、`credentials`、`logs`、`work`。
应用只感知目录、内容/存储身份和权限；NFS 在部署层配置，默认 Research 提供市场共享，Data Hub 写、Research 容器只读。
NFS 的准备、导出和挂载规则见 [部署说明](../deploy/README.md)，本机运行数据与 Live SQLite 不放在该共享上。
每个发布文件必须核对身份与哈希；目录存在不代表引用的数据存在。

当前同一受管 Live 主机用共享账户进程锁保证唯一占用；身份为环境、BrokerID、账户。
不同环境/账户可并行，同账户不得同时运行两个所有者。锁无超时自动接管，跨主机主备不在当前范围。
接收线程在既有半秒监测周期检查实例、账户和接收锁的文件身份，不依赖 HTTP 请求触发；
锁或账户目录被替换即终止接收，已提交事实保留，不自动重连。这是所有权故障检测，不是发送授权。
`simnow_trading`、`simnow_dev` 是 SANDBOX 的柜台 profile；`ctp_production` 对应 LIVE，目前拒绝启动。实例/数据库隔离，账户锁按柜台 profile、BrokerID、账户确定，不能将两个 SimNow 柜台混成同一个资金账户。

## 2. 当前实现与目标的差距

| 已有实现 | 下一步必须完成 |
|---|---|

| 固定配置、研究 worker、回测/Paper、共享内核、多空数量投影；本地批次新增固定日结算、今昨仓计价和量参与率部分成交 | 真实有效条款、费用调整、保证金、柜台资金投影及完整执行 |
| Live 独立内核/SQLite/账户锁、CTP 只读查询与有界接收、影子信号和账本观察 | 夜盘持续行情、完整材料绑定、发送授权/预占、报撤单、恢复与独立告警 |
| 安装、浏览器、备份与容器故障验收；#53 跨主机实机证据 | 用真实固定数据完成跨日研究，并在明确授权的 SimNow 完成非空交易闭环 |

当前已共享内核入口、行情窗口、策略运行时及部分风险/账户能力，**尚未共享完整期货账户与执行实现**。
Research 与 Live 已共用多空数量规则和 FIFO 计价；Live 查询工作台从已确认成交重放同一 Account，
报告费用前已实现盈亏。柜台完整资金与跨日计价仍需接入统一事实模型，
不能通过重命名或并列保存两套余额宣称统一完成。研究已支持固定日结算、有效费用/保证金/限价和受量参与率限制的部分成交；真实来源装配及柜台资金闭环仍待完成。

## 3. 模块、接口与状态所有权

以下为 `backend/src/northstar_quant/` 内的职责；“核心接口”描述业务边界，不要求新增抽象基类。

| 模块 | 唯一拥有的规则或状态 | 核心接口 / 不可越界 |
|---|---|---|
| `apps/`、`web/`、`cli/` | 装配、页面/API、会话、参数/输出 | 调用业务接口；不实现导入、记账、风险或发单规则 |
| `data_management/` | 来源、同步、加工、质量、清单、引用与生命周期 | 固定发布/读取；不维护交易账户 |
| `trading/` | 交易内核的单线程入口、生命周期、失败策略与完成通知 | 装配所属事件处理器；不保存账户事实或授予发送权 |
| `messaging/` | 实例内同步路由、订阅与生命周期 | 不拥有业务状态、事务、持久日志或执行权限 |
| `persistence/` | UTC 数据库时间、非过期文件锁与显式写事务 | 只提供已复用的存储机制；表、事实修改规则和完整事务由业务所有者负责 |
| `market_data/` | 合约/行情/时段的值与时间数值规则 | 适配器转为值；不导入 ORM、页面或 Research |
| `factors/` | 有界输入、预热、因子计算 | 仅使用决策时可得信息；不含未来标签 |
| `strategies/` | 固定配置、内部状态、目标暴露及理由 | 行情/特征 → 账户无关目标；不下单或改持仓 |
| `risk/` | 定仓、限额、资金/仓位预算与拒绝原因 | 目标 + 只读账户 + 条款 + 预占 → 许可；不保存另一份余额 |
| `execution/` | 开平订单计划、身份、状态、发送尝试、撤单、未决预占 | 许可 → 有界订单；确认回报推进状态，UNKNOWN 保留预占 |
| `broker/` | CTP 协议映射、连接、查询、原始回报与接收证据 | 请求/回报适配；不决定目标、风险许可或通用账户规则 |
| `accounting/` | 资金、成交、费用、结算事实与持仓/权益投影 | 应用已确认事实并核对；请求不能提前改变持仓 |
| `simulation/` | 固定假设下的可成交条件、成交量/价格、费用估计 | 接收订单和后续市场事件；不拥有账户或研究任务 |
| `research/` | 计划、任务、尝试、评价、策略版本和候选 | 组织历史时钟与共享能力；模拟资金/成交明确标识 |
| `live/` | 账户实例、材料绑定、事件顺序、授权、控制和恢复 | 协調本地业务操作；真实/仿真成交只来自柜台 |

一个模块拥有唯一修改规则，不要求一个模块一个数据库或进程。
成交去重、入账、订单/预占推进与处理游标属于同一个完整业务提交，不能因拆包变成几次独立提交。
只读账户视图由账本及订单预占组合，缓存/检查点均可重建，不拥有独立事实。

`risk.RiskEngine` 固定合约、风险参数和条款修订，拥有下单前定仓、条款价格/有效期收紧及费用和保证金预算。
回测主循环及报告核对调用同一业务入口；已绑定条款不能通过省略参数或同名替换绕开。
风险结果不等于 Live 执行授权，柜台当前资金覆盖和未决订单仍须在生产会话执行处确认。

`execution.ExecutionEngine` 接管当前单目标路径的工作订单投影及保留/替换计划。
保留前由 Risk 按原订单价格上界重新计算费用和保证金预算；计划替换不会释放预占。
只有已确认的提交、撤单、失效或与本次已入账成交数量一致的更新才能推进投影；累计回报不制造成交。
回测的同步撤单仍明确属于历史模拟，柜台回报接入和发送前持久化需要另行接入，不能将此内存组件当成完整 Live OMS。

### 进程内消息总线

2026-09-10 按用户确认引入，参考 [Nautilus MessageBus](https://nautilustrader.io/docs/latest/concepts/message_bus/)
及其 [typed_router.rs](https://github.com/nautechsystems/nautilus_trader/blob/0608ce241d3ab3e2e4b5d66115c9b3cc71dbf439/crates/common/src/msgbus/typed_router.rs)
（审阅提交 `0608ce241d3ab3e2e4b5d66115c9b3cc71dbf439`）。借鉴类型路由和同步分发，独立 Python 实现；没有复制源码或新增依赖。

- 每个 Research/Paper 计算会话、每个 Live 接收循环通过 `TradingKernel` 独立创建 `MessageBus`，只能在创建它的线程/进程使用。Live 沿用 CTP 有界接收通道进入核心线程。
- `Endpoint[输入,结果]` 是唯一负责人命令/查询，调用者导入所属模块的同一个端点定义；`Topic[事件]` 按订阅顺序同步通知。主题精确匹配，定义放所属业务旁；不增加通配符、优先级或异步请求跟踪。
- 消息为所属模块的不可变值。总线检查精确类型，业务模块保证嵌套内容不变；Broker 回调字段只读，研究步骤的嵌套报告用不可变 JSON 保存。
- 嵌套调用按深度优先执行，禁止路由循环及分发中修改订阅。命令异常原样传回，业务负责人负责回滚/恢复；事件订阅者异常使总线故障，禁止继续分发，已提交事实不回滚也不自动重发。
- Research `advance` 经端点执行整步计算，成功后发布 `STEP_COMPLETED`；批量报告订阅该事件。暂存状态及未平仓批次，失败撤销新成交，不复制累计历史账本。此事件表示内存计算完成，Paper 的数据库提交仍由所属操作负责。
- Live 柜台回调经唯一接收端点进入原有原文保存、账户应用、影子推进。此版本不广播未提交成交，也未实现报撤单；后续执行端点在 #49/#32 中接入。
- 总线不保存历史、不负责幂等/交易授权、不连接三应用；Data Hub 继续用持久任务。关闭释放处理器；恢复重新装配，不能从路由状态推导发送权。

### 共享交易内核与环境适配

2026-09-10 再次核对 [Nautilus Architecture](https://nautilustrader.io/docs/latest/concepts/architecture/)
和 [Event sourcing](https://nautilustrader.io/docs/latest/concepts/event_sourcing/) 的 `latest` 文档；
沿用上文源码审阅身份，独立 Python 实现，无新增依赖。采用共同内核、单线程状态推进和环境适配；
不照搬进程全局注册表、无界接收队列或异步缓存持久化。

```text
Research/Paper runner                 Live 账户接收 runner
          └──────────────┬────────────────────┘
                    TradingKernel
                单线程入口 + MessageBus
                生命周期 + 失败/完成边界
                         │
               所属环境的事件处理器
                         │
      行情 → 策略 → Risk → Execution（含 OMS）
                           ↓
                       Accounting
                           ↓
                  Portfolio / Cache 投影
```

`Environment` 在内核构造时固定：`BACKTEST`、`SANDBOX`、`LIVE`。Research/文件驱动 Paper 为 BACKTEST，
两个 SimNow profile 为 SANDBOX，真实资金为 LIVE；三类共享 TradingKernel 和所属业务能力。
这是 Northstar 按资金用途采用的定义：2026-09-10 核对的 Nautilus latest 将外部柜台模拟账户也归入 Live，我们保留其适配器边界但不照搬该分类。
部署实例列表使用 `id:broker_profile`，自动推导不可变环境；独立启动使用 `NORTHSTAR_ENVIRONMENT` 与
`NORTHSTAR_BROKER_PROFILE`，不匹配即拒绝，真实资金仍未准入。协议/实例状态分别返回 environment 和 broker_profile。
环境进入研究结果、检查点和柜台接收绑定；SANDBOX/LIVE 不允许采用研究整步回滚策略。实际账户锁继续绑定柜台与账户，不能靠换环境标签取得第二份发送权。

图为组件关系；具体业务顺序仍遵循第 5 节，先应用已发生事实再计算新决策。
Kernel 不实现公式/撮合/账本，不增加独立账户缓存权威。当前处理器为 Research `TradingSession._process`
和 Live `LiveStreams.accept`：前者装配已有模拟/账户/策略/Risk，后者装配可靠接收/账本/行情/影子策略。
完整账户与执行模型按 #19/#20/#49/#32 替换所属组件，不能以共同入口宣称其业务已统一。

- 内核为 READY → RUNNING → CLOSED；无法安全继续时为 FAULTED，只能关闭并从事实重新装配，不提供自动重试/重新启用。
- 一次输入及其完成通知不可重入，跨线程/进程拒绝；关闭释放路由。进程内诊断计数不充当持久事件身份。
- Research 处理器显式承诺整步回滚，计算异常后允许调用者重试；完成通知在处理器成功返回后发布，通知失败使内核故障，不能撤销已经完成的事实。
- Live 默认任何处理异常均使内核故障，后续回调不得继续写入；原始接收/账户提交仍由原来的可靠事务负责。关闭内核不表示订单终态或账户空仓。
- `market_data.Instrument` 只保存合约身份、币种、最小价位与乘数等经济属性，不包含 K 线周期。固定研究输入、模拟适配器、策略订阅和检查点显式绑定周期；同合约不同周期使用同一账户定义，错误周期的输入或恢复在执行前拒绝。2026-09-11 查阅 [Nautilus Data latest](https://nautilustrader.io/docs/latest/concepts/data/) 的 Instrument/BarType 分离原则；没有引入其依赖，当前只实现固定秒数的完成 Bar，不把月线或交易日等同固定秒数。
- `market_data.DataEngine` 按合约、周期和固定来源登记行情订阅，路由完成 Bar，并持有每个流的不可变 `MarketWindow`。未订阅流、身份冲突、倒退时钟及迟到输入在策略前拒绝；重复输入不再分发。
  `strategies.Trader` 使用返回的因果行情帧计算，只在成功后一起提交 DataEngine 候选状态和策略状态；Research 整步失败时原投影保持不变。历史回放和 Live 完成行情均接入此路径，缓存不保存账户事实。
  2026-09-11 再查阅 Nautilus Data/Execution latest：采用按标的/周期/来源区分订阅、处理后分发的原则。当前接入的是已完成 Bar，CTP 原始行情采样与交易日规则仍由其适配入口负责，不宣称已具备订单簿或全部聚合类型。
- Trader 以固定实例标识、配置和行情流绑定策略；同一输入按实例标识稳定排序，任一策略异常时所有候选状态不提交。重复输入不重复产生意图，实例绑定进入意图身份；跨线程/进程、重入及关闭后推进均拒绝。Research 和 Live 完成行情已使用此所有者，未增加 Actor 或执行算法空接口。
- 当前窗口面向单合约完整 Bar，CTP 采样仍由柜台适配器产生标准化 Bar；Trader 已管理固定策略实例的共享订阅与原子状态提交；这不代表多策略账户预算、归因、统一执行算法或完整 Live 跨日账户已完成。
- 回测和当前文件驱动 Paper 都从历史输入推进，Environment 为 BACKTEST；SimNow 为 SANDBOX，真实资金为 LIVE。SimNow 始终采用外部柜台成交，不能以本地撮合替代。环境名称不授予交易。
- 一个 Live 账户所有者独立进程与本地 SQLite；Research 用独立计算进程并行，Web/API 继续独立监管。串行处理不保证外部输入天然可重放，仍需固定输入顺序、时钟与配置身份。
- 网络接收、普通日志和归档可在外围；发送前身份/预占必须可靠提交，成交去重与账本更新保持事务一致，不能统一改成异步后置。

## 4. 数据、条款与研究输入

```text
Tushare → 原始响应 → 响应校验 → 规范化/质量 → 固定研究清单
                                                   ↓
Research：清单 + 只读 Parquet → 固定计划 → 任务/尝试 → 结果/候选
```

Data Hub 仅自动同步 Tushare 全部期货历史数据；没有手工上传、下载范围选择、Tick 或实时 Recorder。

## 5. 国内期货账户与事件顺序

目标账户保留多/空、今/昨仓，不用相反方向开仓自动抵消持仓。订单与成交分别明确开仓、平今、平昨或经验证的平仓规则。
Execution 根据账户仓位、未决冻结和交易所规则生成开平计划；SHFE/INE 等差异经独立验证，不硬套单一净仓模型。

Accounting 的输入为明确身份的成交、费用/调整、资金流与逐日结算事实。费用未知不填零，也不拒收已确认成交。
共享 Account 接受已确认的零余额或负余额，不因欠款拒收成交或无法重放；
模拟初始资金必须为正的约束留在 SimulationConfig，账户记账不替代 Risk 准入。
必要的费用、资金、结算或持仓事实未确立时，账户保持未完整核对，禁止新增风险，不能靠默认值恢复许可。
Accounting 拥有费用与结算计价规则；Simulation 根据固定条款生成模拟费用事实，Risk 用相同规则计算预算。柜台费用以确认事实为准。
日结算更新持仓结算基准并确认对应盈亏，不等于平仓；今昨仓迁移、费用、保证金与权益必须逐项勾稽，重复事件不重复入账。
今昨仓迁移按确认的交易日结算边界推进，不按自然日零点。
柜台余额/持仓查询是独立核对证据，不能覆盖本地账本以制造“核对成功”。账户累计费用不能重复当作新增费用。

成交量参与约束不能使用委托生效前累计的成交量。停市、无成交量、超价、过期及缺条款均有明确结果；数据结束不编造平仓。模拟成交带独立身份，永不冒充柜台事实。

## 7. Live 控制、身份与恢复

公网/局域网可访问不等于操作者已认证；Protobuf、Host/Origin 和 CSRF 不证明用户身份。
三个工作台各自验证单一操作者 `owner`，不限制访问 IP，也不共享账号数据库或会话。
`web` 负责 Protobuf 登录、注销和会话查询；所有管理 API 在进入业务前校验服务器会话，写操作再校验 CSRF。
只读发布接口供跨主机机器访问，保持独立于管理身份；登录不连接柜台，不授予交易执行许可。
密码只保存为各应用配置的 `NORTHSTAR_WORKSPACE_PASSWORD_HASH`；API 启动加载摘要，重启撤销全部旧会话。
首次部署未配置摘要时生成随机密码并仅在部署终端显示，后续即使显式替换配置而未填写新摘要，也保留已安装摘要。
更换密码通过 CLI 生成新摘要并显式部署；没有匿名注册、通用默认密码或前端保存密码的路径。
会话为服务端随机身份，30 分钟绝对有效期；Cookie 为 HttpOnly、SameSite=Strict，HTTPS 使用 Secure。
注销、轮换登录和 API 重启均使对应旧身份失效。操作日志仅记录服务器确认的操作者、路由模板、方法和状态，不记录请求体或凭据。
浏览器未知命令只保存命令身份、路径和实例，不保存请求体；登录失效不删除 UNKNOWN 身份，也不重发操作。
2026-09-11 参考 [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)：
使用 Python 标准库 scrypt（N=2^17、r=8、p=1、随机盐）；校验固定摘要格式，单应用同时只执行一次密码计算，每分钟至多 5 次尝试。
哈希计算在 Web 工作线程，不进入交易内核；不引入中心认证服务。
前端仅选择固定实例，不能修改其环境、账户或凭据；旧请求/未确认命令不能转发到另一个实例。

管理命令通过当前内部协议 3 传递可信操作人：Web 从已认证会话绑定 `owner`，本机 CLI 为 `maintenance`，浏览器自报字段不参与身份判断。命令回执可靠保存操作人、输入、时限与运行实例，同一命令身份不能更换操作人；历史未记录身份的事实不补造归属。回执查询使用统一 `request_id`，重启后查询不重复执行。此身份记录不等于交易发送授权。 SQLite 与 PostgreSQL 同时约束命令身份及终态不可改写/删除，状态只能从受理中的 RUNNING 变为最终回执；重启读出的 UNKNOWN 不会重新获得执行权。

默认无发送。授权绑定环境、账户、合约、策略/配置、代码、时窗和限额；重启、重连或恢复必须重新核对后显式启用。
暂停新增风险不等于撤单，撤单请求不等于确认撤销，请求平仓不等于已经空仓；既有订单继续接收回报。
未知发送结果保留订单身份与预占，只查询核对，不盲重发。所有权过期、复制数据库或连接恢复均不能自动产生第二发送者。

## 8. 交付原则

原生 CTP 接收进程现在具有显式注入的私有订单通道；未提供通道的查询/接收
没有报撤单输入。核心线程仅向容量为一的队列提交，不同步等待 SDK；接收循环
非阻塞核对请求编号、返回和超时。原生线程在登录/查询/订阅确认后才处理请求，
检查账号、操作、编号与有界截止时间，拒绝重复或过期请求，再构造原生结构。
本地排队返回不代表 SDK 返回，更不代表柜台受理；原生返回码由 RequestSent 原始证据保存。
不确定传输封闭该通道并停止会话，不重发；报撤单拒绝本身不关闭行情/回报接收。
脚本化 SDK 的实际 spawn 进程已验证有界发送、撤单拒绝、超时和子进程回收；
没有外部柜台连接。管理端运行授权与当前账户事实检查仍需接入，不能直接调用此通道。

### 当前运行实例的执行限额同意

`live.ExecutionAuthority` 保存 owner 明确同意的账号、接收会话、合约、固定配置、
截止时间、单笔手数/金额和累计委托手数。会话固定其创建运行实例；新内核不能
对遗留 RECEIVING 行重新授权。授权与撤销不可改写，恢复后的许可属于旧运行实例，
不能自动生效。维护客户端没有同意权限。

`admit` 在 OrderJournal 的订单/预占事务内核验当前同意、运行实例、会话状态、
合约、期限及限额，然后必须执行所属账户/风险的当前就绪检查。许可不证明
账户已核对，也不能覆盖市场、条款、未决委托和入账完整性要求。累计委托额度
按已持久承诺的数量消耗；拒单不自动返还，避免一次同意被无限重复使用。

独立 Live Web 通过拥有的 Protobuf 接口展示、提交和撤销许可，运行时接口版本为 4；
页面明确“同意限额”与“可以下单”的区别。当前管理端仍未开放实际报撤单，
原生通道和这些许可还须接到同一个账户/风险就绪执行路径。

### 成交发生时间与接收时间

2026-09-11 再次核对 NautilusTrader latest Architecture / Event Sourcing，
继续采用不可变事实重放及接入边界，未引入运行依赖。Northstar 的
`accounting.fills.FillFact` 同时固定 `filled_at` 和 `available_at`；
适配器必须提供明确 UTC 接收时间且不早于成交时间。账户按可得顺序消费，
不同合约的迟到回报不因另一个合约先发生而被拒绝。每个合约保留发生顺序，
倒序成交及结算边界冲突要求核对，不能事后重排 FIFO 来隐藏缺失事实。
模拟器目前在执行事件可得时确认成交，两种时间相同，不能冒充 Tick 级实际成交时间。
Research 会话实现版本同步为 20；订单日志和研究账本恢复读取完整的新事实格式。

### 成交与费用的分别确认

成交事实的费用可以明确为未知，不能填零。`Account` 立即保存成交数量与 FIFO
计价，但只要存在未确认费用，现金与组合估值接口就拒绝提供可用于新增风险的余额；
检查点明确返回未知现金，并列出待确认成交。实际已知费用、平仓与结算仍可记账，
不会因为等待另一笔费用而丢弃已经发生的事实。

`FeeFact` 固定费用身份、币种、总额、明确覆盖的成交集合、发生/可得时间及来源。
同一费用只扣一次；不得覆盖已计费成交，不向每笔成交猜测分摊金额。部分覆盖后仍
保持未知现金；明确核实的零费用是一笔事实，不能由缺失数据自动产生。
费用修订通过 `supersedes_fee_id` 指向当前收费事实，保持同一成交集合与币种，
以新的非负总额替代旧总额，只将差额计入账户；负差额表示退款。每笔修订有独立
身份、来源和因果时间，拒绝缺失前项、分叉、倒序及范围变更，旧事实永久保留。
OMS 在同一写事务保存修订和账户变动，恢复按事件顺序校验完整修订链。退款不会
自动解除此前超预算留下的冲突，也不改变成交事实。当前修订覆盖独立确认的
聚合费用，不支持更改成交内已固定的费用或用累计 Commission 猜测成交覆盖。

2026-09-12 对照 NautilusTrader `latest` [Execution](https://nautilustrader.io/docs/latest/concepts/execution/)
的执行事实与历史修正边界：Northstar 采用保留原事实、显式修订和重放核对，
费用差额与订单预占由各自所有者在一个事务内协调；未引入其运行库或照搬成交撤销规则。

OMS 对已成交但费用未知的手数保留手续费预算。确认费用、对应订单预占释放及
所属账户扣账使用同一 SQLite 写事务，任一失败共同回滚。费用超过原覆盖预算时
仍记实际扣费，同时将关联订单保留为待核对；成交价格或已知费用越界也不丢弃事实。
重启逐笔核验完整费用覆盖与所有订单关联，缺失关联不可当成已完成。Live 订单页面
分别显示成交与费用待确认手数，成交终态不表示现金账本已完整。

CTP 的累计 Commission 观测本身不能创建 FeeFact，必须先由 Broker/Accounting
核实账户范围、执行覆盖与核对截面。这项共享账本能力不宣称外部资金核对已经完成，
也没有开放从页面输入一个费用数就修正生产账本的通道。

### CTP 逐笔成交与订单/账户的共同提交

2026-09-11 核对 vnpy_ctp main 的 `onRtnOrder` / `onRtnTrade`：以交易所
OrderSysID 关联委托再发布成交。Northstar 借鉴此边界，额外固定账号、环境、
交易日、交易所和已验证的本地请求；不依赖进程内字典恢复身份，也未复制网关实现。
参考：https://github.com/vnpy/vnpy_ctp/blob/main/vnpy_ctp/gateway/ctp_gateway.py 。

`broker.execution_fills` 接收已持久保存的原始回报，仅在交易所订单身份已确认时
关联本地订单。先到的成交保留原始账户证据，后续订单身份建立时本地补处理；
未知外部订单不猜成本地订单。首次匹配固定成交可得时间，后续重复接收只增加
来源证据；经济字段冲突保留原始冲突回报并停止推进，不修改先前成交。

匹配后的 OMS 逐笔数量、费用待确认预占、CTP 成交关联及账户回报处理进度
共用 SQLite 写事务。账户失败共同回滚，原始接收记录仍在；策略暂停不丢弃
实际成交。启动和联合恢复核对原始回报、交易所身份、OMS 事件及所属账户的
完整固定前缀，缺少任何关联不能宣称完成。

当前原始 BrokerLedger 仍只证明逐笔持仓事实；它不是已经核对的现金账本。
CTP 成交的费用保持未知，完整现金核对与当前有效条款仍是开启执行的前置条件。
这些本地检查不替代真实 SimNow 接入及明确授权的非空交易验收。

研究报告从逐步核对后的权益轨迹生成按交易日/月份的观察区间收益、20 个已观察交易日滚动收益和回撤区间。夜盘按显式交易日归属；缺日期不补零，未恢复回撤保留至最后观察，资本非正后的比例留空。2026-09-11 查阅 [QuantStats stats.py main](https://github.com/ranaroussi/quantstats/blob/main/quantstats/stats.py) 的分期复合收益与回撤报告思路；只参考职责，Northstar 使用现有 Decimal 账本，不新增依赖或复制实现。月份和日末都是输入覆盖内的最后观察，不冒充完整收盘结算；不推算年化、夏普或完整交易日历。

### 恢复时重建账户观察与持仓核对

柜台查询的完整性、字段投影和权限状态先从原始回调重建，拒绝修改投影后重新
计算哈希的结果；账户基线、基线比较、持仓入账和持仓比较再从保留的查询或流前缀重新推导；
哈希只证明字节对应，不能替代这些业务核验。`position_projection` 由入账与恢复
共同调用，重新解码成交、去重、检查问题、计算今昨仓，并重算独立查询的差异。
来源范围、账户、合约和因果时间一并核验；不能通过同时修改 JSON 和哈希隐藏
成交、价格、持仓差异或把只读观察改成执行许可。恢复仅验证，不修复来源和目录。
资金字段以固定顺序比较，避免数据库 JSON 对象的键顺序影响跨存储恢复。
这仍是同日、初始空仓的柜台观察和持仓核对，不代表完整资金或跨日结算已完成。

### Live 柜台事实的共享 FIFO 投影

`BrokerLedger.context` 从经重建验证的初始空仓基线、成交前缀及本机合约信息，
调用 `accounting.broker_account` 转换成明确的外部 `FillFact`，复用 Research 的
`Account` 计价；外部订单身份不伪装成本地发送尝试。行情元数据以 `Instrument`
值交付，不把 ORM 行交给计算模块。读取不修改原始成交或另存一份可变账户。

工作台通过 `BrokerAccountProjection` Protobuf 显示费用前已实现盈亏与费用待确认
笔数，Decimal 金额以字符串传输。当前 CTP 成交没有逐笔费用、完整资金流和结算
覆盖，因此现金始终不提供为可交易余额，总费用保持未知；计价失败也不丢弃柜台事实。
该投影只补齐共同计价调用，不是当前账户就绪证明或完整跨日生产账户。
