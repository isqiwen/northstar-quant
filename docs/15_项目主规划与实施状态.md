# 项目主规划与实施状态

> 状态：执行中<br>
> 生效日期：2026-08-10<br>
> 适用范围：Northstar Quant 的研究、回测、仿真、执行、运维与未来实盘准入<br>
> 本文件是项目未来工作的优先级事实来源；与旧专题文档冲突时，以本文件的阶段门禁为准。

## 1. 项目定位与总原则

Northstar Quant 的目标不是快速堆积策略、资产类别或界面，而是成为一个**可审计的中国商品
期货研究系统**，并在满足严格条件后逐步演进到受控交易系统。

项目必须遵循以下原则：

1. **研究可信优先于功能丰富。** 连续合约收益、短样本或单次回测不能证明策略可交易。
2. **数据可信优先于模型复杂。** 没有权威日历、会话、合约链和动态规则时，任何更复杂的
   信号都不会提升结论质量。
3. **失败关闭优先于便利。** 数据、账户、订单、风控或对账未知时，必须停止升级风险或提交
   新订单。
4. **可复现优先于可展示。** 每次研究结论必须能定位到数据、画像、代码、目标权重和结果
   指纹。
5. **实盘是独立风险项目。** `paper`、`ctp_sim`、日线回测或分钟回放成功，都不能视为真实
   CTP 或实盘授权。
6. **保持模块化单体。** 在真实业务压力出现前，不引入微服务、多账户集群或多资产平台。

## 2. 当前能力基线

| 能力层 | 当前状态 | 可作出的结论 | 不可作出的结论 |
| --- | --- | --- | --- |
| 连续合约 `weight_return` | 可用 | 快速筛选信号方向、参数和组合 | 保证金、换月、真实成交或账户收益 |
| 实际合约日线 `futures_daily` | 可用 | 在现有研究数据上验证动态费率、保证金、涨跌停、换月、限仓和参与率 | 真实账户费率、权威日历完整性或统计显著性 |
| 实际合约分钟回放 | 可用但专项 | 研究盘口、部分成交、TTL、撤单和先平后开 | 未经校准的真实队列位置和网络延迟 |
| 可审计回测制品 | 可用 | 数据/配置/目标/代码指纹、报告、JSON、PDF 可追溯 | 多实验横向研究管理或策略审批 |
| `ctp_sim` | 可用但有限 | 本地期货语义、今昨仓、保证金、异步回报和恢复演练 | 期货公司 CTP 前置可用性 |
| `paper` | 基础设施验证 | 通用订单、账本、对账和报告协作 | 期货保证金、结算、平今平昨或真实成交 |
| 真实 CTP / production | 未实现 | 无 | 不得创建或启用真实交易路径 |

当前内置实际合约画像使用研究级公开数据，配置区间为 2026-03-26 至 2026-06-30。60 日
信号窗口之后的有效评估期很短，因此报告正确地拒绝展示伪精确的年化统计。它是端到端工程
验收样本，不是策略有效性样本。

## 3. 不可跳过的依赖链

```text
P0 工程与研究准入基线
→ P1 权威数据、日历与规则供应链
→ P2 策略实验与样本外验证
→ P3 实际合约可交易性与期货归因
→ P4 CTP 仿真与风险状态机
→ P5 真实 CTP + 期货公司模拟前置
→ P6 受控实盘试点
→ P7 稳态运营与逐步扩展
```

任何阶段的验收失败都应回退到前一阶段修复，不得通过降低测试、关闭风控或修改报告文字来
绕过门禁。

## 4. AI 实施协议

AI 应按本文件中未完成的最高优先级工作推进，但权限分为三类：

| 类别 | 工作示例 | AI 可否直接实施 |
| --- | --- | --- |
| 绿色：本地工程 | 文档、测试、CI、类型化配置、回测逻辑、模拟测试、报告、迁移草案 | 可以；必须附测试与验收结果 |
| 黄色：外部依赖 | 数据供应商评估、数据许可、期货公司模拟前置申请、生产数据库方案 | 可以准备接口、验收规范和导入工具；不得假定供应商或凭据已经存在 |
| 红色：真实资金/外部交易 | 创建 production 画像、填写 CTP 凭据、提交/撤销真实订单、启动非 paper 调度器 | 不得执行；必须获得用户的明确目标、账户、画像和确认 |

每项实现必须同时更新：代码、测试、配置、文档和必要的 Alembic 迁移。完成条件是质量检查
通过，而不是“命令看起来能跑”。

## 5. 阶段路线图

### P0：工程与研究准入基线

**目标：** 让任何开发者都能在隔离环境中稳定运行、测试和理解研究边界；清除配置与文档
的“看似生效”风险。

| 编号 | 工作项 | 状态 | 验收标准 |
| --- | --- | --- | --- |
| P0-01 | 固化本主规划、能力矩阵、升级门禁和 AI 实施协议 | 本变更完成 | 文档已链接至 README，阶段、依赖和红线明确 |
| P0-02 | 建立 PostgreSQL 驱动的 GitHub Actions CI | 本变更完成 | CI 使用隔离 `northstar_test`，运行迁移、pytest 与 Ruff |
| P0-03 | 完善本地开发引导 | 本变更完成 | macOS/Linux 与 Windows 均有安全入口，创建/确认开发 PostgreSQL 和 `northstar_test`；Windows 明确要求操作者先创建本地 `.env`，不会覆写任何密钥 |
| P0-04 | 收敛运行时配置事实来源 | 本变更完成 | 已移除未接入运行时的 `configs/risk/global.yaml` 和 `configs/portfolio/multi_strategy.yaml`；有效参数以交易画像为唯一来源 |
| P0-05 | 类型与质量基线 | 本变更完成 | 固化 89 条 mypy 诊断的精确基线；CI 校验实际快照，PR 对比目标分支并拒绝新增诊断；pytest 对遗留 SQLite `.env` 注入仅进程内的 PostgreSQL 测试默认值，后续只允许减少 |
| P0-06 | 文档一致性契约 | 本变更完成 | 核心文档链接、Windows/macOS/Linux 引导、安全默认值、已移除配置和新手教程 Python 示例均由 contract 测试验证 |

**本阶段禁止事项：** 扩展真实 CTP、启用生产画像、把公开数据结论作为交易结论。

**类型债务治理：** 当前基线保留 89 条历史 mypy 诊断，不代表项目已类型清洁。执行
`uv run python scripts/check_mypy_baseline.py check` 会要求实际诊断与版本化快照完全一致；
只有显式执行 `emit`、审阅输出并提交快照后才可记录已修复的结果。PR 还会与目标分支快照
比较，任何新增诊断都会失败，减少诊断则被允许。

### P1：可信中国期货数据、日历与规则供应链

**目标：** 建立可授权、可版本化、可回放的数据基础。

- 数据供应商、授权边界、目标品种和候选研究门槛已固化为版本化配置；具体候选、数值、
  状态和人工激活步骤只在[研究准入政策与数据治理](16_研究准入政策与数据治理.md)维护。
  在合同与书面证据齐备前，所有商业来源必须失败关闭，AI 不得购买服务、创建账户或假定
  合同/凭据存在。
- 建立 `raw → normalized → derived` 三层数据制品；每层保存来源、获取时间、内容哈希、
  schema、供应商版本、转换版本和质量结果。
- 接入权威交易日历：节假日、夜盘归属、特殊开闭市、到期/交割限制和品种级会话。
- 保存逐日主力选择、保证金、手续费、涨跌停、限仓和实际合约状态快照。
- 覆盖多个市场状态的多年实际合约数据，并满足已激活研究政策的历史长度和覆盖率要求。

**验收标准：** 目标品种交易日、会话和规则快照覆盖率为 100%；任一未知缺失、未来规则或
断裂合约链都会失败关闭；任一历史研究可按旧数据版本复跑，更新不会覆盖旧版本。

### P2：策略实验与样本外验证

**目标：** 让策略研究从单次回测升级为可比较、可复核的实验。

- 建立 `ExperimentSpec` 与 `ExperimentRun`：策略版本、参数空间、训练/验证/OOS 区间、
  数据版本、成本情景、随机种子和审批状态。
- 提供参数敏感性、walk-forward、滚动训练、固定样本外区间与成本/滑点/延迟压力测试。
- 建立策略模板和契约测试：未来函数、显式平仓、参数边界、数据缺失、上市不足、换月和风险
  上限。
- 先扩展少量可解释策略；机器学习、强化学习和大规模因子库在本阶段验收前不进入主线。
- 定义期货组合风险预算：单品种、交易所、相关性簇、波动目标、杠杆和回撤降风险。

**验收标准：** 每个候选策略都有独立 OOS、多个市场阶段、参数邻域稳定性和成本压力结果；
数据、代码、参数或目标变化会生成新的实验 ID。

### P3：实际合约可交易性、归因与研究决策

**目标：** 验证“研究收益”是否能在实际合约约束下保持成立。

- 将 `futures_daily` 固化为低频候选策略的主判定引擎。
- 校准实际账户手续费/保证金快照、滑点、成交量参与率、容量、延迟、换月、涨跌停和强平场景。
- 将 `performance` 演进为期货专用归因：多空、乘数、平今/平昨、换月、费用和未平仓头寸；
  不得把 fill event 当作闭合交易。
- 建立研究卡和实验比较：样本/OOS、基准、回撤期、品种贡献、暴露、成本、容量、换月、
  保证金、约束和失败事件。

**验收标准：** 连续合约与实际合约结果差异可解释；每个候选策略在预先定义的成本、容量、
换月和保证金压力下仍满足门槛；跨引擎不同口径的指标不允许直接横比。

### P4：CTP 仿真与风控闭环

**目标：** 在本地 `ctp_sim` 中证明异常时系统不会增加未知风险。

- 明确 `research`、`paper`、`ctp_sim`、`production` 四类生命周期和调度权限。
- 实现风险状态机：`NORMAL → LIMIT_ONLY → REDUCE_ONLY → HALT → MANUAL_RECOVERY`。
- 将全局风险政策接入运行时，或正式删除未接入配置；运行时风险不仅能阻断新开仓，还须定义
  降风险、人工平仓和恢复流程。
- 建立故障注入：断网、重启、迟到/重复回报、部分成交、撤单失败、未知订单、价格停滞、
  涨跌停、保证金突增、夜盘跨日和平今/平昨。
- 建立数据新鲜度、目标批次、订单状态、执行租约、风险门禁和对账差异的监控与 runbook。

**验收标准：** 每个故障均证明“不重复下单、不放行未知订单、不静默超风险”；订单、成交、
持仓、资金和保证金日终对账全部有分类和责任归属。

### P5：真实 CTP 与期货公司模拟前置

**目标：** 仅接入期货公司模拟环境，完成真实柜台语义验证。

- 独立实现 `CTPBrokerAdapter`：认证、结算确认、报单、撤单、回报订阅、查询、重连与
  账户/合约身份映射。
- 使用密钥管理、账户白名单、真实数据提供器白名单和最小权限；不得把凭据写入仓库。
- 未知提交状态必须阻止新订单，直到通过查询与对账恢复确定状态。
- 先 shadow，再以极低风险在期货公司模拟账户下单；每日生成对账、滑点、偏离和异常报告。

**验收标准：** 在期货公司模拟前置持续至少 20 个交易日并覆盖夜盘/节假日场景；订单、成交、
持仓、资金和保证金逐项可对账；kill switch、重启、恢复和人工处置均有演练记录。

### P6：受控实盘试点

**目标：** 在明确授权下，以最小可承受风险验证真实运行，而不是追求规模。

- 一个账户、一个 production 画像、少量品种、极低额度和人工双确认。
- 禁止策略/参数当日热变更；每日对账、每周复盘；触发红线自动降级为 shadow 或人工模式。
- 完成备份、PITR、恢复演练、RTO/RPO、容量、连接池、审计归档和发布回退。

**验收标准：** 策略、风险和运维负责人共同批准；连续稳定运行并完成所有对账；任何红线触发
均有自动保护和人工恢复证据。

### P7：稳态运营与逐步扩展

在 P6 稳定后，才逐品种、逐账户扩展，完善 HA、监控 SLO、容量、变更审批、组合管理和
灾难恢复。不得一次性扩大账户、品种或自动化权限。

## 6. 研究与安全门槛的所有者决策

研究准入的具体供应商、品种和数值阈值由
[研究准入政策与数据治理](16_研究准入政策与数据治理.md)及其 YAML 配置唯一维护。项目
所有者必须在激活政策前书面确认或修改；它们不能硬编码在策略里，也不能被单次回测绕过。
所有者需要确认的类别包括：

- 最小 OOS 年数、交易次数和市场阶段覆盖；
- 最大允许回撤、保证金占用、单品种/交易所暴露和容量；
- 成本、滑点、延迟和流动性压力倍数；
- 允许的缺数据、会话、规则或对账差异数量；
- 每一阶段的审批人、暂停权、恢复条件和复盘频率。

## 7. Definition of Done

任何开发任务完成前都必须满足：

1. 变更范围与本规划的阶段编号一致；
2. 有针对性的 unit/integration/contract 测试；涉及数据库时有 Alembic 迁移；
3. `uv run ruff check .` 与相关测试通过；
4. 报告、配置和运行说明同步更新；
5. 不削弱 kill switch、preflight、订单幂等、对账或失败关闭行为；
6. 若需要外部授权、账户、凭据、供应商或真实交易，明确停止并请求用户决定。
