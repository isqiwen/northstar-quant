# 开发路线

第一轮目标是打通完整回测与 Live Sim（柜台仿真资金），最终再进入受控实盘。
当前已实现能力见 [架构](ARCHITECTURE.md)，下列内容是待交付目标。

## 第一轮：数据 → 完整回测 → Live Sim

| 顺序 | 交付结果 |
|---|---|
| 数据基础 | 一个获准来源自动采集、增量更新与补数；独立持久执行，重启不丢任务，缺口与失败可见 |
| 数据整理 | 明确合约、日历、时间、单位与有效条款；固定清洗规则，保留原始证据，异常隔离，重处理产生新版本 |
| 数据查看 | K 线、成交量、时间范围、覆盖与缺口、异常明细、清洗前后差异、来源和发布血缘；范围查询与导出 |
| 完整回测 | 单策略、单真实合约，覆盖夜盘/日盘及多个交易日；连续账户、结算、今昨仓费用、保证金与受约束模拟成交 |
| 研究运行 | 固定数据/参数/代码，独立持久 worker、进度/取消/中断恢复、逐笔交易/资金/净值/回撤与同条件评价 |
| Live Sim 基座 | 同一 Live 内核、独立前端/API/存储；固定材料绑定、明确仿真环境、运行健康与独立告警，不要求先采购云主机 |
| Live Sim 执行 | 核对仿真账户与行情，先落实授权、订单身份、预占、唯一发送者及 UNKNOWN 保护，再报撤单、确认成交与记账 |
| 控制与恢复 | 启停、暂停新增风险、撤单/请求平仓、重连核对、受控恢复和联合备份；管理端退出不拥有内核停止权 |
| 第一轮验收 | 网页从自动数据到跨日回测，再把固定候选绑定到 Live Sim，完成仿真开平仓、对账、故障恢复及市场段归档复盘 |

“完整回测”首先限定为一个实际策略和真实合约的跨日完整业务链；多合约、自动换月和多策略账户另行交付。
研究输入须包括范围内适用的结算和条款，缺少必要事实时拒绝继续，不以默认常数猜测。
不能以一次 CSV 样例运行、只读行情、影子信号或内部 Paper 成功宣布第一轮完成。

## Data Hub 的职责

- 来源目录：用途许可、频率、覆盖、获取方式、凭据引用和来源健康；先接通一个实际来源，再按需求扩展。
- 自动采集：历史下载、定时增量、断点/水位、限流重试、补数、任务审计和积压/磁盘告警。
- 清洗与质量：时间/交易日/单位标准化、去重、冲突、缺失和异常诊断；禁止静默补价格/成交量或覆盖原文。
- 图形检查：行情图、覆盖日历、质量分布、异常定位与修订对比；图表降采样与原始明细分开，不能篡改研究数据。
- 发布与复用：不可变快照、内容身份、血缘与引用、按范围读取/导出；行情、结算价和适用条款可追溯。
- 生命周期：容量、受保护引用、保留/清理预览、数据库与文件联合恢复；清洗数据不等于删除证据。

Data Hub 不充当 Live 必需的实时行情中转，不拥有交易账户真相；Live 独立取得行情和柜台回报。

## Live Sim 与真实 Live

使用同一套 Live 会话、策略、Risk、Execution、Broker、Accounting、控制和恢复规则。
第一轮只允许明确绑定的仿真环境/账户/凭据/条款与授权；资金和成交事实来自柜台仿真账户，不能混入生产数据。
不得为 Sim 简化发送前校验、预占、去重或未知结果处理，也不另建 Paper 风格的自动撮合发送路径。

仿真柜台与生产市场的成交、流动性、费用/结算能力可能不同，应记录实际能力和限制，不能保证市场行为完全相同。
真实开户、生产准入、生产环境接入和用户本人启用真实资金属于后续独立阶段。

## 后续阶段

第二轮处理受保护云部署、生产机构/账户准入及有独立授权和限额的真实开平仓。
高级因子挖掘、多合约组合、自动换月、多策略资金分配按实际需求后置，不挤占第一轮闭环。
