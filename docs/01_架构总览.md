# 架构总览

Northstar Quant 是**模块化单体**：研究、回测、执行和报告位于一个可测试的 Python
应用中，而不是分散为难以审计的微服务。核心原则是单向依赖、数据可复现、外部副作用
可追踪，以及交易路径默认失败关闭。

## 两条主流程

研究与回测不读取账户，也不提交订单：

```text
交易画像 + 已验证数据制品
  → canonical strategy pipeline
  → portfolio / risk target
  → profile-selected backtest engine
  → immutable run manifest + report
```

账户相关路径只在未来合格的 production 画像中可用：

```text
冻结日频目标
  → 最新账户 / 行情 / 风险状态
  → preflight
  → execution plan
  → pre-trade checks
  → broker adapter
  → reconciliation + audit records
```

执行计划不是券商订单。任何一个必要输入、风险结论、数据授权或合约映射缺失时，路径必须
停止，不能以估算值、旧快照或连续合约替代。

## 模块职责

| 模块 | 职责 | 不负责什么 |
| --- | --- | --- |
| `common` | 值对象、订单状态和数量规则 | 市场、账户或配置 I/O |
| `config` | Settings、交易画像、数据源、品种池和研究准入政策的严格加载 | 下载、下单或修改环境 |
| `data` | 下载/导入、标准化、schema 校验、manifest 与存储 | 把公开数据升级为实盘授权 |
| `indicators` | 纯行情到特征计算 | 策略组合或下单 |
| `strategies` | 策略注册、输入契约与目标权重 | 账户资金和订单数量 |
| `portfolio` | 多策略目标合成 | 成交或券商状态 |
| `risk` | 研究与交易前风险检查 | 绕过 preflight 或 broker 门禁 |
| `backtest` | 连续收益研究、实际合约日线、分钟订单回放和准入评估 | 真实交易收益承诺 |
| `execution` | 执行计划、路由、paper/ctp_sim 适配器 | 真实 CTP 报单（尚未实现） |
| `live` | 目标冻结、风控、preflight、调度和对账编排 | 绕过 lifecycle 或数据门禁 |
| `db` | ORM、迁移、仓储和运行审计 | 业务策略计算 |
| `monitoring` | 健康检查、告警和运行健康 | 代替风控决策 |
| `reporting` | Markdown、JSON、PDF 和邮件制品 | 重新计算或篡改回测结果 |
| `performance` | 独立的绩效计算工具 | 当前回测报告的唯一权威口径 |
| `cli` | 命令编排入口 | 隐藏安全检查 |

`performance` 目前仍是独立工具模块；回测报告的权威指标来自对应回测引擎和
`backtest.runner`。在统一期货成交归因接入前，不应把该模块的 long-only 交易分析结果
与期货回测统计混为同一口径。

## 策略与回测边界

策略按**输出语义**组织：目标权重、执行意图或交易计划。当前标准回测只接受目标权重，
并要求策略在平仓日显式输出 `target_weight: 0.0`；省略一行会被下游时间序列视为旧目标
延续，从而错误持仓。

低频研究使用三层验证：

1. `weight_return`：连续合约快速筛选；
2. `futures_daily`：实际合约、保证金、费用、换月和参与率验证；
3. `futures_intraday_replay`：仅在订单生命周期或容量会改变结论时使用。

数据字段、执行时序和适用边界由 [期货回测器说明](12_期货回测器说明.md) 唯一维护。

## 依赖边界

`tests/contract/test_architecture_boundaries.py` 校验包级依赖无环，并要求核心层遵守：

```text
common    → 无内部依赖
config    → common
risk      → common
data      → common, config, logging_
execution → common, config, risk, logging_
db        → common, config, execution, logging_
```

共享语义应下沉到 `common`；跨边界协调应发生在 `runner`、`live` 或 `cli` 等明确的
composition root，而不是在低层模块之间形成反向依赖。

## 真实交易状态

已有 `paper` 和本地 `ctp_sim` 基础设施，但真实 `CTPBrokerAdapter`、production 画像、
经授权的实时数据和期货公司模拟前置演练均未完成。因此真实资金路径仍被阻断。当前
能力、已阻断功能和后续前置条件见 [执行与安全边界](04_实盘执行现状与增强说明.md)；
阶段门禁见 [项目主规划与实施状态](15_项目主规划与实施状态.md)。
