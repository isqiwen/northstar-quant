# 按运行生命周期拆分四个角色，保持一个项目

本地数据/研究与云端交易具有不同的可用性、资源和权限要求，工作台更新不能结束交易接收，
因此选择一个仓库、一个 Python 包中的 Data、Research、Live、Console 四个运行角色，
替代单应用生命周期作为目标部署；Strategy、Risk、Accounting 继续共享进程内计算，
不拆成逐次网络调用的 Module，也不建立公共协议仓库。

独立 Live 持有实时输入、账户事实及执行权，本地管理和异步归档不进入交易必需路径。
代价是需要明确跨进程命令、产物身份和分域恢复；先交付 Live/Console 独立运行并继续仿真交易，
不以完整数据或研究平台为前置。只维护当前实现和协议，固定版本及历史证据不构成兼容承诺。
当前能力、目标职责与实施切片见 [架构](../ARCHITECTURE.md) 和 [开发顺序](../ROADMAP.md)。
