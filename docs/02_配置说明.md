# 配置说明

Northstar Quant 目前不是一个“所有 YAML 逐层覆盖”的统一配置系统。不同配置文件有明确且彼此独立的职责。

## 运行时 Settings

`src/northstar_quant/config/settings.py` 使用 Pydantic Settings 管理运行时参数：

1. 显式构造参数
2. `NORTHSTAR_*` 环境变量
3. 当前工作目录的 `.env`
4. 代码中的安全默认值

数据库、券商、账户、告警、SMTP、运行目录和全局调度参数属于这一层。`.env` 是本地文件，不得提交。

关键安全默认值：

```text
NORTHSTAR_BROKER=paper
NORTHSTAR_LIVE_TRADING_ENABLED=false
NORTHSTAR_KILL_SWITCH_ENABLED=false
NORTHSTAR_LIMIT_CHASE_FALLBACK_MODE=cancel
NORTHSTAR_PAPER_ACCOUNT=paper-account
NORTHSTAR_EXECUTION_LEASE_TTL_SECONDS=120
```

`paper` 与未来的真实期货账户必须使用不同账户命名空间，避免模拟归因被误当成真实
账户健康状态。

## 国内期货执行边界

当前只支持连续合约的离线研究。`configs/instruments/ctp.yaml` 提供连续合约到实际
CTP 合约的显式映射，但 CTP 报单状态机尚未实现；在此之前，所有期货画像都会在订单
计划阶段明确拒绝执行。

仓库默认 CTP 映射为空，不包含任何未经账户持有人核验的实际 `instrument_id`。因此，
即使误开真实交易开关，下单也会以 `INSTRUMENT_NOT_CONFIGURED` 阻断。生产环境
可通过下面的环境变量指向单独维护并审计的配置：

```text
NORTHSTAR_CTP_CONTRACT_MAPPING_PATH=configs/instruments/ctp.yaml
```

## 执行租约

`NORTHSTAR_EXECUTION_LEASE_TTL_SECONDS` 控制账户级执行租约有效期，默认 120
秒，允许范围为 30–3600 秒。租约范围是 `broker + account`，不是 profile；
同一账户的不同策略画像也不能并发修改券商订单。追价查询和撤单期间会续约，
租约丢失后立即停止券商写操作。

## 交易画像

`configs/profiles/` 是市场、资产、频率、策略组合、执行政策和生命周期角色的事实来源。
仓库只内置一个离线研究起点：
`offline/cn_futures_daily_trend_offline.yaml`。用户应在验证数据和策略后，基于它创建自己的
期货研究画像；仓库不提供会被误用的模拟账户或真实账户画像。

目录仍按是否连接账户分为三类：

```text
configs/profiles/
├── offline/        # 历史数据、研究、回测与本地撮合；不连接券商
├── simulated/      # 连接券商模拟账户，验证实时运行链路
└── live/           # 连接真实账户，受完整实盘安全门控保护
```

`offline/` 可使用 `lifecycle.role: research` 或 `experimental` 表示研究成熟度；
`simulated/` 必须使用 `simulated`；`live/` 必须使用 `production`。后两个目录目前只保留说明，
没有内置 YAML；目录负责表达连接边界，角色负责运行时安全门控。

文件名和 YAML 内的 `profile_id` 必须完全一致，并以所属目录的类别后缀结尾。例如：

```text
offline/cn_futures_daily_trend_offline.yaml
simulated/<你的画像>_simulated.yaml
live/<你的画像>_live.yaml
```

加载器会拒绝无类别后缀、文件名与 `profile_id` 不一致、目录与角色不匹配的画像。

加载器递归读取 YAML，但命令始终以 YAML 内的 `profile_id` 选择画像，而不是文件路径：

```bash
uv run northstar research futures-trend --profile cn_futures_daily_trend_offline
```

每个 `profile_id` 必须全局唯一，且画像必须直接放入上述三个连接边界目录之一。主要字段包括：

- `market / asset_type / data_frequency / rebalance_frequency`
- `timezone / calendar / currency`
- `lifecycle.role`
- `data`
- `strategies`
- `execution`
- `backtest`
- `risk`
- `schedule`
- `versions`

只有 `lifecycle.role: production` 的画像可以进入 live 主线。

真实券商还要求：

```yaml
data:
  live_trading_eligible: true
```

该声明只表示画像允许使用真实交易数据，不会绕过 manifest、数据来源、新鲜度和完整性检查。内置的
`offline` 画像使用 AKShare 主力连续合约数据并明确设置为 `false`。用户创建 `live` 画像后，仍必须通过上述资格
以及完整 preflight；没有 `production` 画像时，live scheduler 会明确拒绝启动，不会回退使用默认
offline 画像。

### 字段完整参考

交易画像字段的代码注释位于
[`trading_profile.py`](../src/northstar_quant/config/trading_profile.py)。下表说明 YAML
每个已建模字段的含义；不认识的顶层字段只会保存在 `metadata`，不会自动改变交易行为。

#### 顶层字段

| 字段 | 类型/示例 | 含义与约束 |
| --- | --- | --- |
| `profile_id` | `cn_futures_daily_trend_offline` | 全局唯一程序 ID。必须与文件名相同，并以目录类别后缀 `_offline`、`_simulated` 或 `_live` 结尾。 |
| `name` | `中国商品期货日线趋势研究` | 面向人的名称，不参与代码路由。 |
| `market` | `CN` | 交易市场，影响日历、执行注册表和市场规则。 |
| `asset_type` | `FUTURES` | 本项目仅支持国内期货。 |
| `data_frequency` | `1d` / `1w` / `1m` | 行情和信号计算频率。 |
| `rebalance_frequency` | `1d` / `1w` / `5m` | 调整持仓的频率；可不同于数据频率。 |
| `strategy_family` | `trend_following` | 画像默认策略分类，供注册表兼容性检查；策略条目可单独声明更具体的分类。 |
| `currency` | `CNY` | 金额、费用、订单门槛的计价货币。 |
| `timezone` | `Asia/Shanghai` | IANA 时区，定义调度与报告日期边界。 |
| `calendar` | 研究日历 ID | 连续合约研究使用的日期对齐日历；真实期货执行必须改用交易所交易时段配置。 |
| `universe_id` | `cn_commodity_continuous_core` | 连续合约研究标的池的稳定名称；实际下载 symbol 在 `data.download.symbols`。 |
| `benchmark_symbol` | `RB_CONT` | 研究报告使用的连续合约参考标的，不是实际下单合约。 |
| `futures` | 对象 | 期货合约规格路径、连续合约和执行边界，见下文。 |
| `lifecycle` | 对象 | 连接边界下的运行角色，见下文。 |
| `data` | 对象 | 数据来源、价格口径、下载规则及真实交易资格，见下文。 |
| `strategies` | 列表 | 策略组合，见下文。至少需要一个 `enabled: true` 策略才能运行策略管线。 |
| `execution` | 对象 | 再平衡和数量单位约束，见下文。 |
| `backtest` | 对象 | 回测引擎及撮合假设，见下文。 |
| `versions` | 对象 | 版本锚点，只做追溯记录，不自动加载版本。 |
| `risk` | 对象 | 对 `RiskLimits` 的画像级覆盖，未知键会报错。 |
| `schedule` | 对象 | 此画像的 cron 调度覆盖。 |
| 其他顶层键 | 任意 | 读取后保存为 `metadata`，当前不驱动策略、风控或执行。 |

#### `lifecycle`：连接边界和运行角色

| 字段 | 示例 | 含义 |
| --- | --- | --- |
| `role` | `research` | `offline/` 仅允许 `research` 或 `experimental`；`simulated/` 必须为 `simulated`；`live/` 必须为 `production`。只有 `production` 可进入 live 服务。 |
| `line_id` | `cn_futures_daily_trend_research` | 稳定的策略线/账户线标识，用于运营追踪，不应用作期货资金账号。 |

`offline` 不连接券商，适合历史研究、回测和本地撮合；`simulated` 才是连接券商模拟账户；
`live` 表示真实账户路径，但仍必须通过数据、合约、风控和环境开关检查。

#### `data` 与 `data.download`：数据来源和口径

| 字段 | 示例 | 含义与注意事项 |
| --- | --- | --- |
| `data.provider` | `akshare` | 标准数据集的来源标识。当前为 AKShare 的新浪主力连续合约日线；它不保证数据新鲜或可用于真实交易。 |
| `data.dataset_id` | `continuous_research` | 数据集逻辑名称，用于 manifest 与画像一致性校验。 |
| `data.path` | `cn/futures/1d/continuous.parquet` | 相对 `storage/market/` 的标准化 parquet 路径。不要写绝对路径。 |
| `data.price_field` | `close` | 连续合约研究取用的价格列；不是实际交割合约下单价格。 |
| `data.adjusted` | `true` | 数据集是否按复权语义处理；不能替代 `price_field` 的明确选择。 |
| `data.live_trading_eligible` | `false` | 真实交易的数据资格声明。默认必须为 `false`；即使为 `true` 也仍需通过 manifest、新鲜度和完整性检查。 |
| `data.download.enabled` | `true` | 是否允许 `northstar data download` 为该画像获取数据。 |
| `data.download.provider` | `akshare` | 自动下载提供器；为空时回退到 `data.provider`。 |
| `data.download.symbols` | `[RB_CONT, I_CONT]` | 连续合约或实际合约 symbol 列表，必须与合约规格和数据口径相匹配。 |
| `data.download.start_date` | `2015-01-05` | 下载起始日，`YYYY-MM-DD`。 |
| `data.download.end_date` | `2026-01-01` | 可选下载截止日；为空通常下载到提供器可得的最新日期。 |
| `data.download.options` | `{vendor_symbols: {RB_CONT: RB0}}` | 提供器专用参数。AKShare 必须用 `vendor_symbols` 显式映射内部连续 symbol 到上游代码；可选 `request_interval_seconds` 用于控制请求间隔。 |

#### `futures`：合约与执行边界

| 字段 | 示例 | 含义与约束 |
| --- | --- | --- |
| `contract_spec_path` | `configs/futures/cn_commodity_research.yaml` | 合约规格主数据路径。必须包含 symbol、交易所、乘数、最小变动价位及可交易标志。 |
| `symbols_are_continuous` | `true` | 行情是否为连续合约。为 `true` 时，只允许研究，绝不能形成实际订单。 |
| `execution_allowed` | `false` | 仅在每个 symbol 均映射到实际可交易合约、已核验保证金/手续费/开平仓规则并具备国内期货柜台适配器后才可设为 `true`。 |

#### `strategies`：策略组合

`strategies` 是对象列表，每个对象含以下字段：

| 字段 | 示例 | 含义 |
| --- | --- | --- |
| `strategy_id` | `futures_trend` | 策略注册表 ID；必须存在且与期货市场、频率兼容。 |
| `strategy_family` | `trend_following` | 可选策略分类；填写后必须与注册表定义一致。 |
| `enabled` | `true` | 是否进入 canonical strategy pipeline。关闭的条目保留配置但不运行。 |
| `capital_weight` | `0.7` | 多策略组合的初始资金权重。目标权重策略会组合并施加组合风控；选择策略子集时会重新归一。 |
| `params` | `{lookback_days: 126}` | 对策略构造器默认参数的覆盖。未知参数会拒绝，避免拼写错误静默生效。 |

#### `execution`：再平衡与手数约束

| 字段 | 示例 | 含义 |
| --- | --- | --- |
| `long_only` | `true` | 目标组合是否只允许多头；不会自动授予券商做空权限。 |
| `rebalance_min_trade_value` | `10000` | 低于该金额的再平衡差额不生成计划交易。 |
| `rebalance_weight_tolerance` | `0.015` | 当前权重和目标权重差异不超过该值时不交易。 |
| `order_qty_step` | `100` | 全方向通用数量步长。 |
| `buy_qty_step` | `1` | 开仓方向数量步长；期货通常为整手。优先于通用步长。 |
| `sell_qty_step` | `1` | 平仓或开空方向数量步长；需显式体现柜台开平仓规则。优先于通用步长。 |

#### `backtest`：回测撮合假设

| 字段 | 示例 | 含义 |
| --- | --- | --- |
| `engine` | `weight_return` | 连续合约信号/收益研究引擎；不模拟保证金、换月或实际成交。 |
| `initial_cash` | `100000` | 回测初始现金，不是实际账户余额。 |
| `commission_bps` | `5.0` | 单边佣金基点；`5` 表示 0.05%。 |
| `min_commission` | `5.0` | 单笔最低佣金，使用画像 `currency`。 |
| `slippage_bps` | `5.0` | 模拟成交相对参考价格的滑点基点。 |
| `lot_size` | `1` | 研究参数；实际期货合约手数、乘数和保证金须由专用期货回测器处理。 |
| `execution_delay_sessions` | `1` | 信号产生到成交之间的交易时段数。日线收盘信号至少为 1，避免未来函数。 |
| `sellable_after_sessions` | `0` | 期货 T+0 研究画像应为 0。 |

#### `versions`：可追溯性锚点

| 字段 | 含义 |
| --- | --- |
| `profile` | 整体画像版本。 |
| `benchmark` | 基准定义和总回报口径版本。 |
| `strategy_params` | 策略参数集合版本。 |
| `execution_policy` | 成交时点、费用、滑点、手数等执行假设版本。 |
| `risk_policy` | 风控阈值及规则版本。 |

这些值应在任何影响结果的配置变化时递增或更换；目前它们是审计标签，不是自动版本控制系统。

#### `risk`：画像级风控覆盖

`risk` 的键直接对应 `RiskLimits`，支持：

| 字段 | 含义 |
| --- | --- |
| `max_single_weight` | 单一标的最大绝对权重。 |
| `max_gross_exposure` | 组合绝对权重总和上限。 |
| `min_cash_buffer` | 必须保留的最小现金比例。 |
| `min_order_notional` / `max_order_notional` | 单笔订单金额下限/上限。 |
| `max_order_qty` | 单笔最大数量。 |
| `order_qty_step` / `buy_qty_step` / `sell_qty_step` | 订单数量步长；与 `execution` 同名项会由画像管线合并。 |
| `enforce_available_cash` | 买入前是否必须取得并检查可用资金。 |
| `enforce_sellable_qty` | 卖出前是否必须取得并检查可卖数量。 |
| `enforce_tradeable_state` | 是否必须检查停牌等标的可交易状态。 |
| `enforce_price_limit` | 是否必须检查涨跌停价格限制。 |

`risk` 不支持未知键；真实账户应优先启用需要实时账户或市场状态的检查，缺失所需数据时系统会 fail-closed。

#### `schedule`：画像级 cron 覆盖

当前可使用的常见键为：

| 字段 | 示例 | 含义 |
| --- | --- | --- |
| `shadow_run_cron` | `20 15 * * 1-5` | 影子运行/信号检查时间。 |
| `rebalance_cron` | `35 15 * * 1-5` | 再平衡运行时间。 |
| `daily_report_cron` | `45 15 * * 1-5` | 日报生成时间。 |
| `weekly_report_cron` | `0 16 * * 5` | 周报生成时间。 |
| `monthly_report_cron` | `0 16 28-31 * *` | 月报生成候选时间；实际日期仍应结合交易日逻辑。 |

cron 使用画像的 `timezone` 和 `calendar`。离线画像可以保留这些字段用于报告演练，但不应把它当作账户调度授权。

## 策略配置

`configs/strategy/*.yaml` 提供策略构造器默认参数和说明元数据；profile 中 `strategies[].params` 可以覆盖构造器参数。

canonical pipeline 与直接策略构建使用同一个注册表入口，并校验：

- strategy family
- market
- asset type
- data frequency
- YAML 未知字段
- profile 未知参数

未知参数会直接报错，不再静默丢弃。

## 日志配置

`configs/app.yaml` 当前只由日志初始化逻辑消费，控制日志级别、控制台、JSON Lines 文件、滚动和保留周期。它不会覆盖 Pydantic Settings。

## 当前未接入主流程的配置

以下目录目前主要是设计样例或未来扩展点，不应被视为已生效的运行时政策：

- `configs/data/*.yaml`
- `configs/risk/global.yaml`
- `configs/portfolio/*.yaml`

在为它们建立类型模型、加载入口和测试前，不要仅修改这些文件并假设交易行为已经变化。

## 数据 manifest

下载流程会记录 profile、dataset 和 data source 等来源信息。真实券商 preflight 会核对 manifest 与活动画像。

当前 manifest 尚未包含 parquet 内容哈希、完整配置哈希和代码版本，因此仍需继续演进为不可变数据版本；在此之前，`live_trading_eligible` 不能单独证明数据内容可信。

## 期货连续合约研究配置

画像的 `futures` 明确区分连续合约研究与实际执行：

```yaml
futures:
  contract_spec_path: configs/futures/cn_commodity_research.yaml
  symbols_are_continuous: true
  execution_allowed: false
```

连续合约只能用于信号和收益研究。当前 `weight_return` 回测不会模拟保证金、合约乘数、
手续费、换月、夜盘、涨跌停或开平仓；因此它不能用于判断真实可交易收益，更不能生成订单。
实际期货模拟与实盘必须使用逐日实际合约数据和专用 CTP 执行适配器。

## 调度配置

cron 表达式来自活动 profile 的 `schedule`，时区与交易日历来自同一 profile 的 `timezone` 和 `calendar`。全局 Settings 只作为缺省值。

真实券商模式下，正式交易日历不可用会阻断执行；不会退化为“周一到周五”判断。
