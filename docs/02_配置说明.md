# 配置说明

Northstar Quant 目前不是一个“所有 YAML 逐层覆盖”的统一配置系统。不同配置文件有明确且彼此独立的职责。

## 运行时 Settings

`src/northstar_quant/config/settings.py` 使用 Pydantic Settings 管理运行时参数：

1. 显式构造参数
2. `NORTHSTAR_*` 环境变量
3. 当前工作目录的 `.env`
4. 代码中的安全默认值

数据库、券商、账户、告警、SMTP、运行目录和全局调度参数属于这一层。`.env` 是本地文件，不得提交。

关键安全默认值：

```text
NORTHSTAR_BROKER=paper
NORTHSTAR_LIVE_TRADING_ENABLED=false
NORTHSTAR_KILL_SWITCH_ENABLED=false
NORTHSTAR_IBKR_READONLY=true
NORTHSTAR_LIMIT_CHASE_FALLBACK_MODE=cancel
NORTHSTAR_PAPER_ACCOUNT=paper-account
NORTHSTAR_EXECUTION_LEASE_TTL_SECONDS=120
```

`paper` 与 IBKR 使用不同账户命名空间，避免 paper 归因被误当成真实账户健康状态。

## IBKR Instrument Registry

`configs/instruments/ibkr.yaml` 是数据 symbol 到 IBKR 合约身份的事实来源。每条
记录必须完整提供：

```yaml
- data_symbol: 经过数据管线使用的 symbol
  broker_symbol: 经过 IBKR 核验的 symbol
  con_id: 经过 IBKR 核验且大于 0 的整数
  sec_type: STK
  exchange: SMART
  primary_exchange: 经过 IBKR 核验的主交易所
  currency: 交易币种
  enabled: false
```

加载器会拒绝未知字段、缺失字段、非布尔 `enabled`、无效 `con_id`，以及重复的
`data_symbol`、`con_id` 或券商合约身份。真实下单和行情只按 `data_symbol`
查找启用记录，再使用完整映射构造 Contract；IBKR qualification 返回的
`conId` 必须与配置精确一致。持仓、订单和成交则必须用返回的 `conId` 反向
解析为同一个数据 symbol。

仓库默认 registry 为空，不包含任何未经账户持有人核验的真实 `conId`。因此，
即使误开真实交易开关，下单也会以 `INSTRUMENT_NOT_CONFIGURED` 阻断。生产环境
可通过下面的环境变量指向单独维护并审计的配置：

```text
NORTHSTAR_IBKR_INSTRUMENT_REGISTRY_PATH=configs/instruments/ibkr.yaml
```

## 执行租约

`NORTHSTAR_EXECUTION_LEASE_TTL_SECONDS` 控制账户级执行租约有效期，默认 120
秒，允许范围为 30–3600 秒。租约范围是 `broker + account`，不是 profile；
同一账户的不同策略画像也不能并发修改券商订单。追价查询和撤单期间会续约，
租约丢失后立即停止券商写操作。

## 交易画像

`configs/profiles/*.yaml` 是市场、资产、频率、策略组合、执行政策和生命周期角色的事实来源，主要字段包括：

- `market / asset_type / data_frequency / rebalance_frequency`
- `timezone / calendar / currency`
- `lifecycle.role`
- `data`
- `strategies`
- `execution`
- `backtest`
- `risk`
- `schedule`
- `versions`

只有 `lifecycle.role: production` 的画像可以进入 live 主线。

真实券商还要求：

```yaml
data:
  live_trading_eligible: true
```

该声明只表示画像允许使用真实交易数据，不会绕过 manifest、数据来源、新鲜度和完整性检查。仓库默认 production 画像仍使用 `demo`，因此明确设置为 `false`。

## 策略配置

`configs/strategy/*.yaml` 提供策略构造器默认参数和说明元数据；profile 中 `strategies[].params` 可以覆盖构造器参数。

canonical pipeline 与直接策略构建使用同一个注册表入口，并校验：

- strategy family
- market
- asset type
- data frequency
- YAML 未知字段
- profile 未知参数

未知参数会直接报错，不再静默丢弃。

## 日志配置

`configs/app.yaml` 当前只由日志初始化逻辑消费，控制日志级别、控制台、JSON Lines 文件、滚动和保留周期。它不会覆盖 Pydantic Settings。

## 当前未接入主流程的配置

以下目录目前主要是设计样例或未来扩展点，不应被视为已生效的运行时政策：

- `configs/data/*.yaml`
- `configs/risk/global.yaml`
- `configs/portfolio/*.yaml`

在为它们建立类型模型、加载入口和测试前，不要仅修改这些文件并假设交易行为已经变化。

## 数据 manifest

下载流程会记录 profile、dataset 和 data source 等来源信息。真实券商 preflight 会核对 manifest 与活动画像。

当前 manifest 尚未包含 parquet 内容哈希、完整配置哈希和代码版本，因此仍需继续演进为不可变数据版本；在此之前，`live_trading_eligible` 不能单独证明数据内容可信。

## 日频状态机回测配置

画像的 `backtest` 控制研究回测使用的引擎和显式成交假设：

```yaml
backtest:
  engine: daily_stateful # 或 weight_return（原有简化权重收益回测）
  initial_cash: 100000
  commission_bps: 5.0
  min_commission: 5.0
  slippage_bps: 5.0
  lot_size: 100
  execution_delay_sessions: 1
  sellable_after_sessions: 1
```

`daily_stateful` 只适用于日频目标权重策略：收盘生成目标，至少下一交易日开盘
成交，维护现金、持仓成本、可卖数量和成交账本。费用和市场规则必须按实际市场、
券商和品种复核；配置中的示例数值不是实际费率。`cn_etf_daily_paper` 是安全的
研究与撮合模拟画像，仍使用 demo 数据且没有 live 权限。

## 调度配置

cron 表达式来自活动 profile 的 `schedule`，时区与交易日历来自同一 profile 的 `timezone` 和 `calendar`。全局 Settings 只作为缺省值。

真实券商模式下，正式交易日历不可用会阻断执行；不会退化为“周一到周五”判断。
