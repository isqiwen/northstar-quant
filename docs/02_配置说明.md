# 配置说明

Northstar Quant 目前不是一个“所有 YAML 逐层覆盖”的统一配置系统。不同配置文件有明确且彼此独立的职责。

## 运行时 Settings

`src/northstar_quant/config/settings.py` 使用 Pydantic Settings 管理**环境变量支持的**运行时参数：

1. 显式构造参数
2. `NORTHSTAR_*` 环境变量
3. 项目根目录的 `.env`
4. 代码中的安全默认值

数据库、券商、账户、告警、SMTP 和全局调度参数属于这一层。`.env` 是本地文件，不得提交。
`.env.example` 与 `.env.production.example` 会逐项列出所有仍支持的 `NORTHSTAR_*` 设置：前者还
列出开发 Docker 和测试数据库所需的变量。新增 Settings 字段时，契约测试会要求同步维护这两份清单。

应用 YAML 配置只有一组完整字段：受版本控制的 `configs/app.example.yaml` 是**展示模板**，从不在
运行时读取；未跟踪的 `configs/app.yaml` 是开发和生产唯一会加载的**活动配置**。二者必须具有完全
相同的字段和层级，契约测试会校验这一点。输出目录位于活动配置的顶层 `runtime` 段，不会被 shell、
systemd 或 `.env` 的同名变量悄悄覆盖。

| 文件 | 是否提交 | 是否被应用读取 | 职责 |
| --- | --- | --- | --- |
| `configs/app.example.yaml` | 是 | 否 | 完整、非敏感的 YAML 参数展示模板。 |
| `configs/app.yaml` | 否 | 是 | 开发和每个生产发布版本唯一的完整活动 YAML 配置。 |
| `.env` / `.env.production` | 否 | 是 | 数据库 URL、密码、令牌和环境级安全开关；完整变量清单见对应 example。 |
| `deploy.env` | 否 | 否（仅部署脚本读取） | 服务器目录、服务名和部署目标；发布时用于生成该 release 的活动 `app.yaml`。 |

数据库只支持 PostgreSQL，URL 必须使用
`postgresql+psycopg://`。开发运行库与测试库必须分开：

```text
NORTHSTAR_DATABASE_URL=postgresql+psycopg://northstar:本地密码@127.0.0.1:5432/northstar
NORTHSTAR_TEST_DATABASE_URL=postgresql+psycopg://northstar:本地密码@127.0.0.1:5432/northstar_test
```

macOS/Linux 通过 `scripts/setup_dev.sh` 启动 Docker PostgreSQL；它首次运行时会生成随机
开发密码，保存在本地 `.env`，并把同一密码写入运行库和测试库 URL。Windows 通过
`scripts/setup_dev.ps1` 启动；为避免覆写本地密钥，操作者必须先从 `.env.example` 创建
`.env` 并设置非空 `POSTGRES_PASSWORD`，脚本只在当前进程中构造连接串。两个入口都会在
`configs/app.yaml` 缺失时从 `configs/app.example.yaml` 创建它，绝不覆写已有活动配置。两种入口
都使用固定数据库用户 `northstar`，不会启用真实交易。仓库中没有默认密码，`.env` 不得提交。
数据库测试会在 `northstar_test` 中为每个测试创建独立 schema，并在测试结束后删除，避免
跨测试污染。

如果旧版 `.env` 仍含 `sqlite:///...`，直接运行 CLI 会在 Settings 校验阶段失败。不要删除
历史 SQLite 文件或猜测密码；应在设置本地 `POSTGRES_PASSWORD` 后，把两个 URL 更新为上述
PostgreSQL 形式，或重新按开发初始化步骤创建本地 `.env`。

关键安全默认值：

```text
NORTHSTAR_BROKER=paper
NORTHSTAR_LIVE_TRADING_ENABLED=false
NORTHSTAR_KILL_SWITCH_ENABLED=false
NORTHSTAR_LIMIT_CHASE_FALLBACK_MODE=cancel
NORTHSTAR_PAPER_ACCOUNT=paper-account
NORTHSTAR_EXECUTION_LEASE_TTL_SECONDS=120
```

`paper` 与未来的真实期货账户必须使用不同账户命名空间，避免模拟归因被误当成真实
账户健康状态。

### 创建本地 `.env`

首次开发可执行：

```powershell
Copy-Item .env.example .env
```

随后只填写本机密码、令牌及确有必要的运行时变量。`NORTHSTAR_TEST_DATABASE_URL` 仅供测试支持层
使用，生产 `.env.production` 不应包含它。不要在 `.env` 或操作系统环境中设置
`NORTHSTAR_STORAGE_DIR`、`NORTHSTAR_DOWNLOADS_DIR`、`NORTHSTAR_REPORTS_DIR` 或
`NORTHSTAR_LOG_DIR`：这些旧变量会使应用失败关闭，并给出迁移提示。

## 运行时输出目录

运行时文件只配置根目录或明确的例外路径，不应为每次研究随意改变主输出位置。所有相对路径
均相对项目根目录；本地 `storage/`、`reports/` 和 `logs/` 均不纳入 Git。默认配置为：

```yaml
runtime:
  storage_dir: storage
  downloads_dir: null # 自动派生为 storage_dir/downloads
  reports_dir: reports
  log_dir: logs
```

首次开发由初始化入口复制示例；若手动初始化，执行
`Copy-Item configs/app.example.yaml configs/app.yaml`（Git Bash 使用 `cp`）。随后只编辑完整的
`configs/app.yaml`，不得创建局部覆盖文件。Linux 部署同样使用完整活动配置：部署脚本会根据
`deploy.env` 已校验的 `RUNTIME_*_DIR` 在每个待发布版本中生成 `configs/app.yaml`，详见
[Linux 一键部署](07_Linux一键部署.md)。

旧版的 `configs/app.local.yaml` 不再被支持；发现该文件时应用会失败关闭。迁移时先把需要保留的
值完整填入 `configs/app.yaml`，再删除旧文件，避免误以为局部覆盖仍会生效。

| 配置 | 默认位置/行为 | 适用场景 |
| --- | --- | --- |
| `runtime.storage_dir` | `storage/` | 标准化数据、Paper/CTP 仿真状态等长期运行状态的根目录。 |
| `runtime.downloads_dir` | `null` 时自动派生为 `<storage>/downloads/` | 下载缓存需要独立磁盘时，在完整 `runtime` 段中填写路径。 |
| `runtime.reports_dir` | `reports/` | 回测、日报、周报等正式制品的根目录。 |
| `runtime.log_dir` | `logs/` | JSON Lines 审计日志根目录；文件名、轮转周期和保留份数仍由 `logging` 段控制。 |
| `NORTHSTAR_PAPER_STATE_PATH` | 未设置时为 `<storage>/brokers/paper/<paper-account>/state.json` | 只有在 `<storage>` 内需要固定状态文件位置时才设置。状态文件内会记录账户，账户不匹配时拒绝加载。 |
| `NORTHSTAR_CTP_SIM_STATE_PATH` | 未设置时为 `<storage>/brokers/ctp_sim/<ctp-sim-account>/state.json` | 本地 `ctp_sim` 语义演练状态；按账户隔离，且与 Paper 状态分离。显式路径也必须位于 `<storage>` 内。 |

主要输出制品如下。除 PostgreSQL 外，它们均位于上述可配置根目录内；不要将这些目录加入 Git，
也不要通过清理下载缓存来删除研究证据。

| 制品 | 默认位置 | 说明 |
| --- | --- | --- |
| 下载缓存 | `<downloads>/<adapter>/<market>/<asset>/<frequency>/<dataset>.parquet` 及配对 `.manifest.json` | 可重新下载的缓存；唯一允许 `data cleanup` 处理的正式文件类别。 |
| 标准市场数据 | `<storage>/market/<market>/<asset>/<frequency>/<dataset>.parquet`、`.manifest.json` 与可能存在的 `.publishing.json` | 经校验的回测输入；必须保留并由 manifest 保护。 |
| Paper / `ctp_sim` 状态 | `<storage>/brokers/<broker>/<account>/state.json` 及运行期锁文件 | 本地账户状态，不可跨账户复用。 |
| 报告制品 | `<reports>/<类型>/<画像>/<策略>/<周期>[/<run-id>]/report.md`、`report.json`、可选 `manifest.json` / `report.pdf` | 人类可读报告、结构化数据和回测可复现证据。 |
| 应用日志 | `<log-dir>/northstar.log` 及按 `configs/app.yaml` 轮转的历史文件 | 目录由 `runtime.log_dir` 决定；名称和保留规则不随之改变。 |
| 数据库 | PostgreSQL 服务的独立数据卷 | 不属于项目工作区输出；开发库和 `northstar_test` 必须隔离。 |

`NORTHSTAR_PAPER_ACCOUNT` 是本地 Paper 状态命名空间的一部分，只允许 1–64 位的字母、数字、
下划线和连字符，且必须以字母或数字开头。这样可避免账户名成为路径片段时发生路径穿越。
切换账户会自动切换到独立状态文件；即使显式设置了 `NORTHSTAR_PAPER_STATE_PATH`，加载时也会
校验文件所属账户，不能跨账户复用。

两个显式状态路径均受 `runtime.storage_dir` 约束。这使部署脚本和 systemd 只需对白名单中的
运行时存储目录授予写权限；如需把模拟状态迁移到独立磁盘，应调整完整 `runtime` 配置，而不是
把单个状态文件指向任意系统路径。

`NORTHSTAR_CTP_SIM_ACCOUNT` 采用相同的账户标识规则和状态目录派生方式。它只对应本地
语义演练，不连接真实 CTP 前置；切换该账户同样会切换到独立的状态文件。

旧版本的 `storage/paper_broker_state.json` 不再是默认位置。不会自动迁移它，以免把没有账户
身份的旧状态静默归属给新账户；如确有保留价值，应先在隔离环境中核对其来源，再以新账户重新
建立 Paper 状态。

### 下载缓存的安全清理

`configs/maintenance/output_retention.yaml` 只定义下载缓存和原子写入残留临时文件的保留期；
它与数据供应商合同中的 `license.retention_days` 没有自动关联。默认 `enabled: false`，不会在
任何下载、回测、报告或调度命令中自动删除文件。

```powershell
# 只列出将会处理的过期下载缓存与 .tmp 文件，不删除。
uv run northstar data cleanup

# 只有先在策略 YAML 中设为 enabled: true，且显式传入 --apply，才实际删除。
uv run northstar data cleanup --apply
```

该命令只在 `runtime.downloads_dir` 内工作；它会拒绝符号链接、路径重叠和预览后发生变化
的文件。`storage/market`、所有正式报告、回测 manifest 以及 `.publishing.json` 失败关闭标记
永远不属于清理范围。删除下载缓存时，若存在与缓存同名的 sidecar manifest，会作为同一缓存对
一起删除，避免留下无对应数据的元数据。

## 国内期货执行边界

当前支持连续合约快速研究、实际合约逐日回测、实际合约分钟订单回放，以及本地
`ctp_sim` 的期货语义演练；尚未实现**真实 CTP** 的认证、报单、撤单、回报订阅和查询
状态机。
`configs/instruments/ctp.yaml` 提供连续合约到实际 CTP 合约的显式映射；在完成真实
执行适配前，所有内置期货画像都会在订单计划阶段明确拒绝执行。

仓库默认 CTP 映射为空，不包含任何未经账户持有人核验的实际 `instrument_id`。因此，
即使误开真实交易开关，下单也会以 `INSTRUMENT_NOT_CONFIGURED` 阻断。生产环境
可通过下面的环境变量指向单独维护并审计的配置：

```text
NORTHSTAR_CTP_CONTRACT_MAPPING_PATH=configs/instruments/ctp.yaml
```

## 执行租约

`NORTHSTAR_EXECUTION_LEASE_TTL_SECONDS` 控制账户级执行租约有效期，默认 120
秒，允许范围为 30–3600 秒。租约范围是 `broker + account`，不是 profile；
同一账户的不同策略画像也不能并发修改券商订单。追价查询和撤单期间会续约，
租约丢失后立即停止券商写操作。

## 交易画像

`configs/profiles/` 是市场、资产、频率、策略组合、执行政策和生命周期角色的事实来源。
仓库内置三个离线起点：
`offline/cn_futures_daily_trend_offline.yaml` 与
`offline/cn_futures_daily_actual_offline.yaml`、
`offline/cn_futures_intraday_replay_offline.yaml`。另有
`simulated/cn_futures_daily_trend_simulated.yaml`，仅用于本地 `ctp_sim` 语义演练；
仓库不提供真实账户 production 画像。

目录仍按是否连接账户分为三类：

```text
configs/profiles/
├── offline/        # 历史数据、研究、回测与本地撮合；不连接券商
├── simulated/      # 模拟运行边界；当前仅内置本地 ctp_sim 语义演练
└── live/           # 连接真实账户，受完整实盘安全门控保护
```

`offline/` 可使用 `lifecycle.role: research` 或 `experimental` 表示研究成熟度；
`simulated/` 必须使用 `simulated`；`live/` 必须使用 `production`。当前仅 `simulated/`
含本地 `ctp_sim` YAML，`live/` 只保留说明；目录负责表达连接边界，角色负责运行时安全门控。

文件名和 YAML 内的 `profile_id` 必须完全一致，并以所属目录的类别后缀结尾。例如：

```text
offline/cn_futures_daily_trend_offline.yaml
simulated/<你的画像>_simulated.yaml
live/<你的画像>_live.yaml
```

加载器会拒绝无类别后缀、文件名与 `profile_id` 不一致、目录与角色不匹配的画像。

加载器递归读取 YAML，但命令始终以 YAML 内的 `profile_id` 选择画像，而不是文件路径：

```bash
uv run northstar research futures-trend --profile cn_futures_daily_trend_offline
```

每个 `profile_id` 必须全局唯一，且画像必须直接放入上述三个连接边界目录之一。主要字段包括：

- `market / asset_type / data_frequency / rebalance_frequency`
- `timezone / calendar / currency`
- `lifecycle.role`
- `data`
- `research_admission`
- `strategies`
- `execution`
- `backtest`
- `risk`
- `schedule`
- `versions`

只有 `lifecycle.role: production` 的画像可以进入 live 主线。

真实券商还要求：

```yaml
data:
  live_trading_eligible: true
```

该声明只表示画像允许使用真实交易数据，不会绕过 manifest、数据来源、新鲜度和完整性检查。内置的
`offline` 画像使用 AKShare 主力连续合约数据并明确设置为 `false`。用户创建 `live` 画像后，仍必须通过上述资格
以及完整 preflight；没有 `production` 画像时，live scheduler 会明确拒绝启动，不会回退使用默认
offline 画像。

### 字段完整参考

交易画像字段的代码注释位于
[`trading_profile.py`](../src/northstar_quant/config/trading_profile.py)。下表说明 YAML
每个已建模字段的含义；未知顶层字段会直接拒绝。只有显式 `metadata` 对象可承载非运行时
说明信息，且不会自动改变交易行为。

#### 顶层字段

| 字段 | 类型/示例 | 含义与约束 |
| --- | --- | --- |
| `profile_id` | `cn_futures_daily_trend_offline` | 全局唯一程序 ID。必须与文件名相同，并以目录类别后缀 `_offline`、`_simulated` 或 `_live` 结尾。 |
| `name` | `中国商品期货日线趋势研究` | 面向人的名称，不参与代码路由。 |
| `market` | `CN` | 交易市场，影响日历、执行注册表和市场规则。 |
| `asset_type` | `FUTURES` | 本项目仅支持国内期货。 |
| `data_frequency` | `1d` / `1w` / `1m` | 行情和信号计算频率。 |
| `rebalance_frequency` | `1d` / `1w` / `5m` | 调整持仓的频率；可不同于数据频率。 |
| `strategy_family` | `trend_following` | 画像默认策略分类，供注册表兼容性检查；策略条目可单独声明更具体的分类。 |
| `currency` | `CNY` | 金额、费用、订单门槛的计价货币。 |
| `timezone` | `Asia/Shanghai` | IANA 时区，定义调度与报告日期边界。 |
| `calendar` | 研究日历 ID | 连续合约研究使用的日期对齐日历；真实期货执行必须改用交易所交易时段配置。 |
| `universe_id` | `cn_commodity_continuous_core` | 画像标的池的稳定 ID；`data.download.symbols` 必须与对应 universe 的成员一致，不能单独扩大品种范围。 |
| `benchmark_symbol` | `RB_CONT` | 研究报告使用的连续合约参考标的，不是实际下单合约。 |
| `futures` | 对象 | 期货合约规格路径、连续合约和执行边界，见下文。 |
| `lifecycle` | 对象 | 连接边界下的运行角色，见下文。 |
| `data` | 对象 | 数据来源、价格口径、下载规则及真实交易资格，见下文。 |
| `research_admission` | 对象 | 候选策略研究准入政策绑定；只影响研究结论，不会授权订单。 |
| `strategies` | 列表 | 策略组合，见下文。至少需要一个 `enabled: true` 策略才能运行策略管线。 |
| `execution` | 对象 | 再平衡和数量单位约束，见下文。 |
| `backtest` | 对象 | 回测引擎及撮合假设，见下文。 |
| `versions` | 对象 | 版本锚点，只做追溯记录，不自动加载版本。 |
| `risk` | 对象 | 对 `RiskLimits` 的画像级覆盖，未知键会报错。 |
| `schedule` | 对象 | 此画像的 cron 调度覆盖。 |
| `metadata` | 对象 | 显式保存非运行时说明信息；不会驱动策略、风控或执行。 |
| 其他顶层键 | 不支持 | 为避免拼写错误静默失效，加载器会直接拒绝。 |

#### `lifecycle`：连接边界和运行角色

| 字段 | 示例 | 含义 |
| --- | --- | --- |
| `role` | `research` | `offline/` 仅允许 `research` 或 `experimental`；`simulated/` 必须为 `simulated`；`live/` 必须为 `production`。只有 `production` 可进入 live 服务。 |
| `line_id` | `cn_futures_daily_trend_research` | 稳定的策略线/账户线标识，用于运营追踪，不应用作期货资金账号。 |

`offline` 不连接券商，适合历史研究、回测和本地撮合；当前 `simulated` 只用于本地
`ctp_sim` 语义演练，不连接期货公司；`live` 表示未来真实账户路径，仍必须通过数据、
合约、风控和环境开关检查。

#### `data` 与 `data.download`：数据来源和口径

| 字段 | 示例 | 含义与注意事项 |
| --- | --- | --- |
| `data.provider` | `akshare` | 标准数据集的技术 adapter 标识。连续研究使用 `akshare`，实际合约日线使用 `akshare_actual_daily`；adapter 可用不等于数据授权成立。 |
| `data.source_id` | `akshare_continuous_public_v1` | 版本化数据源/许可身份，必须与 adapter、市场和用途兼容；公开来源均不具备候选研究或实盘资格。 |
| `data.dataset_id` | `continuous_research` | 数据集逻辑名称，用于 manifest 与画像一致性校验。 |
| `data.path` | `cn/futures/1d/continuous.parquet` | 相对 `storage/market/` 的标准化 parquet 路径。不要写绝对路径。 |
| `data.signal_frequency` | `1d` | 策略实际读取的频率；为空时等于顶层 `data_frequency`。分钟回放画像必须显式为 `1d`。 |
| `data.price_field` | `close` | 连续合约研究取用的价格列；不是实际交割合约下单价格。 |
| `data.adjusted` | `true` | 当前仅作为数据口径追溯标签；运行时价格选择仍只由 `price_field` 决定，不能用此字段改变收益口径。 |
| `data.live_trading_eligible` | `false` | 真实交易的数据资格声明。默认必须为 `false`；即使为 `true` 也仍需通过 manifest、新鲜度和完整性检查。 |
| `data.download.enabled` | `true` | 是否允许 `northstar data download` 为该画像获取数据。 |
| `data.download.provider` | `akshare` | 自动下载提供器；为空时回退到 `data.provider`。实际日线只允许 `akshare_actual_daily`。 |
| `data.download.symbols` | `[RB_CONT, I_CONT]` | 连续画像填写连续 symbol；实际日线画像填写 `RB`、`CU` 等品种代码。 |
| `data.download.start_date` | `2015-01-05` | 下载起始日，`YYYY-MM-DD`。 |
| `data.download.end_date` | `2026-01-01` | 可选下载截止日；为空通常下载到提供器可得的最新日期。 |
| `data.download.options` | `{vendor_symbols: {RB_CONT: RB0}}` | 提供器专用参数。连续合约配置 `vendor_symbols`；实际日线配置 `product_exchanges`、`research_position_limit_lots`。可选 `request_interval_seconds` 控制请求间隔。 |

#### `research_admission`：候选策略研究门槛

| 字段 | 示例 | 含义与约束 |
| --- | --- | --- |
| `enabled` | `true` | 是否在回测完成后计算候选策略研究准入；关闭时只产出普通研究报告。 |
| `policy_id` | `cn_commodity_futures_research_conservative_v1` | `configs/research/admission/` 中的严格政策 ID；启用时必须存在且与画像市场、资产和回测引擎兼容。 |

准入结果只写入 `analytics`、报告和 manifest；`PASS` 也不会修改 `execution_allowed`、
broker 或 live 开关。数据来源、品种池和阈值的具体含义见
[研究准入政策与数据治理](09_研究准入政策与数据治理.md)。

#### `futures`：合约与执行边界

| 字段 | 示例 | 含义与约束 |
| --- | --- | --- |
| `contract_spec_path` | `configs/futures/cn_commodity_research.yaml` | 合约规格主数据路径。必须包含 symbol、交易所、乘数、最小变动价位及可交易标志。 |
| `symbols_are_continuous` | `true` | 行情是否为连续合约。为 `true` 时，只允许研究，绝不能形成实际订单。 |
| `execution_allowed` | `false` | 仅在每个 symbol 均映射到实际可交易合约、已核验保证金/手续费/开平仓规则并具备国内期货柜台适配器后才可设为 `true`。 |

#### `strategies`：策略组合

`strategies` 是对象列表，每个对象含以下字段：

| 字段 | 示例 | 含义 |
| --- | --- | --- |
| `strategy_id` | `futures_trend` | 策略注册表 ID；必须存在且与期货市场、频率兼容。 |
| `strategy_family` | `trend_following` | 可选策略分类；填写后必须与注册表定义一致。 |
| `enabled` | `true` | 是否进入 canonical strategy pipeline。关闭的条目保留配置但不运行。 |
| `capital_weight` | `0.7` | 多策略组合的初始资金权重。目标权重策略会组合并施加组合风控；选择策略子集时会重新归一。 |
| `params` | `{lookback_days: 126}` | 对策略构造器默认参数的覆盖。未知参数会拒绝，避免拼写错误静默生效。 |

#### `execution`：再平衡与手数约束

| 字段 | 示例 | 含义 |
| --- | --- | --- |
| `long_only` | `true` | 目标组合是否只允许多头；不会自动授予券商做空权限。 |
| `rebalance_min_trade_value` | `10000` | 低于该金额的再平衡差额不生成计划交易。 |
| `rebalance_weight_tolerance` | `0.015` | 当前权重和目标权重差异不超过该值时不交易。 |
| `order_qty_step` | `100` | 全方向通用数量步长。 |
| `buy_qty_step` | `1` | 开仓方向数量步长；期货通常为整手。优先于通用步长。 |
| `sell_qty_step` | `1` | 平仓或开空方向数量步长；需显式体现柜台开平仓规则。优先于通用步长。 |

#### `backtest`：回测撮合假设

| 字段 | 示例 | 含义 |
| --- | --- | --- |
| `engine` | `weight_return` | 连续合约信号/收益研究引擎；不模拟保证金、换月或实际成交。 |
| `initial_cash` | `100000` | 回测初始现金，不是实际账户余额。 |
| `commission_bps` | `5.0` | 单边佣金基点；`5` 表示 0.05%。 |
| `min_commission` | `5.0` | 单笔最低佣金，使用画像 `currency`。 |
| `slippage_bps` | `5.0` | 模拟成交相对参考价格的滑点基点。 |
| `lot_size` | `1` | 研究参数；实际期货合约手数、乘数和保证金须由专用期货回测器处理。 |
| `execution_delay_sessions` | `1` | 信号产生到成交之间的交易时段数。日线收盘信号至少为 1，避免未来函数。 |
| `sellable_after_sessions` | `0` | 期货 T+0 研究画像应为 0。 |
| `slippage_ticks` | `1.0` | 实际合约成交按不利方向移动的 tick 数。 |
| `max_volume_participation` | `0.05` | 日线或分钟 bar 最多使用成交量的比例。 |
| `order_ttl_bars` | `5` | 分钟回放委托经过多少根该合约 bar 后自动过期。 |
| `queue_ahead_ratio` | `0.25` | 被动限价单触价时假设排在前方的分钟成交量比例。 |

#### `versions`：可追溯性锚点

| 字段 | 含义 |
| --- | --- |
| `profile` | 整体画像版本。 |
| `benchmark` | 基准定义和总回报口径版本。 |
| `strategy_params` | 策略参数集合版本。 |
| `execution_policy` | 成交时点、费用、滑点、手数等执行假设版本。 |
| `risk_policy` | 风控阈值及规则版本。 |

这些值应在任何影响结果的配置变化时递增或更换；目前它们是审计标签，不是自动版本控制系统。

#### `risk`：画像级风控覆盖

`risk` 的键直接对应 `RiskLimits`，支持：

| 字段 | 含义 |
| --- | --- |
| `max_single_weight` | 单一标的最大绝对权重。 |
| `max_gross_exposure` | 组合绝对权重总和上限。 |
| `min_cash_buffer` | 必须保留的最小现金比例。 |
| `min_order_notional` / `max_order_notional` | 单笔订单金额下限/上限。 |
| `max_order_qty` | 单笔最大数量。 |
| `order_qty_step` / `buy_qty_step` / `sell_qty_step` | 订单数量步长；与 `execution` 同名项会由画像管线合并。 |
| `enforce_available_cash` | 买入前是否必须取得并检查可用资金。 |
| `enforce_sellable_qty` | 卖出前是否必须取得并检查可卖数量。 |
| `enforce_tradeable_state` | 是否必须检查停牌等标的可交易状态。 |
| `enforce_price_limit` | 是否必须检查涨跌停价格限制。 |

`risk` 不支持未知键；真实账户应优先启用需要实时账户或市场状态的检查，缺失所需数据时系统会 fail-closed。

#### `schedule`：画像级 cron 覆盖

当前可使用的常见键为：

| 字段 | 示例 | 含义 |
| --- | --- | --- |
| `daily_signal_cron` | `20 15 * * 1-5` | 完整日线到齐后生成并冻结目标。 |
| `execution_cron` | `5 9,21 * * 1-5` | 在日盘或夜盘开盘后读取冻结目标并执行；重复运行保持幂等。 |
| `runtime_risk_cron` | `*/1 * * * 1-5` | 独立刷新账户、保证金、持仓、挂单和行情风险结论。 |
| `shadow_run_cron` | `20 15 * * 1-5` | 影子计划与运行健康检查时间。 |
| `daily_report_cron` | `45 16 * * 1-5` | 日报生成时间。 |
| `weekly_report_cron` | `0 17 * * 5` | 周报生成时间。 |
| `monthly_report_cron` | `0 17 24-31 * *` | 月报生成候选时间；仅在当月最后交易日生成。 |
| `yearly_report_cron` | `15 17 * 12 *` | 年报生成候选时间；仅在当年最后交易日生成。 |

cron 使用画像的 `timezone` 和 `calendar`。离线画像可以保留这些字段用于报告演练，但不应把它当作账户调度授权。

运行时实时风控阈值由 `NORTHSTAR_RUNTIME_RISK_*` 环境变量控制。默认要求券商状态
不超过 30 秒、行情不超过 15 秒、保证金占用不超过 75%、可用资金比例不低于 15%，
且最新结论在 90 秒内。生产环境应根据券商字段口径和账户风险预算核验这些值，不能只
因为默认值存在就直接启用真实交易。

## 策略配置

`configs/strategy/*.yaml` 提供策略构造器默认参数和说明元数据；profile 中 `strategies[].params` 可以覆盖构造器参数。

canonical pipeline 与直接策略构建使用同一个注册表入口，并校验：

- strategy family
- market
- asset type
- data frequency
- YAML 未知字段
- profile 未知参数

未知参数会直接报错，不再静默丢弃。

## 日志配置

完整的 `configs/app.yaml` 是唯一活动应用配置：`runtime` 段控制四个输出根目录，`logging` 段控制
日志级别、控制台、JSON Lines 文件名、滚动和保留周期，不能再设置目录。
`configs/app.example.yaml` 具有相同 schema，但仅用于创建和审阅活动配置，运行时绝不回退读取它。
YAML 不会覆盖环境变量支持的 Pydantic Settings；反过来，环境变量也不能覆盖 `runtime` 输出路径。

## 配置事实来源与未接入配置

以下配置已经由严格 loader 接入运行时，不能把它们视为说明性样例：

- `configs/data/sources.yaml`：数据源、技术 adapter、许可状态和用途边界；
- `configs/instruments/universes/*.yaml`：画像允许使用的品种池；
- `configs/research/admission/*.yaml`：候选策略的数据、样本、风险、压力和稳健性门槛；
- 画像中的 `data.source_id`、`universe_id` 与 `research_admission.policy_id`：将上述配置
  绑定到具体研究工作流。

数据制品和回测 manifest 会冻结这些配置的 SHA-256；变更后必须重新下载、导入或运行，
不会静默复用旧制品。供应商、授权与准入语义由
[研究准入政策与数据治理](09_研究准入政策与数据治理.md) 唯一维护。

此前未被运行时加载的 `configs/risk/global.yaml` 和
`configs/portfolio/multi_strategy.yaml` 已被移除，避免出现“修改了 YAML 但行为没有变化”的假象。
当前有效的策略、组合和风控参数必须写入交易画像中的 `strategies`、`risk`、`execution`
和 `backtest` 段。未来如需独立配置文件，必须同时提供类型模型、唯一加载入口和覆盖它的测试。

## 数据 manifest

下载流程会记录 profile、dataset 和 data source 等来源信息。真实券商 preflight 会核对 manifest 与活动画像。

当前 `data_manifest_v3` 记录 parquet SHA-256、完整 profile 指纹、schema 版本、数据源
许可状态、品种池和研究准入政策的 ID/SHA-256。数据发布使用发布中标记，策略每次加载
都会重新校验内容哈希、行数、画像身份、治理配置和 schema；任一错配都会失败关闭。回测
运行还会在报告同目录的 `manifest.json` 记录数据、有效画像、策略目标、代码提交/工作树
差异哈希和结果校验和；正式研究比较应引用该运行清单的 `run_id`。

## 期货研究与实际合约回测配置

画像的 `futures` 明确区分连续合约研究与实际执行：

```yaml
futures:
  contract_spec_path: configs/futures/cn_commodity_research.yaml
  symbols_are_continuous: true
  execution_allowed: false
```

连续合约只能用于信号和收益研究。当前 `weight_return` 回测会应用画像中的佣金、最低
佣金、滑点和信号延迟，但不会模拟保证金、合约乘数、换月、夜盘、涨跌停或开平仓；
因此它仍不能用于判断真实可交易收益，更不能生成订单。`lot_size != 1` 或
`sellable_after_sessions != 0` 会被显式拒绝，避免配置静默失效。

`cn_futures_daily_actual_offline` 使用 `backtest.engine: futures_daily`，并要求
`futures.symbols_are_continuous: false`。其 `akshare_actual_daily` 提供器下载实际
合约日线，并把前一交易日金十主力参考规则延迟到下一交易日生效；缺失规则时拒绝发布。
`research_position_limit_lots` 是画像中的研究上限，不冒充交易所限仓。策略侧生成无
换月跳跃的连续信号指数，成交侧只使用实际合约。完整字段和数据边界见
[`04_期货回测器说明.md`](04_期货回测器说明.md)。

`cn_futures_intraday_replay_offline` 使用
`backtest.engine: futures_intraday_replay`。其原始 `data_frequency` 为 `1m`，
但 `data.signal_frequency: 1d`。该画像仅用于可选的执行专项验证：策略读取聚合后的
无跳跃日线，撮合读取原始分钟 OHLC、买一卖一、盘口量和动态规则。状态机支持
市价/限价、下一 bar 生效、部分成交、
排队量、依赖委托、撤单、超时、换月、平今/平昨费、逐日结算、保证金和强平阻断。

实际合约离线画像仍设置 `execution_allowed: false`。真实模拟账户与实盘还必须实现专用
CTP 执行适配器、期货账户记账、tick/L2 队列验证以及完整对账。

## 调度配置

cron 表达式来自活动 profile 的 `schedule`，时区与交易日历来自同一 profile 的 `timezone` 和 `calendar`。全局 Settings 只作为缺省值。

真实券商模式下，正式交易日历不可用会阻断执行；不会退化为“周一到周五”判断。
