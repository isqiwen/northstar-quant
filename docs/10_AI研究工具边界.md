# AI 研究工具边界

`northstar_quant.application.agent_tools` 是 P7 的唯一 AI 研究与情报工具组合边界。
它不是 HTTP 服务、CLI、Agent runtime 或通用插件执行器；上层 Agent 必须通过其
`TypedResearchToolApi` 及其显式注入的受控 ports 工作。

## 允许的工具

工具名是封闭枚举，且只允许以下九项：

```text
search_datasets
search_events
get_feature
create_experiment
run_backtest
run_validation
compare_experiments
generate_research_card
inspect_dataset_quality
```

不存在字符串别名、动态分发或“通用执行”入口。每个工具都有冻结的 request / response
dataclass；调用方不能传入 callable、DataFrame、SQL、文件路径、策略源代码、裸收益序列、
环境变量或凭据。

## 依赖与时间语义

构造 `TypedResearchToolApi` 时，应用组合层必须显式提供：

- 已发布且只读的 Dataset Catalog；
- 已绑定 evidence、`available_at` 与受控情报投影的只读 Event Catalog；
- 精确 Feature version 的只读 Feature Catalog；
- 仅能处理受控研究证据链的 Research Workflow port。
- 只读、已审计的 Data Quality Catalog；它只能返回已冻结的质量与 lineage 检查投影。

Tool API 不读取 Settings、环境变量、数据库、文件系统或网络，也不导入 portfolio、risk、
broker、execution 或 live service。没有 injected port 时即失败，绝不回退到全局单例、隐式
数据库或“latest”版本。

所有 `as_of` 必须是带时区的时间；Dataset、Event、Feature 以及工作流结果的
`available_at` 晚于请求 `as_of` 时一律拒绝。搜索响应只包含身份、SHA-256、血缘和授权/
evidence 摘要，不返回原始 payload、Document 内容、URL、路径或秘密。

`inspect_dataset_quality` 只接受已搜索并精确绑定的 immutable DatasetSummary，返回六类完整、
hash-only 的诊断：`gap`、`revision`、`anomaly`、`stale_source`、`contract_mismatch` 与
`broken_lineage`。每类只能是 `DETECTED`、`NOT_DETECTED` 或 `UNKNOWN`，并须携带冻结的
assessment、lineage-verification 与 evidence 哈希及 PIT `available_at`。缺少 anomaly、lineage
或其它证据时必须是 `UNKNOWN`，绝不能被推断为正常；它不返回原始数据、质量明细、路径、URL、
自由文本诊断或修复建议。

## 研究状态边界

- `create_experiment` 只建立 `STATIC_REPRODUCIBILITY_ONLY` 研究规格，明确
  `eligible_for_backtest=False`、`eligible_for_trading=False`；它不授予运行或准入权限。
- `run_backtest` 只能引用预先登记的受控 research backtest request，不接受 Agent 提供的
  数据、代码或配置对象。
- `run_validation` 只能引用受控 backtest run，不接受裸收益输入。
- `compare_experiments` 必须由 workflow 先证实可比性；不可比即失败，不产生排名、升档或
  交易建议。
- `generate_research_card` 只能绑定既有 `RESEARCH_ONLY` decision，不能创建人工批准、
  candidate、paper、sim 或 production 状态。

全部 API 响应都显式保持 `eligible_for_trading=False`。该边界不会创建
`ApprovedPortfolioTarget`、`ExecutionPlan`、BrokerOrder 或任何实盘/模拟盘能力。

## Research Agent（P7-WP02）

`northstar_quant.application.research_agent.ResearchAgent` 是一个确定性的、无特权的研究编排器。
构造时只接收一个 `TypedResearchToolApi`；它不持有 LLM/provider、数据库、配置、文件系统、网络、
领域 registry 或其注入 ports。当前没有自动外部模型调用：上游模型或用户产生的假设/提案必须先被
构造成受限的 typed request，且永远不会被当成代码或命令执行。

一次完整 run 固定唯一的带时区 `as_of`，只能按下列顺序调用闭合工具面：

```text
search_events
→ search_datasets
→ get_feature（每项已注册、精确且当前仅允许 static PIT 的 FeatureReference）
→ create_experiment（STATIC_REPRODUCIBILITY_ONLY）
→ run_backtest（预登记 research request）
→ run_validation（已观察的 backtest run）
→ generate_research_card（既有 RESEARCH_ONLY decision）
```

Hypothesis 必须绑定已搜索到的 event ID、event hash 和 evidence hash；FeatureSpec proposal 只是“使用某个已注册
Feature version”的不可执行提议，不能注册 Feature、生成策略或物化数据。Dataset、Feature、
Experiment、Backtest、Validation 与 Card 的身份在每个下一步骤前重新比对；任一数据未来可见、
evidence/ID 不匹配、响应类型不正确、工具失败或副作用未知时立即停止，不重试、不跳步。

输出为 `RESEARCH_ONLY`，包含只含 tool 名、request/response hash 和 predecessor hash 的有序 trace。
trace 不保留原始查询、Document、路径、凭据或 chain-of-thought。单个 Agent 实例会在第一项工具调用
前消耗 run identity；同一实例中的同一 run 或 request hash 不得自动 replay。跨进程的同一
`run_id` reservation refusal 由受控 workflow adapter 在独立的 P10-WP06 审计组合层完成；它不是
`ResearchAgent` 或 `TypedResearchToolApi` 的依赖。

## Durable Research Agent Evidence Audit（P10-WP06）

`ResearchAgent` 仍只接收一个 `TypedResearchToolApi`，不获得 session、repository 或任何数据库能力。
跨进程审计由独立的 application composition wrapper 在 Agent 外部执行；它不能扩展工具 allowlist、
不能新增 CLI、scheduler、broker、risk 或交易入口，也不能把审计记录作为新的 Agent capability。

审计仅使用 PostgreSQL，并以 append-only、hash-only 事实保存一次 run 的最小 provenance。wrapper 必须先
提交 pre-run reservation，随后才调用 Agent；成功时追加终态和有序 trace。只有在 Agent 正常返回后、
结果绑定可确定地验证失败时才追加受限的失败状态；任何 tool/Agent 异常均保留 unresolved reservation，
因为不能安全证明其未产生副作用。
持久化内容限于受控 identity、SHA-256 commitments、带时区时间、`as_of`、固定 lifecycle/non-tradable
标记、受限状态/原因代码、trace 顺序和前驱哈希。它不保存 raw prompt、query、Document、raw result text
（结果正文）、rationale、exception message、payload 或 CoT/chain-of-thought。

前向 PostgreSQL migrations `0009_agent_run_audit` 与 `0010_agent_run_audit_hardening` 同时约束 hash
形状、trace tool allowlist、已证明 failure-code allowlist 和 `RESEARCH_ONLY` 语义，并拒绝对审计表的
`UPDATE`、`DELETE` 或 `TRUNCATE`；约束不授予任何数据库、交易或运维能力。

同一 `run_id` 的已预约、已完成、失败或未知记录都会在调用 Agent 前拒绝自动 replay；进程在 reservation
之后崩溃而未写终态时，该 run 保持 unresolved，跨进程重试同一 identity 仍失败关闭。审计结果始终为
`RESEARCH_ONLY`、`eligible_for_trading=False`，不创建 candidate、target、approval、plan、order 或任何
账户/市场操作。这是受限研究证据的 PostgreSQL 审计边界，不构成真实 CTP、实盘、生产身份或生产部署验证。

## Intelligence Agent（P7-WP03）

`northstar_quant.application.intelligence_agent.IntelligenceAgent` 也只接收一个
`TypedResearchToolApi`，并且只通过 `invoke(ToolName.SEARCH_EVENTS, ...)` 消费 P7-WP03 完成时
已有的八项闭合 allowlist。它没有第二个 intelligence facade，也不导入 SourceAdapter、Document、Event、Ontology、
Analogue Engine、Impact Graph、数据库、配置、文件系统、网络或模型 provider。

这里的 “source research” 是对 Event Catalog 已发布投影中 **授权证据引用** 的检索，不是网页抓取：
每条引用只携带 source/document 的 opaque ID、document content SHA-256、evidence SHA-256、非空
span、published/available 时间；没有正文、引文、canonical URL、路径或供应商 payload。一个 run 固定
唯一带时区 `as_of` 和精确 event ID/event hash/evidence hashes。Agent 只接受完全匹配的 event projection；
证据、身份、版本或时间被修订、缺失、歧义或未来可见时立即失败关闭。

同一 projection 中允许的只读结论严格为：

```text
authorized source/document/span citation
→ structured Event summary
→ cited historical analogue
→ cited Event → mechanism → commodity economic impact
```

历史 analogue 必须是不同 Event、event time 严格早于 reference Event、含独立的授权历史证据、在
`as_of` 前可见，并带有受控 matching method SHA-256 与 [0, 1] 的结构化（以及可选受限 embedding）
相似度。impact 只能陈述已绑定 evidence 的 mechanism、commodity 与经济 direction；不会暴露价格、
contract/instrument 选择、target、signal、approval、Feature、order 或 execution 语义，且任何
BUY/SELL/LONG/SHORT 等动作词均被拒绝。

每种 finding 都保留其 evidence hashes，结果固定为 `RESEARCH_ONLY` 与
`eligible_for_trading=False`。run 只执行一次 `search_events`；不自动重试、不以第二次查询填补缺口。
该路径没有写入能力，因此调用者可以显式提交同一个不可变请求进行新的只读读取，但这不构成隐藏的
Agent replay 或状态恢复。trace 只记录 tool/request/response/predecessor hash，不记录 query、正文、
路径、秘密或 chain-of-thought。

## Data Quality Agent（P7-WP04）

`northstar_quant.application.data_quality_agent.DataQualityAgent` 只接收一个
`TypedResearchToolApi`，固定执行 `search_datasets → inspect_dataset_quality` 两次 typed
`invoke`。请求必须精确绑定 dataset ID、dataset version、schema、lineage 和 assessment hash，并使用
同一个带时区 `as_of`；候选歧义、版本/血缘/assessment 不匹配、未来可见、缺类、重复类、无证据或
未知 response 均立即失败关闭。

它输出的是不可变、哈希化的 `DIAGNOSTIC_ONLY` 质量发现与两段 secret-free trace，始终
`eligible_for_trading=False`。`UNKNOWN` 保持为需要人工审查的未知状态，不能转换为通过或省略。
Agent 不导入 Data Platform、ArtifactStore、数据库、配置、文件系统、网络或数据帧，也没有采集、
重算、删除、修复、重发、发布、批准、target、order 或 execution 能力。任何受控修复必须在独立的
人工批准数据工作流中发生，不能从 Agent 输出触发。

## 当前实现与后续工作

P7-WP01 提供严格的 typed facade 和可替换 ports，不把目前进程内的 Feature/Experiment
Registry 伪装成持久化研究账本。P10-WP06 的 Research Agent evidence audit 在独立 application
composition wrapper 中以 PostgreSQL migration 和 focused integration/contract/architecture tests 实现；
最终质量门禁以 Master Plan 的记录为准。不得用 SQLite、临时文件或 Agent 内部状态替代 durable reservation、
终态或 trace 事实。

P7-WP02、P7-WP03 与 P7-WP04 的 Agent 实现只能消费此 research-only allowlist，不能绕过它直接接触
交易、风险、配置、数据库或 deployment 权限。后续**研究类** Agent 如需新能力，必须先以独立 Work
Package 扩展本闭合边界，同时更新全部调用方、测试与文档；不得私自注入第二条 capability path。

## Ops Agent（P7-WP05）

`northstar_quant.application.ops_tools` 是与研究工具边界**分离**的、只读运维观测组合边界。
`TypedResearchToolApi` 保持九项 research-only allowlist；任何 ResearchAgent、IntelligenceAgent 或
DataQualityAgent 都不会获得 `TypedOpsToolApi`。这种分离避免“健康检查”或“日志诊断”成为研究 Agent
可横向升级的能力。

Ops facade 的闭合 allowlist 只有一个原子读取：`inspect_ops_snapshot`。它只通过显式注入的
`OpsSnapshotCatalog` 取得一个冻结、已授权且同一 scope 的快照，恰好包含：

```text
health
→ redacted log summary
→ deployment diagnosis
→ backup status
```

请求只有带时区的 `as_of`，不接受 host、IP、endpoint、path、service、shell、日志过滤条件、命令、
部署目标、账户或 broker 参数。快照和四个 section 均使用 hash、受限 enum、稳定 reason code 与 bounded
count；所有 section 具有同一 `scope_hash`、不可变 evidence hash 和
`observed_at <= available_at <= as_of`。未授权、未来可见、scope 不一致、缺失/重复 evidence、未验证
脱敏或未知响应类型均失败关闭。

任何通过该边界的输出都不得携带原始 health dict、日志正文、exception、stack、URL、文件路径、环境变量、
凭据、主机/账户/订单/仓位 payload、`details_json`、backup artifact 或 release journal 内容。现有
`application.health`、远程 ops 脚本、backup/readiness 和 release journal 可能访问配置、数据库、文件、
SSH 或进程并返回自由文本，故不能被 Agent 或 facade 直接导入；它们将来只能作为受信 collector 的后台
输入，先产生可审计的 immutable projection。

`northstar_quant.application.ops_agent.OpsAgent` 只接收一个 `TypedOpsToolApi`，只公开
`run(OpsAgentRequest)`，且一次 run 固定执行一次 `invoke(inspect_ops_snapshot, ...)`。run/request identity
在调用前即被消费；失败、畸形结果或未知副作用不会自动重试。输出是单条无敏感 hash trace 的
`DIAGNOSTIC_ONLY` artifact，并始终为 `eligible_for_trading=False`。

Ops Agent 对 kill switch 与风险状态只有观察权限：`ENABLED`、`HALT`、`MANUAL_RECOVERY` 和 `UNKNOWN`
会原样保留。它不含 command、action、recommendation、recovery、approval、target、order 或 trade 字段，
也没有 deploy、restart、rollback、migrate、restore、resume 或 risk transition API。因此它不能绕过 kill
switch，不能将 HALT 自动恢复为 NORMAL，也不能操作真实或模拟账户。

## P8 候选证据矩阵（WP01–WP05）

`northstar_quant.application.candidate_acceptance` 不是 Agent、工作流、交易入口或跨领域命令面。它只接收
已产生的 hash-only 证据，精确覆盖 Data PIT、Intelligence、Research、Portfolio/Risk、Execution simulation、
Deployment、Monitoring、Backup/Restore 和 AI Safety 这九条独立车道，以及四条明确的跨车道 seam。

P8-WP02 为 `INTELLIGENCE_TO_RESEARCH` 提供唯一已有真实接缝证据：受控的
`Event/evidence/完整 ontology/mechanism/impact/context` 先固定为 P4
`intelligence_feature_projection_v3` immutable static projection。每条 Event evidence 必须同时固定 P1 raw
source artifact snapshot、document ID、content SHA-256、UTF-8 span 和 source publication receipt；每个
MarketContext 必须同时固定恰好一个 P1 normalized artifact、context `DatasetVersion`/receipt 和完整闭合行的
content commitment。随后仅由 `application/` 在与 P1 发布器相同的 `ArtifactStore` 中重放并逐条验证 source
receipt/raw artifact/document/content/span，再要求 context `DatasetVersion` 恰有一个绑定指定 receipt 的 normalized
artifact，并重建其完整行以核对 commitment、identity 与 PIT，才受控发布到 P1。P1 使用不允许额外列的闭合
schema，随后以 `DatasetVersion`/PIT 形成 P2 的 `FeatureLineage`/`FeatureBackfill`，其中才绑定精确
`FeatureVersion`。P2 只接收狭窄的受限 feature-input、成对数值/受限缺失原因、PIT 与 hash-only provenance，
不会取得原始 Document、URL、source/context payload 或 LLM rationale；授权、身份、ontology、receipt、scope、
语义类型或 PIT 未知、缺失、不匹配或未来可见时立即失败关闭。这条接缝固定 research-only/non-tradable，不能
提升 Research Decision，也没有 `StrategyTarget`、`PortfolioTarget`、`ExecutionPlan`、broker 或任何订单能力。

P8-WP03 另为 `RESEARCH_TO_PORTFOLIO_RISK` 提供第二条、独立的真实接缝：
`ResearchStrategyTargetActivator` 不是 Agent、工作流或 Typed Tool API capability，因而不会让
`ResearchAgent` 获得 candidate、人工批准或 target 创建权。它只重放已具名批准为 `CANDIDATE` 且具 PASS
admission evidence 的 Research Card/Decision、精确 `ExperimentSpec`/`ExperimentRun`、Dataset/Feature/
StrategyVersion 和目标提案；独立具名的 `HumanStrategyTargetActivationApproval` 必须精确绑定这些身份后，
才签发 hash-only activation receipt 与 `StrategyTarget` v2。该过程保持
`STATIC_REPRODUCIBILITY_ONLY`、`decision_time_safe=false` 和 `eligible_for_trading=False`，不会创建
`PortfolioTarget`、风险批准、`ExecutionPlan`、broker order 或任何交易权限。P3 activation reference
不是可信存储/认证边界。P8-WP04 的 application-owned
`ExecutionProvenancePreflight` 现要求原始 activation request 与 claimed receipt 成对输入并重新激活，
精确匹配后才允许进入 P3 risk replay 和 P5 plan/runtime-risk/preflight replay；只给手写 hash、
`StrategyTargetActivationRef` 或 synthetic target 一律失败关闭。

WP04 接收的 runtime evidence 同样是显式 typed contract：PIT data manifest/time、完整 account/position
snapshot、account-attribution alerts、`ctp_sim_market_data` quotes 以及具体 data symbol / CTP identity /
volume multiple / margin rule 的有效窗口必须同时一致。`ExecutionPlan` 和 `PreflightResult` 不在 request
surface 上，均只能在该边界内部重建。输出仅是短时 hash-bound `ctp_sim` evidence receipt；它没有 Agent/
Tool API、broker、router、submit、cancel、recover、数据库或网络能力，并固定
`eligible_for_ctp_sim=false`、`eligible_for_trading=false`、`eligible_for_live=false`。

回执只有 `BLOCKED` 或 `CANDIDATE_EVIDENCE_ONLY`，无论在 offline、paper 还是 `ctp_sim`，
`eligible_for_trading` 都固定为 `False`。当前已有三条彼此独立的真实接缝：P4→P1→P2 的
`INTELLIGENCE_TO_RESEARCH`、带人工 activation receipt 的 `RESEARCH_TO_PORTFOLIO_RISK`，以及 P8-WP05
受 guard 的 `PORTFOLIO_RISK_TO_EXECUTION_SIMULATION`。最后一条只由独立 application executor 建立：它重放
原始 P2/P3/provenance request、从 `ctp_sim` 重取账户/报价、在 PostgreSQL 将 exact commitment 一次性消费并
与 durable intent 原子提交。只有该 executor 能签发不透明的 submission authority；模拟 adapter 在自身状态锁内
重验 consumption、真实 state/quote，且 reconciliation 不接受调用方 snapshot，随后由 consumption-aware
reconciliation 验证 fill。AI Tool API、Agent、CandidateAcceptance verifier 都不可达这个 executor；它也不能接入 real CTP、开启 live、
恢复 HALT 或提交真实订单。Data PIT→Research 仍显式 `BLOCKED`。即使三条测试接缝都存在，这些证据仍不代表
单一候选获得自动研究升级、真实订单、部署、恢复或真实交易授权。

`just candidate-acceptance` 仅调用固定的本地 pytest 证据集合。它会先拒绝 live trading、production/
未知环境和非 `paper` / `ctp_sim` broker，且没有 SSH、shell、部署、恢复、网络或 broker 控制能力。
