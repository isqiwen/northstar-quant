# 从第一个策略到可审计回测

本文面向第一次使用 Northstar Quant 的研究者。目标不是把一个想法直接接到实盘，而是
完整走通一条安全的离线研究路径：

```text
独立研究画像 → 已发布数据集 → 策略目标权重 → 回测器 → 报告/清单/PDF → 结论与复核
```

示例实现一个最小的日线向上突破策略 `first_breakout`。它在收盘价突破过去 N 个**已完成**
交易日最高收盘价时持有等权多头，否则目标权重为 0。这个规则足够简单，适合验证工程流程；
它不是投资建议，也不是已验证的交易策略。

## 0. 先理解边界

- 本教程只使用 `offline/research` 画像；不会连接券商，也不会生成真实订单。
- 所有命令都使用 `uv run northstar`，避免依赖本机是否把 CLI 放进 PATH。
- 项目只支持 PostgreSQL。先按仓库根目录 `README.md` 的“快速开始”完成本地环境、
  PostgreSQL 和迁移；不要把 SQLite 地址填入 `NORTHSTAR_DATABASE_URL`。
- 连续合约 `weight_return` 回测只适合快速筛选方向；实际合约日线 `futures_daily`
  才会模拟保证金、换月、动态费率、涨跌停和成交量约束。两者都不代表实盘收益。

本教程中所有新文件都使用 `first_breakout` 这个 ID。请在自己的项目中替换为唯一、清晰的
策略 ID，且不要覆盖内置 `futures_trend`。

## 1. 先复制一个独立的研究画像

每个回测画像都绑定数据 manifest 的配置哈希。因此，不能只复制画像后继续复用原来的
`data.path`：重新下载会覆盖原数据制品的 manifest，旧画像随后会因为哈希不匹配而被拒绝。
新策略必须使用自己的 `dataset_id` 和 `data.path`。

复制内置连续合约研究画像：

```bash
# macOS / Linux
cp configs/profiles/offline/cn_futures_daily_trend_offline.yaml \
  configs/profiles/offline/cn_futures_first_breakout_offline.yaml
```

```powershell
# Windows PowerShell
Copy-Item configs/profiles/offline/cn_futures_daily_trend_offline.yaml `
  configs/profiles/offline/cn_futures_first_breakout_offline.yaml
```

在新文件中至少修改以下字段；其余数据下载、期货规格、风控和离线安全设置先保留原样：

```yaml
profile_id: cn_futures_first_breakout_offline
name: 中国商品期货日线首次突破研究

lifecycle:
  role: research
  line_id: cn_futures_first_breakout_research

data:
  # 必须与原画像不同，避免 data manifest 冲突。
  dataset_id: first_breakout_continuous_research
  path: cn/futures/1d/first_breakout_continuous.parquet
  # 保留复制来的 provider、download.symbols、vendor_symbols 等字段。

strategies:
  - strategy_id: first_breakout
    strategy_family: trend_following
    enabled: true
    capital_weight: 1.0
    params:
      lookback_days: 20

versions:
  profile: cn-futures-first-breakout-research-v1
  strategy_params: first-breakout-20d-v1
```

文件名必须等于 `profile_id`，并以 `_offline.yaml` 结尾；目录、文件名和
`lifecycle.role: research` 会被加载器共同校验。

> 风控和组合参数只通过交易画像中的 `strategies`、`risk`、`execution` 和 `backtest`
> 字段生效。项目已移除未接入运行时的全局风险与组合 YAML，避免修改配置却不改变行为。

## 2. 实现最小目标权重策略

新建 `src/northstar_quant/research/strategies/first_breakout.py`：

```python
"""面向新手教程的日线首次突破策略。"""

from __future__ import annotations

import polars as pl

from northstar_quant.research.strategies.base import DailyStrategyBase


class FirstBreakoutStrategy(DailyStrategyBase):
    """收盘价突破过去 N 个已完成交易日高点时等权持多。"""

    strategy_id = "first_breakout"
    required_market_columns = ("symbol", "close")

    def __init__(self, lookback_days: int = 20) -> None:
        if lookback_days < 2:
            raise ValueError("lookback_days 必须大于等于 2")
        self.lookback_days = lookback_days

    def generate_targets(self, market_df: pl.DataFrame) -> pl.DataFrame:
        self.validate_market_data(market_df)

        signals = (
            market_df.select("date", "symbol", "close")
            .sort(["symbol", "date"])
            .with_columns(
                # shift(1) 保证 t 日信号只比较 t-1 及更早的价格，避免未来函数。
                pl.col("close")
                .shift(1)
                .rolling_max(window_size=self.lookback_days)
                .over("symbol")
                .alias("prior_high")
            )
            .with_columns(
                pl.when(pl.col("prior_high").is_null())
                .then(pl.lit(None, dtype=pl.Float64))
                .when(pl.col("close") > pl.col("prior_high"))
                .then(1.0)
                .otherwise(0.0)
                .alias("signal_value")
            )
        )

        active_counts = (
            signals.filter(pl.col("signal_value") > 0)
            .group_by("date")
            .agg(pl.len().alias("active_count"))
        )
        targets = (
            signals.filter(pl.col("signal_value").is_not_null())
            .join(active_counts, on="date", how="left")
            .with_columns(
                pl.when(pl.col("signal_value") > 0)
                .then(pl.lit(1.0) / pl.col("active_count").fill_null(1))
                .otherwise(0.0)
                .alias("target_weight")
            )
            .select("date", "symbol", "signal_value", "target_weight")
            .sort(["date", "symbol"])
        )
        return self.to_targets_frame(targets.to_dicts())
```

### 输出契约：为什么必须显式输出 0

日线目标权重策略必须输出以下列：

| 列 | 含义 |
| --- | --- |
| `date` | 决策交易日 |
| `symbol` | 研究标的，例如 `RB_CONT` |
| `signal_value` | 可审计的原始信号 |
| `target_weight` | 目标组合权重，可正、负或为 0 |

在一个标的已经形成信号后，即使它当天不应持有，也必须输出
`target_weight: 0.0`。不能通过“省略这一行”表达平仓；下游为了支持低频目标会前向填充，
省略行会错误地把旧仓位继续持有。

策略只负责生成目标权重：组合层会按 `capital_weight` 合并多个策略，并应用画像的
`risk.max_single_weight`、`risk.max_gross_exposure` 与 `execution.long_only` 约束。不要在
策略里偷偷读取账户余额、下单或绕过风控。

## 3. 注册策略并提供默认参数

在 `src/northstar_quant/research/strategies/registry.py` 顶部增加导入：

```python
from northstar_quant.research.strategies.first_breakout import FirstBreakoutStrategy
```

然后在已有 `futures_trend` 注册语句后增加：

```python
register_strategy(
    "first_breakout",
    FirstBreakoutStrategy,
    strategy_family=StrategyFamily.TREND_FOLLOWING,
    supported_markets=(Market.CN,),
    supported_asset_types=(AssetType.FUTURES,),
    supported_data_frequencies=(DataFrequency.D1,),
)
```

如需从包根导入策略，可同时更新 `src/northstar_quant/research/strategies/__init__.py` 的导入和
`__all__`；回测运行的必要步骤是 `registry.py` 中的注册。

新建 `configs/strategy/first_breakout.yaml`：

```yaml
strategy:
  id: first_breakout
  name: 教程：日线首次突破
  lookback_days: 20
  rebalance_frequency: 1d
```

YAML 中的 `lookback_days` 是构造器默认值；画像的
`strategies[].params.lookback_days` 会覆盖它。两处未知参数都会直接报错，因此不要靠拼写
接近的字段猜测是否生效。

## 4. 先写一个回归测试

新建 `tests/research/unit/test_first_breakout.py`：

```python
from datetime import date, timedelta

import polars as pl
import pytest

from northstar_quant.research.strategies.first_breakout import FirstBreakoutStrategy


def test_first_breakout_emits_a_long_and_an_explicit_flat_target():
    rows: list[dict[str, object]] = []
    for offset, (a_close, b_close) in enumerate(
        zip([100.0, 101.0, 103.0], [100.0, 99.0, 98.0], strict=True)
    ):
        current_date = date(2024, 1, 2) + timedelta(days=offset)
        rows.extend(
            [
                {"date": current_date, "symbol": "A_CONT", "close": a_close},
                {"date": current_date, "symbol": "B_CONT", "close": b_close},
            ]
        )

    targets = FirstBreakoutStrategy(lookback_days=2).generate_targets(
        pl.DataFrame(rows)
    )
    latest = targets.filter(pl.col("date") == date(2024, 1, 4)).sort("symbol")

    assert latest["signal_value"].to_list() == pytest.approx([1.0, 0.0])
    assert latest["target_weight"].to_list() == pytest.approx([1.0, 0.0])
```

运行最小质量检查：

```bash
uv run pytest tests/research/unit/test_first_breakout.py -q
uv run ruff check src/northstar_quant/research/strategies/first_breakout.py \
  tests/research/unit/test_first_breakout.py
```

测试至少要覆盖：预热期无目标、突破开仓、信号消失后的显式 0、多个标的权重和、参数
边界和缺失行情。策略产生空 DataFrame 不一定是错误，但如果它代表“全部平仓”，必须由
完整目标截面表达，而不是让执行层沿用旧快照。

## 5. 下载、校验数据并运行第一次回测

先为新画像发布自己的数据制品：

```bash
uv run northstar data download \
  --profile cn_futures_first_breakout_offline
uv run northstar data validate \
  --profile cn_futures_first_breakout_offline
```

然后只运行这条策略：

```bash
uv run northstar backtest run first_breakout \
  --profile cn_futures_first_breakout_offline
```

不要使用 `uv run northstar research futures-trend` 来验证自定义策略；它是内置趋势研究命令。对
任何新的目标权重策略，使用 `backtest run <strategy_id>`。CLI 会打印报告的精确路径，类似：

```text
reports/backtest/<profile_id>/first_breakout/<开始日-结束日>/<run_id>/report.md
```

同目录还会生成：

| 文件 | 用途 |
| --- | --- |
| `report.md` | 供人阅读的绩效、基准、执行审计、持仓和限制说明 |
| `report.json` | 完整结构化指标、曲线、目标、成交/约束事件 |
| `manifest.json` | 数据内容哈希、画像哈希、目标哈希、有效配置、代码版本与结果校验和 |
| `report.pdf` | 执行 PDF 命令后生成的归档版报告 |

生成 PDF 时，把 CLI 打印出的 Markdown 路径原样传入：

```bash
uv run northstar report pdf \
  reports/backtest/<profile_id>/first_breakout/<period>/<run_id>/report.md
```

同一 `run_id` 的完整制品不会被重跑静默覆盖；若相同 ID 对应的清单不同，程序会拒绝写入。
这使一次报告可以作为可追溯的研究证据，而不只是一个会被后续运行改写的文件。

## 6. 怎样阅读和分析结果

先打开 `report.md`，再按以下顺序检查 `report.json` 与 `manifest.json`：

1. **样本与评估起点**：查看“评估起始日”“热身排除权益观测数”和“统计样本状态”。
   只有从首个可执行非零目标开始的权益才用于主要绩效。少于 20 个执行后权益观测时，
   年化收益、波动率、夏普、索提诺、卡玛、跟踪误差和信息比率应为 `N/A`，这不是报错。
2. **收益与风险一起看**：比较总收益、最大回撤、正收益期占比、月度收益和净值曲线。只看
   收益而不看回撤、波动与样本长度，不能判断策略质量。
3. **比较基准**：读取 `analytics.benchmark`。基准不可用时必须看 `reason`，不能把缺失的
   比较指标解释为超额收益。
4. **检查仓位与换手**：阅读期末目标权重、`turnover_curve` 与平均换手。高换手策略即使连续
   收益回测好看，也可能在真实费用和流动性约束下失效。
5. **检查执行能力边界**：连续合约 `weight_return` 报告会标记
   `analytics.execution.detail_level: not_modeled`，此时没有逐笔成交、保证金或换月结论。
   实际合约日线回测才会提供成交事件、手续费、名义金额、保证金和未成交/约束事件。
6. **冻结输入**：核对 `manifest.json` 的 `data.content_sha256`、
   `profile.profile_config_sha256`、`strategy.target_frame_sha256` 和代码信息。任何一个变了，
   都是另一项实验，不应和旧报告直接横向比较。

建议把“分析策略”拆成可检验的问题，而不是只问“收益率高不高”：

| 问题 | 应检查的证据 |
| --- | --- |
| 是否存在未来函数？ | 信号只使用 t-1 及以前的数据；`execution_delay_sessions` 至少为 1。 |
| 是否有足够样本？ | 多个市场阶段、样本外区间、滚动窗口；不是只满足 20 个观测。 |
| 是否稳健？ | 小范围改变 `lookback_days`、标的池、成本和滑点后，结论是否仍成立。 |
| 是否依赖单一标的或时段？ | 目标权重、分标的收益归因、月度收益和最大回撤发生时点。 |
| 是否可交易？ | 实际合约日线的保证金、费用、涨跌停、成交量参与率和约束事件。 |
| 是否能复现？ | 同一数据/配置/代码指纹是否得到相同 `run_id` 与结果校验和。 |

## 7. 从快速研究升级到实际合约验证

连续合约回测通过后，复制
`configs/profiles/offline/cn_futures_daily_actual_offline.yaml`，仍使用独立的 `profile_id`、
`dataset_id` 和 `data.path`，并把 `strategies` 改为 `first_breakout`。例如数据路径可设为：

```yaml
data:
  dataset_id: first_breakout_actual_contracts_research
  path: cn/futures/1d/first_breakout_actual_contracts.parquet
```

保留其 `backtest.engine: futures_daily`、`futures.symbols_are_continuous: false` 与
`futures.execution_allowed: false`，然后运行：

```bash
uv run northstar data download \
  --profile cn_futures_first_breakout_actual_offline
uv run northstar data validate \
  --profile cn_futures_first_breakout_actual_offline
uv run northstar backtest run first_breakout \
  --profile cn_futures_first_breakout_actual_offline
```

策略仍读取由实际主力合约无未来函数拼接而成的连续信号；成交侧只处理真实合约。实际合约
画像中的公开规则和费率仍是研究级数据，不是期货公司账户费率。若数据历史太短，报告应
明确拒绝展示伪精确的年化统计，而不是把短样本结论包装成策略有效性。

## 8. 常见报错与排查顺序

| 现象 | 优先检查 |
| --- | --- |
| `策略已注册` / 找不到策略 | `registry.py` 是否只注册一次；`strategy_id` 是否在代码、YAML、画像中完全一致。 |
| `不支持的策略参数` | 构造器参数名、`configs/strategy/*.yaml` 和 `strategies[].params` 是否一致。 |
| 数据 manifest 哈希不匹配 | 新画像是否复用了旧 `data.path`；为新画像使用独立路径后重新下载。 |
| 没有任何历史目标权重 | 检查预热窗口、数据日期范围、`required_market_columns` 和信号条件。 |
| 旧仓位没有平掉 | 每个已形成信号的标的是否在平仓日显式输出 `target_weight: 0.0`。 |
| 年化/夏普显示 N/A | 先检查执行后权益观测数；短样本时这是保护性行为，不是把空值改成 0。 |
| 命令启动时数据库 URL 报错 | 使用 PostgreSQL 开发环境；不要以 SQLite 回退绕过项目配置。 |

完成本教程后，下一步应是补充更多单元测试、做样本外与敏感性分析，并在实际合约日线
回测中验证可交易性。任何一步都不授权连接真实 CTP 或提交真实订单。
