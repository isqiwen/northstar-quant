# 代码与配置注释规范

本项目与真实资金相邻，注释的目标是让使用者能审计“为什么这样计算、哪些假设成立、
缺少信息时系统会如何失败”，而不是逐行复述 Python 语法。

## 注释层次

1. 模块文档字符串：说明模块边界、输入输出和不负责的事项。
2. 类与公共函数：说明业务语义、关键前置条件、失败关闭行为和返回值口径。
3. 数学与数据转换：写明公式、单位、时间对齐和未来函数边界。
4. 订单、持久化与状态机：写明状态转换、幂等键、租约、恢复路径和不可重试条件。
5. YAML 字段：说明单位、默认值、覆盖优先级、是否已接入运行时及实盘风险。

## 必须说明的量化假设

- 价格是收盘价、结算价、复权价还是连续合约拼接价。
- 信号在何时产生、何时可执行，是否存在延迟。
- 权重、名义金额、保证金、手数和合约乘数是否被混用。
- 日线 OHLC 无法确定同日触发顺序时采用的规则。
- 数据、账户、合约映射或券商回报缺失时是否阻断交易。

## 不应写的注释

- 重复变量名或语法，例如“将 x 赋给 x”。
- 用注释隐藏已不成立的兼容逻辑。
- 把密码、令牌、账户号或其他敏感信息写入代码或 YAML。

涉及真实交易风险的行为变更，必须同时更新相关配置注释、代码文档字符串、测试和运行说明。
