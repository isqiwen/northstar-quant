# 国内期货执行现状与边界

## 当前可用能力

- 连续合约日线数据、趋势策略和离线研究回测；
- CTP 合约映射的严格加载与校验；
- 订单幂等键、跨进程执行租约、订单/成交持久化与终态恢复的通用基础设施；
- 收盘后冻结日频目标、下一时段读取目标的分层运行链路；
- 独立盘中实时风控评估、数据库结论和逐订单新鲜度门禁；
- 本地 paper 适配器，用于通用订单和账本基础设施验证；
- 隔离的 `ctp_sim` 本地语义仿真柜台，支持具体合约、保证金、今昨仓、开平仓、
  异步成交、撤单、重连恢复和数据库对账；
- 日线期货计划器，可把连续策略信号显式映射为具体合约，并按权益、乘数和动态
  保证金率换算整数手数；SHFE/INE 反手会拆成平昨、平今、开仓。

`configs/instruments/ctp.yaml` 的每条映射必须明确给出：

```text
continuous_symbol → data_symbol → instrument_id + exchange_id
                → product_id + volume_multiple + price_tick
```

连续合约不能直接下单。实际合约映射默认 `trading_enabled: false`，只有人工核验
合约、交易所、乘数和最小变动价位后才可启用。

## 当前明确阻断的能力

本项目尚未实现真实 CTP 的连接、认证、结算确认、报单、撤单、回报订阅和查询。因此：

- `NORTHSTAR_BROKER=ctp` 会在尝试连接前报错；
- 连续合约画像不能生成执行计划；
- `ctp_sim` 只能使用 `simulated` 画像，`ctp` 只能使用 `production` 画像；
- `ctp_sim` 的成功结果不能作为真实 CTP 柜台可用性的证明；
- 不存在任何可绕过这些检查的旧券商适配器或回退路径。

## 实盘接入的后续条件

在新增 `CTPBrokerAdapter` 前，至少需要完成：

1. CTP 会话、认证与结算确认的断线恢复；
2. `instrument_id + exchange_id` 的订单、成交与持仓反向映射；
3. 把已经在 `ctp_sim` 中验证的开仓、平今、平昨语义映射到真实 SDK 枚举；
4. 接入期货公司实际保证金、手续费、涨跌停、夜盘和合约到期规则；
5. 使用期货公司模拟前置重复断网、重启、部分成交和对账演练。

在此之前，项目只适合离线研究和流程验证，不应启用真实资金。
