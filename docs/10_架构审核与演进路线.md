# 架构审核与演进路线

## 当前结论

项目已收敛为国内中低频期货研究系统：连续合约快速研究和实际合约逐日保证金回测是
日常主线，实际合约分钟订单回放只用于必要的执行专项验证。三者都只用于研究。股票、
ETF、旧数据源、
旧策略、空壳仿真回测入口和旧券商适配器均不再保留。

当前已具备的可靠性基础包括订单幂等持久化、账户级执行租约、订单终态恢复、成交归因
和运行健康记录。持仓已使用可表达空仓的批次头，并按 broker/account/profile 隔离；
数据制品也会校验内容哈希。这些机制仍不等于具备真实期货交易能力。

## 已实现的 CTP 合约边界

真实账户使用 `configs/instruments/ctp.yaml`；本地语义仿真使用隔离的
`configs/instruments/ctp_sim.yaml`。两者的 `broker` 字段必须与适配器一致，不能混用。
映射按 `continuous_symbol`、`data_symbol`、`instrument_id`、`exchange_id`、品种、
乘数和最小变动价位进行严格校验；重复或禁用映射会失败关闭。

日线期货计划器已能按具体合约乘数和动态保证金率计算整数手数，并生成开仓、平仓、
平今和平昨计划。`ctp_sim` 可执行这些计划并演练异步回报、断线恢复和对账；真实
`NORTHSTAR_BROKER=ctp` 仍会在连接前明确拒绝。

## 下一阶段

1. 接入可信的国内期货历史数据供应链，持续保存原始文件、主力日历和动态规则来源。
2. 先用日线成交量和仿真成交校准容量；只有执行细节会影响策略结论时再接入 tick/L2。
3. 单独实现 `CTPBrokerAdapter`：认证、结算确认、报单、撤单、成交/持仓/资金查询。
4. 先在本地 `ctp_sim` 持续完成断网、重启、重复回报、部分成交和平今平昨演练，
   再在期货公司模拟前置重复同一套演练。
5. 通过数据、风控、对账与人工审批后，才考虑创建真实 `*_live` 画像。
